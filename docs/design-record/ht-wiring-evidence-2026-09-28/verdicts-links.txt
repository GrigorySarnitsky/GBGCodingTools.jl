No finding is FALSE. Notes on the checks' classes, for the tool:

- RULE.DOC.XLINK always reports `d.line`, the line where the docstring opens, instead of the line of the mention. All eight TRUE XLINK findings point at the wrong line (947→1022, 34→47, 51→62, 68→72/73, 17→36, 80→159). The LINK_UNIFORMITY finding does the same (401→411).
- XLINK resolves a backticked identifier by name alone, through the export table. So a bare `scalar_dissipation` meant as a field or keyword of a local type (FlowParameters) is credited to the exported Observables function of the same name. The bullet-heading exemption covers only fields listed in the same docstring. This is what makes the two UNCLEAR cases.
- XLINK counts a name as linked if it is linked ANYWHERE in the docstring, not only earlier. A bare first mention followed by a later link is therefore never reported, although the statement asks for the link at the first mention. This is a missed finding, not a false one: SimulationRun.jl:159 `StochasticOU`, linked only at 304.
