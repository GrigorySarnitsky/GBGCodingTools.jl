## BLOCKERS

1. **ARCHITECTURE §6.2 steps 2–3 (L828–839) + step 10 (L873–877); §6.7 (L938–940); §6.8 (L955–957) — the gate deadlocks every round.** Preflight OPENS the round (writes `ROUND.toml`), then `gbg round prepare` runs `docs_build`, whose `GBGCodingTools.makedocs` runs `gbg gate check-docs check-consistency`, which returns 1 for "any open round" — the round just opened. The same circle closes a bug-hunt: close requires `Pkg.test()` green, `Pkg.test()` runs `TestHarness.gate()` → `gbg gate bug-hunt audit-changes` → the still-open hunt round → 1; and the audit-changes round that must be opened before the hunt closes, and whose `bank` "itself RUNS executable_claims" (`Pkg.test()`), trips its own gate too. Nothing in either document exempts the active round. **Fix:** define the gate's blocking predicate as "a round that is `banked` and not `closed`/`abandoned`" (an `opened`-but-unbanked round is WARN, as `ROUND.OPEN` already is in §7.3), AND let `prepare`, `pass open`, `bank` and `close` export `GBG_ACTIVE_ROUND=<round>` so `gbg gate` skips exactly that round when invoked from inside its own build/test. State the same in IMPLEMENTATION 1.4 (`makedocs`) and 1.6 (`gate.py`), and add a selftest arm ("gate ignores the round it is preparing; fails on any other open round").

2. **IMPLEMENTATION Phase 1 DoD (L285–293) vs Phase 3 (L325–331) — the fixture's docs env cannot resolve before the tag exists.** Phase 3 instantiates `fixture/GBG Fixture/docs` "against the tag", so the fixture's `docs/Project.toml` carries `[sources] url+rev = "v1.0.0"`; Phase 1's DoD runs `julia --project="fixture/GBG Fixture/docs" …make.jl` before any tag is pushed → Pkg cannot fetch `v1.0.0` → fails. And with a `path = "../../.."` source instead, the wrapper's quick doctor (`PIN.SOURCES`, `PIN.TREESHA`, `PIN.CONFIG` — all exemption-free) FAILS the same build, and `gbg --dev doctor` in the same DoD fails likewise. **Fix:** the in-tree fixture uses `[sources] GBGCodingTools = {path = "../../.."}` in all its envs; in `--dev` mode (or when `GBG_DEV=1`) the doctor reports `PIN.SOURCES`/`PIN.TREESHA`/`PIN.CONFIG` as WARN with the note "dev checkout"; the url+rev/pinned-copy behaviours are exercised in Phase 3 against a throwaway copy of the fixture outside `$DEV` (`gbg selftest --pinned`). Write this in §8 and in Phase 1/3.

3. **IMPLEMENTATION Phase 1 DoD (L291) — `"$DEV/gbg"` inside the single-quoted `bash -c '…'` string.** `DEV` is a plan variable, never `export`ed, so the child shell expands it to empty and runs `python3 /gbg --dev doctor` → exit 2/127. Also `--dev` is defined (1.2) as a SHIM flag, not a CLI flag. **Fix:** `export DEV=…` at the top of the plan (and `export B=…`), and state in 1.3 that `__main__.py` also accepts `--dev` (sets `GBG_DEV=1`, stamps `dev+<sha>`).

4. **ARCHITECTURE D2 (L130–137) + IMPLEMENTATION 1.2 (L135–137) — the shim cannot find the dev checkout.** "Outside any consumer it routes to the dev checkout" / "none → `exec python3 "$DEV/gbg"`", but the shim is installed by `python3 ~/.julia/packages/GBGCodingTools/*/gbg install` from the PINNED copy, which does not know where the dev checkout is, and `SHIM.HASH` requires the installed body to equal `bin/gbg` byte-for-byte, so `install` cannot substitute the path in. Phase 3's `gbg fleet` and Phase 8's `gbg fleet --deep` therefore have no runnable route. **Fix:** the shim reads the dev path from `~/.config/gbg/dev-checkout` (one line, written by `gbg install --dev-checkout "<path>"` or by `install.sh`), falls back to `$GBG_DEV_CHECKOUT`, and exits 2 with "no dev checkout registered" otherwise; add `ENV.DEV_CHECKOUT` (WARN) to §7.3.

5. **ARCHITECTURE D9 (L316–317), §7.3 `ENV.SHIM`/`SHIM.HASH`/`GIT.BRANCH` (L1009–1010, L1036) — the quick doctor inside `run_gate` fails every CI docs build.** A GitHub runner has no `~/.local/bin/gbg` and checks out a detached HEAD, so `ENV.SHIM`, `SHIM.HASH` and `GIT.BRANCH` FAIL, `run_gate` `error()`s, and the consumer's Docs deploy (which the working agreements say must stay green on push) goes red the moment the wrapper lands (Phase 4 PF-3). **Fix:** enumerate the QUICK set explicitly (`PIN.CONFIG PIN.SOURCES CFG.VALID CFG.SURFACES WIRE.* MANAGED.* POL.* ROUND.MARKER ROUND.DIR`) and mark `ENV.SHIM`, `SHIM.HASH`, `GIT.*` as "local only — skipped when `CI` is set", in §7.3 and in IMPLEMENTATION 1.4.
