# The review of rc.35 to rc.42 — every finding and its fate (2026-09-29)

Three independent reviewers read the changes from v2.0.0-rc.34 to rc.42, each a part of the diff, and
reported a defect only with a reproduction they had run. They found 26. Each is fixed below, with a
test or an example that fails on the code it was found in, unless a line says otherwise. The review
was run because the suite and the floor were green and nobody had read the changes: on 2026-09-23 the
same kind of review found twelve defects behind a green suite.

## The engine: config, change guard, exclusions, docstring lines

- **E-1.** A built page mapped to one source form only, so a page built from `docs/src/X/index.md`,
  or the local build's plain `docs/build/X.html`, escaped an exclusion. · fixed: every form maps
- **E-2.** Built-site findings were filtered for exclusions after the rule ran, so a rule comparing pages
  answered by which page sorted first. · fixed: excluded pages are left out before any rule reads them
- **E-3.** A named CLAUDE.md section ended only at a column-0 `#` heading, so an instruction under an
  indented or underlined heading passed the change guard as documentation. · fixed: one heading reader,
  `Texts.markdown_headings`, as CommonMark reads headings
- **E-4.** An `@path` import line inside a named section counted as documentation, though it reads
  another file's instructions into every session. · fixed: an import line is always code
- **E-5.** The config check read headings its own way, including comment lines in fenced code, so a
  name matching only such a comment passed and admitted nothing. · fixed: the same heading reader
- **E-6.** An exclusion matching only ignored files passed locally and failed on a fresh clone.
  · fixed: validated against the files a clone holds
- **E-7.** `docstring_line` assumed a docstring's text starts below its quotes, wrong for a one-line
  docstring, a blank line after the quotes and Windows line endings. · fixed: the reader records the
  line the text starts on

## The rules

- **R-1.** `JULIA_MANUAL` took any `;`…`name...` on a line for a keyword splat: prose, a `vcat`
  splat, `f(args...)`. · fixed: a splat inside one call's parentheses, after its `;`
- **R-2.** Its `do` pattern took prose ") do not store" and missed a non-ASCII argument.
  · fixed: `do` and at most its arguments' names, or the inline `do x … end` of a signature
- **R-3.** A splat on a signature's continuation line was missed or reported a line late. · fixed
- **R-4.** Its lines, and the four rules R-12 and W-23 changed, were one off for the cases of E-7.
  · fixed with E-7
- **R-5.** `FENCED_CODE` dropped a tab-indented block and a fence indented four spaces. · fixed
- **R-6.** It placed a block at an earlier list paragraph with the same text. · fixed: each candidate
  confirmed by the parser, line by line
- **R-7.** `LOCAL_PATH` read a Windows path as relative on Linux. · fixed: absolute on any host
- **R-8.** It found a path's line in the raw text, missing an escaped path and taking a comment.
  · fixed: the line whose `path = "…"` value, read as TOML, is the path
- **R-9.** `ARGS_FORM` read arguments bound in prose, followed by an unrelated list, as bullets under
  the sentence. · fixed: the sentence must end at "are" or "are:"
- **R-10.** `FIELDS` cut a bullet's head only at a dash, so in the colon form every code span of the
  description counted as a field: eight false findings in GBGCloudPhysics. · fixed: one bullet-head
  reader, `Texts.bullet_head_names`, shared with R-11
- **R-11.** `XLINK` took only a bullet's first name as its own, so later names of "- `a`, `b` —" read
  as unlinked mentions: sixteen in GBGCloudPhysics. · fixed, and a head that wraps onto its next line is
  read whole (six more there, and two field findings): `Texts.bullets`
- **R-12.** `LINK_UNIFORMITY` reported the linked name's first appearance anywhere, not the run.
  · fixed: the run itself, found again in the docstring's text

## The machinery: the push hook, the command, the floor, bump, witnesses

- **M-1.** The push hook missed pushes with a quoted `-C` path, `git -c key=value`, `--no-pager`.
  · fixed
- **M-2.** It missed `gbg release`, which pushes a tag. · fixed
- **M-3.** It read the whole call, description included, so a command mentioning a push ran a build.
  · fixed: the command alone, quoted strings and heredoc bodies not commands unless a shell runs them
- **M-4.** It built the working tree and always this package: an uncommitted fix passed a broken
  commit, and a push of another repository ran this one's build. · fixed: a push while tracked files
  are uncommitted is stopped, and another repository's push is not this hook's. A command that commits
  before it pushes is checked on the tree it is about to commit: the first version stopped this package's
  own commit-and-push, since the hook runs before the whole command
- **M-5.** The floor's clone kept files removed with `git rm` and the old name of a `git mv`. · fixed
- **M-6.** The witness runner filed a failed `@test_logs` as broken. · fixed: any failed result counts
  as a failure
- **M-7.** `bump` looked only at `Manifest.toml`, not a version's own `Manifest-v1.12.toml`. · fixed

## Left for the owner

- Where a type has a field and another module a function of the same name, a bare mention in prose is
  read as the field. In GBGCloudPhysics' cache, "read through the accessors — `mean_s_w`, `mean_s_i`" may
  mean the Observables functions. The same question as W-24, which arose only in HT's Phenomenology and
  was set aside there; here it is outside it.
