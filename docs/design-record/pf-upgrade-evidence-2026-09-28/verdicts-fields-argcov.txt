What the ARGCOV check gets wrong: it treats an argument as documented only when its name shows up as a backtick code span (`family`, `family::T`, `family = …`) or as a word inside a code span. An argument described in prose by its own name in emphasis or plain text ("a storage *family* — `Array`, `CuArray`, `ROCArray` — in place of the array") counts as undocumented, even though the reader learns both its values and its effect. The rule only asks that the argument be "documented in its body". Needing a code span is the check's own narrowing, and the check's own docstring says so ("Documented means: the name is a code span"). This is borderline. If the owner rules that an argument must be named in code font, these six become TRUE, and PF fixes each by changing the emphasis *family* to the code span `family`. In that case the rule's statement should say so. One more note for all FIELDS findings: the finding sits on the line where the docstring opens, not on the "The fields are" line. That is the check's convention (one location per docstring), and it is not a misreading.
