The rules GBGCodingTools is held to

Written by AI, not regularly reviewed

This page is written by AI and is not reviewed regularly by a human.

Generated at build time from the rule values in GBGCodingTools vdev. Each rule carries its own check and the examples that show the check matches it, so this text and the program that enforces it cannot disagree. A rule's id is stable and is what a finding, a switch and a report all name.

Checked by a program — 65

These run in every build and every test of the package; a breach is a red build.

RULE.ASK.NO_COORDINATES

A question's decision and context name no rule, file or piece of code; those go in its items and its exhibit.

A decision carrying an identifier asks the owner to hold a coordinate in his head before he can reach the question, and the question is the part he is being asked about. A name in backticks is exempt: quoting one is how a question says which exact name it means.

Covered by a program.

RULE.ASK.NO_HOUSE_TERMS

A question is written in the owner's words, not in this package's.

He is being asked about his own work. A question written in the tool's vocabulary is answerable only by someone who has read the tool, which makes the answer the tool's rather than his.

Covered by a program. This package may set house_terms; unset, it is ["fileset", "file set", "ratchet", "anchor", "wiring check", "managed block", "pin", "switch", "rulebook", "instrument", "lane", "hat", "round", "harness", "consumer"].

RULE.ASK.ONE_DECISION

A question's decision is one sentence, and it ends in a question mark.

Two sentences in a decision are two decisions, and the owner answers with one option: whichever he meant, the other is recorded as answered and was not.

Covered by a program.

RULE.ASK.SHORT

A question's decision and its context are short enough to read in one pass; its exhibit is not measured.

What does not fit belongs in the exhibit, which holds the commits, the diffs and the definitions the owner reads to decide. A limit on the exhibit would push the evidence out of the question instead of shortening the question.

Covered by a program. This package may set decision_words; unset, it is 40. This package may set context_words; unset, it is 150.

RULE.CIT.BLOCK_LIST

References are listed one to a line, never run together with semicolons.

A reader looking for one reference in a semicolon-separated run has to parse the whole paragraph.

Covered by a program.

RULE.CIT.DOI

Every reference carries a clickable DOI, or an Open Library link for a book, on its title. A work whose entry states it has no DOI — the words "no DOI", in any case — may carry on its title instead an https link to its stable public record.

A DOI a reader cannot click is a string to retype; one written as a bare label is indistinguishable from prose.

Covered by a program.

RULE.CIT.FULL_INLINE

A docstring cites author–year in its prose and carries the full reference in a # References section, identical to the canonical entry in title and DOI.

A full reference mid-sentence takes the reader's eye out of the sentence, and a hand-copied entry drifts from the one the package keeps.

Covered by a program. This package may set references; unset, it is docs/ARCHITECTURE.md.

RULE.CIT.RESOLVES

Every DOI or Open Library link on a title answers, and answers with the work the title names.

A link is a promise that the reader can reach the work. A DOI that answers 404, or answers with another paper's record, breaks it and nothing in the text looks different. This reaches the network, so it runs only under gbg check --network — on request, never in a build or a test — which is why the reader's rule about inaccessible sources does not ask it.

Covered by a program, which reaches the network and runs only under gbg check --network.

RULE.DOC.AI_BANNER

A rationale page and a rendered Literate example carry the provenance banner, verbatim; a script that is never rendered is not a page and carries none.

A banner reworded in one package is a banner a reader learns to skim past in all of them.

Covered by a program. This package may set banner_pages; unset, it is String[].

RULE.DOC.API_GROUPING

One docstring has one home on the built site, and a Base function the package extends is public.

Two homes for one docstring is two things to keep true, and the second teaches a reader nothing.

Covered by a program.

RULE.DOC.ARGCOV

Every argument in a docstring's signature, positional and keyword, is named as code in its body, or delegated: a paragraph opening "Arguments: as for", or an # Arguments section opening "As for", links a function documented in the same file whose own docstring names all its arguments, in the form RULE.DOC.ARGS_FORM asks, without delegating, whose arguments include all of this signature's, and the paragraph names as code each of its arguments this signature lacks.

A reader passing an argument the docstring never mentions has to read the source to learn what it does. Where several functions take one function's arguments, one list serves them all, and the conditions keep the pointer from covering an argument that list lacks.

Covered by a program.

RULE.DOC.ARGS_FORM

Three or more arguments, or any keyword, are listed as bullets under an # Arguments heading, where several may head one bullet together; fewer are bound in running prose, as in "The arguments are a, the first, and b, the second."; the two are never mixed. A type lists its constructor's arguments so too, even where its # Fields section repeats them. A docstring that delegates its arguments as RULE.DOC.ARGCOV states takes neither form.

A reader looking for one argument of many needs a list; a reader of a two-argument call needs a sentence; a reader of a function that takes another's arguments needs the one list they both take.

Covered by a program.

RULE.DOC.ARG_BULLET

An argument or field bullet names its argument in a plain code span, never a bold one.

Bold marks structure (RULE.DOC.EMPHASIS); a name set in bold reads as a heading over the paragraph rather than as the argument.

Covered by a program.

RULE.DOC.CURRENT

No stale claim: a rule cited by id names a rule that exists, and a retired phrasing is not used.

A citation of something renamed or removed reads exactly like one that resolves, which is why it survives.

Covered by a program.

RULE.DOC.EMPHASIS

Bold marks structure alone: a heading, an admonition's title, a table's header row, and a run-in head that opens a paragraph, a list item, a quotation or a table cell. Bold anywhere else in a sentence, and bold italic, is never used; what it marked is stress or a term at its definition, which are italic, or a sentence that should carry its weight by its order.

One mark doing three jobs tells the reader none of them: in one package bold opened bullets, introduced defined terms and stressed not, hundreds of times inside a sentence. The authorities agree that emphasis and a defined term are italic and bold is for structure — Knuth slants the emphasised not and never bolds it (The TeXbook, ch. 4), LaTeX's \emph sets italic, SIAM's style manual says "Bold is not used for emphasis", and the Chicago, Google, Microsoft and Apple guides and Wikipedia agree — and a reader finds a run-in head by where bold stands, which bold scattered through the sentences hides. A journal's volume in a reference is plain as well: some citation styles bold it, and no rule here asks for it (the owner, 2026-10-17). Where a bold span stands decides the question, so a program does; whether its italic is earned is RULE.DOC.EMPHASIS_RARE's (the owner, 2026-10-16, on GBGHomogeneousTurbulence's request).

Covered by a program.

RULE.DOC.FENCED_CODE

A code block in a page or a rationale document is fenced with three backticks, never indented; a docstring's indented signature is exempt.

An indented block is code only by context, so a program reading the page cannot tell it from an indented paragraph without the parser's whole reading, and a list item left indented after a blank line renders as code nobody wrote.

Covered by a program.

RULE.DOC.FIELDS

A type with named fields documents them in a # Fields section, in bullets: every bullet a real field, and every field at the head of a bullet, alone or with others; a field named only inside another's bullet has none. A sentence listing them, "The fields are …", is no such section.

A field list that has drifted is worse than none: it names what does not exist and hides what does.

Covered by a program.

RULE.DOC.INTERNAL_API

An API page puts its internal section last, holds no empty block of collected docstrings, and is never indexed.

Internals in the middle of the public surface, and an index on a hand-grouped page, both make a reader work around the page.

Covered by a program.

RULE.DOC.JULIA_MANUAL

A docstring or page that uses a keyword splat (kwargs...) or a do block links the Julia manual's section on it.

A reader who has not met the construct learns it where it is used, and the manual is its official home: a paraphrase of it drifts, and a link does not.

Covered by a program.

RULE.DOC.LINKS

Cross-referencing is discriminating: a target is linked at most once in one docstring, or in the prose of one section of a page under docs/src/ outside its tables, at its first genuine mention; a heading begins a section and is not prose.

A link draws the eye and says the target is worth following; a second one to the same target adds nothing a reader of the same docstring or section has not just met, and dilutes the links that matter. A long page is read from the middle — a reader lands in a section from a search, a heading's link or the sidebar — so a page's count starts again at each heading (the owner, 2026-10-18). A table is not held to it, since a row stands alone and is read alone. A target is a binding, one target under any text that reaches it, qualified or bare; a link to a heading is a way around the site, which no rule here counts.

Covered by a program.

RULE.DOC.LINK_UNIFORMITY

In one run of names, either every name is linked or none is.

A list where one name links and the next does not reads as though the difference meant something.

Covered by a program.

RULE.DOC.NO_DEAD_REFS

A docstring cites no section number and no inaccessible source; it reads complete at the REPL.

At the REPL there are no links: a section number cannot be followed, and it is renumbered besides.

Covered by a program.

RULE.DOC.REF_ABUT

A cross-reference never abuts a second code span; the whole call is the link text.

The two render as adjacent monospace chips with a seam, as though the name had been cut in half.

Covered by a program.

RULE.DOC.REGISTER

A tunable is an option, a setting or a keyword argument, never a knob or a tweak.

The house register is plain and exact; knob is neither, and reads as though the value did not matter.

Covered by a program.

RULE.DOC.RETIRED_CLAIMS

A phrase a package has retired does not reappear in its documentation.

A claim retired once is retired because it was wrong, and the way a wrong claim comes back is that somebody copies the sentence that carried it. A DECISION LOG quotes what it retires, in order to record that it was retired, so this rule fires on a package's own history and is right to: keep the log in a file of its own and switch the rule off for that file, never for the design document the log was buried in, which is where the guard is worth most. The check is only as good as the list, and the list is kept by the party being checked: nothing in a repository knows that a claim was retired, so a claim dropped from the list is invisible here, and a ban whose reason was itself later overturned stays in force until someone notices.

Covered by a program. This package may set retired_claims; unset, it is GBGCodingTools.Model.RetiredClaim[].

RULE.DOC.SECTION_ORDER

A caveat admonition at a docstring's margin comes after its # Arguments section and before its # Fields section.

RULE.DOC.HOME_ORDER orders a docstring: the arguments, then the caveats that close its prose, then # References, then # Fields last. These two places are where a caveat most often lands wrongly, and a program can find them; an admonition indented under a list item is that item's.

Covered by a program.

RULE.DOC.SENTENCE_OPENER

A sentence opens with a capitalised ordinary word, never a lowercase identifier or a formula; bullets, comments, headings and fenced code are exempt.

At a full stop a reader cannot tell a new sentence beginning with a lowercase name from the old one running on.

Covered by a program.

RULE.DOC.SHAPE

A paragraph of prose stays inside the house cap, an admonition count stays inside its own, and prose that was here before the cap may shrink but never grow.

Prose grows by accretion: each addition is small, nobody rewrites, and the paragraph nobody can read was never written in one sitting.

Covered by a program.

RULE.DOC.SIBLING_LINK

The first mention of a sibling package links to that package's site; later mentions are bare.

A reader meeting the name for the first time must be able to reach it, and a fourth link teaches nothing.

Covered by a program.

RULE.DOC.SIGNATURE_FIDELITY

The signature a docstring displays — in its leading block, or listed in its body — and the methods the module defines agree, argument for argument, in name and in position.

A displayed signature is what a reader calls and the names a reader learns: one the method table has moved past is a call that fails, and a renamed argument is one the reader looks for in the code and does not find.

Covered by a program.

RULE.DOC.SIGNATURE_MIRROR

A docstring's signature block fits the house column of 88 characters, as rendered, and repeats only as much of the method as a reader needs.

A signature wider than the column wraps in the rendered page and in every terminal that shows it.

Covered by a program.

RULE.DOC.TABLE_TOP_LEVEL

A Markdown table is top-level, never indented inside a list item.

Markdown reads an indented block as code, so an indented table renders as the pipes and dashes themselves.

Covered by a program.

RULE.DOC.XLINK

A name another module owns, mentioned on its own, is linked at its first mention in a docstring; in the prose of a page under docs/src/, every name a module of the package exports and documents is linked at its first mention there. Each link is qualified so it resolves; a name inside a code expression owes no link, and a heading is not prose.

A reader meeting a name from elsewhere has nowhere to go: the docstring in front of him does not define it, and a page defines nothing of itself — its section leads, module maps and tables send him to docstrings he cannot reach without the link (one package's pages named 85 such names plain, 2026-10-18). A design document is not such a page: it is read raw as well, where a link to a docstring does not resolve. Documenter's build checks that a link resolves. An argument that shares a documented name is written as the expression it is — depth > 1, depth = 3 — which owes no link, since a program cannot tell the argument from the binding.

Covered by a program.

RULE.GIT.BRANCH

The working branch is the one branch names, master unless the package sets it; a rename is the package's decision.

A rename is a decision about the package, never bundled with a tooling adoption.

Covered by a program in the end-of-turn hook, which reads the branch and the commits not yet pushed — weaker than a build check, since a hook can be skipped and a failing test cannot. This package may set branch; unset, it is master.

RULE.GIT.CI_MANUAL

CI is manual-only, workflow_dispatch and release tags; the matrix runs locally before a commit; docs deploy on push.

Before committing a code change, run the gate locally; a documentation-only change needs a load and the docs build. The docs build is therefore the per-push enforcement point, and the rules that read the built site run inside it.

Covered by a program.

RULE.GIT.LICENSE

A package carries the MIT licence in one file at its root, LICENSE or LICENSE.md: a copyright line naming the year and the holder, then the licence's text word for word.

A repository published without a licence can be read but not legally reused. MIT is what Julia, its standard libraries and nearly every package of the General registry carry, and what each package of the fleet depends on, so it adds nothing a user must check (the owner's ruling, 2026-10-07). The text is compared word for word because an edited licence is a different licence.

Covered by a program.

RULE.GIT.LOCAL_PATH

No committed environment file, a Project.toml's [sources] or a Manifest.toml, names a path outside the repository.

A path outside the repository exists on the machine that wrote it and nowhere else: GBGPeriodicFields committed docs and test projects whose [sources] named this package's Dropbox checkout, and its docs build failed on the runner while every local run passed (2026-09-18).

Covered by a program.

RULE.GIT.MANIFEST_TRACKED

Sub-environment manifests are gitignored; a tracked root manifest is a declared deviation, a switch naming the file.

A stale sub-environment manifest is resolved locally when precompilation breaks; CI resolves its own.

Covered by a program.

RULE.GIT.PUSH

Commit ⇒ push, directly on the configured branch; no feature branches.

The repository is private and synced across machines through GitHub, so work is committed on the default branch and pushed in the same step; GitHub is the cross-machine sync path and the docs site deploys on push. Stage with git add -u plus every new file by name, never -A.

Covered by a program in the end-of-turn hook, which reads the branch and the commits not yet pushed — weaker than a build check, since a hook can be skipped and a failing test cannot.

RULE.GIT.RECORDS

A record the tool keeps for the owner — .gbg/questions.json, and a closed run under .gbg/runs/ — is committed, never left untracked or modified; an open run's is committed at its close.

It holds the owner's rulings and the runs' findings. Uncommitted, they exist on one machine only, and a session on the other neither sees them nor knows that a question's id is taken. No verb commits it: gbg answer and the review's skill say so, and the session commits.

Covered by a program in the end-of-turn hook, which reads the branch and the commits not yet pushed — weaker than a build check, since a hook can be skipped and a failing test cannot.

RULE.GIT.REQUESTS

A cross-package request is a tracked file .gbg/requests/to-<PKG>-<date>-<topic>.md in the requester, whose first paragraph begins Status: and says when the owner approved sending it, as approved by the owner on <date>; a concluded request is deleted.

The requests directory holds what is still awaiting the other package and nothing else.

Covered by a program.

RULE.GIT.TRACKED

A package's git tracks only the package and the tool's files: src/, ext/, test/, of docs/ what its build and site take part in (the pages under docs/src/, the build's script, docs/Project.toml, docs/prose_shape.csv, and each document declared in copies or in a rationale file set the config writes out), examples/, benchmark/, .github/, Project.toml, README.md, a LICENSE, CHANGELOG.md, .gitignore and CLAUDE.md; .gbg/config.jl, .gbg/policy/, .gbg/requests/, .gbg/questions.json, .gbg/settled.jl, .gbg/runs/ and .gbg/leak-accepted.txt; .claude/settings.json, .claude/hooks/, .claude/skills/ and .claude/WORK_QUEUE.md. A draft or a note between sessions lives in inspiration/, which git ignores; any other file is declared with its reason.

Git carried notes between machines because it was the easiest way, and a public release would have published them: one package held a design proposal, notes to other sessions and old review rounds. inspiration/ reaches both machines through Dropbox, so no note needs git, and a file kept on purpose says why.

Covered by a program in the end-of-turn hook, which reads the branch and the commits not yet pushed — weaker than a build check, since a hook can be skipped and a failing test cannot.

RULE.GIT.TRAILER

Every commit ends with the versionless 'Co-Authored-By: Anthropic Claude <noreply@anthropic.com>' trailer, and no other Co-Authored-By or Claude-Session line; never [skip ci].

The trailer names no model version on purpose (ruled 2026-09-08): the model in use changes often and the versions supersede each other, so a version in the trailer is a fact about the day rather than about the work, and it goes stale in the one place git never lets anyone correct it.

Covered by a program in the end-of-turn hook, which reads the branch and the commits not yet pushed — weaker than a build check, since a hook can be skipped and a failing test cannot.

RULE.LEAK.EMAIL

No email address is published but those the package's config approves in leak_emails, GitHub's own and no-reply addresses, the commit trailer's, and those in a domain reserved for documentation.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. An address in a commit's author field is published with the commit; only a rewrite of the history removes it, which is the owner's to make.

Covered by a program.

RULE.LEAK.HOME_PATH

No home-directory path — /home/<name>/, /Users/<name>/, C:\Users\<name> — is published, but a hosted runner's.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. A home path names the person and the machine, and a credential scanner allows it on purpose.

Covered by a program.

RULE.LEAK.MANIFEST_PATH

No Manifest.toml or Project.toml in any commit names an absolute path.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. RULE.GIT.LOCAL_PATH holds the tree as it is; a path committed once and removed since is still in the history.

Covered by a program.

RULE.LEAK.NEVER_PUBLISHED

No file that is never published — an environment file, a private key or certificate, a credentials file, a session transcript — is in any commit.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. Such a file exists to hold a secret, so it is judged by its name and kind, whatever it holds: its holding nothing today says nothing of the commit that held something. A file that only may hold one — an editor's or an assistant's local settings, as .claude/settings.local.json — is judged by what it holds, by the other rules, in every commit: GBGPeriodicFields' was blocking by its name alone while the scan found no credential in any of its versions (the owner, 2026-10-09). RULE.GIT.TRACKED keeps it out of git from now on.

Covered by a program.

RULE.LEAK.SCRATCH_PATH

No path into an assistant's scratch directory, /tmp/claude-<uid>/…, is published.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. A scratch path carries the user's id and the name of the session's project, and points at nothing a reader can open.

Covered by a program.

RULE.LEAK.SESSION_LINK

No link to an assistant's session is published.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. A session link opens a conversation that was never meant to be public, with whatever it held.

Covered by a program.

RULE.LEAK.SYNCED_PATH

No path inside a synced folder — Dropbox, OneDrive, Google Drive, iCloud Drive, Nextcloud — is published.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. A synced folder's path tells where the owner keeps his work, and which service holds it.

Covered by a program.

RULE.LEAK.TERM

No word this machine's ~/.gbg/leak-terms lists — the machines' names, or anything else the owner keeps private — is published, in any case.

A repository made public publishes every commit it ever held, on every branch and tag, deleted files included; a later commit that removes a thing does not unpublish it. What is private to one owner no generic scanner knows, and a list of it committed with a package would publish it: it is kept per machine, outside every repository.

Covered by a program.

RULE.TEX.BOLDSYMBOL_BRACED

A bold symbol braces its argument.

Unbraced, it bolds the next character alone and leaves the rest of the name upright.

Covered by a program.

RULE.TEX.CODE_IN_MATH

A code identifier never sits inside a math span; inside a formula it is written \texttt{…}.

The renderer sets a run of letters in a math span as a product of italic single letters, not as a name. That remedy is for a name taking part in a formula which says more than the name itself: where the formula only names what the code denotes, the name stays a code span and a connective joins the two (RULE.TEX.ONE_SPAN).

Covered by a program.

RULE.TEX.FRAC_BRACED

Both arguments of a fraction are braced.

An unbraced fraction takes one character as its numerator and silently drops the rest.

Covered by a program.

RULE.TEX.INLINE_ONE_LINE

An inline math span opens and closes on one line, never across a list or blockquote marker.

A marker inside an open span lands in the formula, and the prose after it renders as mathematics.

Covered by a program.

RULE.TEX.LEFTRIGHT

\left and \right are not used, except in a formula the package lists in leftright_allowed, each formula listed exactly and on the owner's answer.

An auto-sized delimiter sizes to its content, so the same bracket renders at different sizes in neighbouring formulas; a size chosen with \bigl…\bigr is the same everywhere. Where a formula needs one, the owner says so for that formula.

Covered by a program. This package may set leftright_allowed; unset, it is String[].

RULE.TEX.MATHBB

Blackboard bold is written only on a capital letter or k, the glyphs the renderer has; the identity is written \mathbf{1}.

KaTeX's blackboard font covers A–Z and k alone, so anything else — a digit, the identity \mathbb{1} — silently renders as a plain glyph (GBGPeriodicFields' finding of 2026-07-17, checked against KaTeX's support table 2026-09-28).

Covered by a program.

RULE.TEX.MATHBF

Bold is admitted only for the strings a package lists, plus the identity, which every package is granted.

Bold means one thing in one package and another in the next; unlisted, it is a reader's guess.

Covered by a program. This package may set mathbf_allowed; unset, it is String[].

RULE.TEX.ONE_SPAN

A code span and a math span are never set against each other where the formula continues into or out of the name: where it says more than the name — a definition, or a symbol and then its definition — the name goes inside it as \texttt{…}, and where it only names what the code denotes, a connective joins the two. A formula finished at the edge the name sits on is not continued by it and is left as it is.

Abutting spans render as two disjoint runs at different sizes, leaving the reader to guess whether the second continues the first, qualifies it, or defines it. Apposition says which: atol ($\varepsilon$) keeps the name styled as code — clickable, and the same as every other name on the page — while \texttt{atol} is the math renderer's monospace, and a link wrapped round the whole formula makes its every operator a link to the name.

Covered by a program.

RULE.TEX.PARTIAL

A partial derivative names its index as a symbol, not as a bare letter subscript.

A bare index reads as a variable named i rather than as the direction differentiated in.

Covered by a program.

RULE.TEX.RENDERED_MARKUP

No markup shows on the built page as literal characters.

Asterisks meant to set emphasis, shown as asterisks, are the mark of prose nobody read after building.

Covered by a program.

RULE.TEX.RENDERED_MATH

Mathematics is written in a double-backtick span: never between dollar signs, and never inside a code span.

Dollars render as literal text and a code span renders as monospace; neither comes out as mathematics.

Covered by a program.

RULE.TEX.RENDERED_MATH_SITE

On the built page, every math span has rendered: none still shows its own markup.

A span that renders as its own source is a formula the reader never sees, and the source looks right.

Covered by a program.

RULE.TEX.SPACING

Spacing inside a formula is the renderer's: no thin space except before a differential, no medium or thick space, no negative thin space before a sized delimiter, and none of them doubled.

Hand spacing is tuned to one renderer at one font size and is wrong in every other setting.

Covered by a program.

RULE.TEX.SWALLOWED_ESCAPE

Inside a Julia docstring every LaTeX backslash is doubled; a single-backslash escape is swallowed by the parser.

Julia consumes the escape when it reads the string, so the formula never reaches the documentation build at all.

Covered by a program.

Judged by a reader — 29

No program can decide these. A documentation review hands each to the reader given what it needs; a rule needing more than any reader is given is reported as not judged.

RULE.API.POSITIONAL

In an operation, a required argument is positional or keyword as the package chooses, operation by operation. An argument with a default — an option, a tunable, a hint, a value that parametrises a single method however it is typed — is a keyword, whether or not it changes the result, unless its type selects among the operation's methods: then it is positional, passed as an instance. An operation that extends or mirrors a function of Base, a standard library or another package follows that function's arguments instead, and names it where the operation is documented, so a reader can compare the two signatures. Any other exception is a Switch on this rule in the package's own config, with its reason.

A keyword names its value at the call site and may be given in any order or left out; an optional positional can be neither skipped nor named, and each default adds a method to disambiguate. So an argument with a default is a keyword, as in sort(v; by, rev), round(x; digits) and solve(prob, Tsit5(); abstol), and no guideline in any language makes one positional for changing the result (researched 2026-10-06). The one exception is an optional argument whose type selects the method: Julia picks a method by its positional arguments, and a keyword reaches dispatch only through a second, internal call, so such an argument stays positional, as an instance so a later option extends it without breaking a call — round(x, r::RoundingMode = RoundNearest; digits), lu!(A, pivot = RowMaximum(); check). On a REQUIRED argument the sources part — Julia's manual gives names for an interface with many arguments, SciML's guide prefers positional and warns against abusing required keywords — and the fleet does both: GBGPeriodicFields passes required arguments positionally, the other three name required parameters, selectors among them (dealiasing::DealiasingStrategy, domain::Domain). A rule deciding it would report one package or three, so the package decides, operation by operation (the owner, 2026-10-09). A method that extends Statistics.var must take corrected as a keyword or it is no extension, and mul!(C, A, B, α, β)'s weights are positional wherever a package mirrors it: the mirrored function decides, and naming it lets a reader check the claim.

Covered by a reader given source + other documents, because this needs meaning.

RULE.ASK.PLAIN

A question reads plainly, stands on its own, and invents no word for something that already has one.

A question is read once, by someone who was doing something else. Whether it can be answered without opening anything is a matter of meaning, which no program decides.

Covered by an agent, because this needs meaning.

RULE.CIT.NO_INACCESSIBLE

Never cite an inaccessible source on any user-facing surface: not a gitignored monograph, an accompanying thesis, an appendix or figure the reader cannot open, nor working notes. Whether a link answers is RULE.CIT.RESOLVES's question, not this rule's.

A citation the reader cannot follow is the author telling themselves where they got it; the reader is left with an assertion and nowhere to check it.

Covered by a reader given other documents, because this needs meaning.

RULE.CIT.STYLE

Keep enough surnames to disambiguate two works that would otherwise collide. An eponymous method name takes no year unless the work is actually cited.

Covered by a reader given other documents, because this needs meaning.

RULE.DOC.ADMONITION_TITLE

Every !!! block carries a custom descriptive title. Where this rule's admonition_titles is load-bearing only, a block need carry one only when text elsewhere relies on the block's content; a general aside may keep its default title.

For this package the rule is what admonition_titles says: either every !!! block carries a custom descriptive title, or a block carrying one load-bearing claim does while a general aside may stay a bare !!! note. A caveat admonition is the last substantive block of a docstring, before the fields list.

Covered by a reader given other documents + siblings. This package may set admonition_titles; unset, it is always.

RULE.DOC.ALIASING_BULLET

An aliasing statement specific to one operation — one that names that operation's own arguments — lives in the bullet for its destination argument. The package-wide aliasing guarantee lives once, in the module docstring, and is not repeated per operation.

The package-wide guarantee lives in the module docstring and is not repeated per operation; an operation states it for itself only when it has an operation-specific reason, or when its contract is the contrary one.

Covered by a reader given siblings, because this needs meaning.

RULE.DOC.COORD_FREE

Maps and pairings are stated intrinsically, without flattening a structured space to a bare vector; matrix and flattening machinery appears only in the package's formalization document — the file this rule's formalization names — and nowhere when none is named. Where a basis form is needed to mirror the code, the docstring states the basis and the space it acts on.

Component notation for a genuine fiber algebra is fine; the rule targets flattening a structured space to a bare vector. Where a basis form is needed to mirror the code, state the basis and the space it acts on.

Covered by a differential_geometry reader given other documents, because this needs meaning. This package may set formalization; unset, it is ``.

RULE.DOC.COST_STRUCTURAL

Where a docstring states an operation's cost, it states it by its structure — its complexity, the number of passes, the memory it needs, or a comparison with a named operation — and, where the faster of two choices depends on the case, says which way in words. A measured figure of its speed — a timing, a ratio of times or a throughput — is not stated in a docstring, nor the hardware it was measured on: it goes, dated, to the package's performance document, which the docstring may link.

A measured figure goes stale with every benchmark sweep, and nothing checks a docstring against the next one. In GBGPeriodicFields, a feature commit put that day's ratios into exponential_convolve!; later sessions, asked whether a cost note still held, re-derived the figures and wrote more precise ones back, until three docstrings carried paragraphs of ratios by grid size, thread count, element type and GPU model in the middle of the description — and the newer figures existed nowhere else (its request, 2026-10-08). Structure stays true until the code changes, and the reader learns from it which way to choose. A program cannot tell a measured ratio from one derived from the structure (two passes against one), nor a timing from a simulated time (50 s at dt = 0.05), so a reader judges it (the owner, 2026-10-08).

Covered by a reader given other documents, because this needs meaning.

RULE.DOC.COVERAGE_BASES

An operation that reduces a field over a measure documents every base the code supports for it — the reduction over a grid and the same reduction over a point set are both stated where the operation is documented.

A measure reduction over a grid and the same reduction over a point set are both stated where the operation is documented.

Covered by a reader given source, because this needs meaning.

RULE.DOC.EMPHASIS_RARE

Emphasis is italic, and rare: a sentence carries its weight by its order first, and a word is set in italic only where, read aloud, it would be stressed against what the reader expects, or where a term is defined. Italic is never set inside italic, where it does not show, nor beside bold or quotation marks on the same words; capitals and underlining are never emphasis.

Emphasis marked everywhere marks nothing: the authorities who agree that it is italic agree that it is occasional, and that a sentence places its stress first by putting the stressed words at its end or its start (Fowler's ITALICS, 1926; Strunk's rule 18; Gopen and Swan, 1990). A defined term is italic where it is defined and roman after. Markdown has no underline, and on a Documenter page italic inside italic stays italic, so the reversal LaTeX makes is lost. Whether a stress is earned, or a word is a definition, is a reading of the sentence, so a reader judges it; where bold may stand is RULE.DOC.EMPHASIS's (the owner, 2026-10-16).

Covered by a reader given nothing, because this needs meaning.

RULE.DOC.GRAMMAR

Every sentence has a subject and a verb; concise means few words, not missing verbs.

Concise means few words, not missing verbs — compact prose that still reads as sentences aloud.

Covered by a reader given nothing, because this needs meaning.

RULE.DOC.HOME_ORDER

A function docstring is ordered: identity, when-to-use, arguments (under # Arguments where RULE.DOC.ARGSFORM asks for the list), one formula, citation, links, caveats, then # References, then # Fields last. Implementation internals and design rationale are excluded; so is any term that neither the surrounding sentence nor the package's notation page — the file RULE.DOC.ONENOTATION's notation_page names — defines.

In full: (1) a plain one-sentence identity in the user's terms; (2) when to use it, versus the alternatives; (3) each argument (positional and keyword) and its effect, bound in prose or listed under # Arguments as RULE.DOC.ARGS_FORM decides; (4) one formula if a clean one exists, never overflowing; (5) an inline citation for a named or published method and none for a classical one; (6) cross-links; (7) the caveats a user needs, as an admonition where load-bearing — the last block of the home's PROSE. Then the sections that are not prose, in this order and no other: the # References section of RULE.CIT.FULL_INLINE, then # Fields, which is last (RULE.DOC.FIELDS). Three rules each used to claim the end of a docstring; the order lives here, and they defer to it. Excluded: implementation internals (a # comment), unexplained specialist jargon, architectural rationale and the formal apparatus (the rationale documents).

Covered by a reader given other documents.

RULE.DOC.LEADING_IDENTITY

Item (1) of a docstring is one plain sentence saying what the operation computes — the physical meaning first, or the estimand first, as this rule's leading_identity sets for the package. Whether that sentence is true of the code is RULE.DOC.VERIFIED's question, not this rule's.

For this package the identity leads with what leading_identity names: an operation computed in a derived representation still states what it does to the real object first — with the explicit relation — and gives the derived form it uses after; an estimator states the population quantity it estimates, in standard probability notation, before the estimator. Where no clean form exists, say so briefly rather than forcing one.

Covered by a reader given other documents, because this needs meaning. This package may set leading_identity; unset, it is physical meaning.

RULE.DOC.LITERATE

In the source file of a Literate example, every full-line # comment is prose that will render, any mathematics in such a comment is LaTeX, and a comment inside control flow is written ## so that it does not render. The rule is judged on the source file; what the page made of it is RULE.DOC.LITERATE_RENDERED's question.

A full-line comment inside a control-flow block splits the code fence, so reserve full-line # for narrative prose at statement boundaries. An underscored identifier in that prose is backticked, or Markdown parses it as an italic span.

Covered by a reader given nothing.

RULE.DOC.LITERATE_RENDERED

The built page of a Literate example shows its prose as prose: no stray #, no italics or code block that a comment's underscores or indentation produced, no mathematics split or broken across comment lines, and no comment landing inside a code fence. The rule is judged on the built page.

What a # comment becomes is decided by Literate and then by Markdown, and neither is visible in the source: a_b and c_d renders as italic, a comment beginning # 1. becomes a list item, four spaces of indentation become a code block, and mathematics split across two comment lines is not mathematics. The habits in the source are RULE.DOC.LITERATE's; this rule reads what they produced.

Covered by a reader given rendered.

RULE.DOC.MODULE_MAP

A module docstring lists one linked one-liner per operation family and no formula.

Its order is identity, then the contents list, then an optional trailing remark.

Covered by a reader given siblings.

RULE.DOC.ONE_HOME

One concept, one home: one docstring per operation on the bare binding; the ! form owns the formula and is listed first; every other variant is a thin wrapper that @ref-links the home and carries no second formula.

Per-scheme or per-representation specifics live in the scheme's or the representation's own docstring, linked. Across an f/f! pair the in-place ! form is the home — it owns the formula and the kernel and is listed first — and the allocating form and any operator alias is a thin wrapper that leads with the one-sentence meaning and @ref-links the home, carrying no second copy of the formula.

Covered by a reader given siblings.

RULE.DOC.ONE_NOTATION

One symbol denotes one concept and one concept is denoted by one symbol, as the package's notation page records — the file this rule's notation_page names; a local use that conflicts with the notation page is the one that changes.

Before introducing a symbol, check it is not a synonym for one already in use, and check the section for the glyph and confirm it is free. When an edit introduces a symbol, retire the old one.

Covered by a reader given other documents + siblings, because this needs derivation. This package may set notation_page; unset, it is docs/src/notation.md.

RULE.DOC.RETURNS

A type docstring leads with its constructor. A function docstring whose identity sentence does not name the result states it with a '-> Type' arrow or a 'Returns x.' sentence. Whether the stated result is what the code returns is RULE.DOC.VERIFIED's question, not this rule's.

A mutator whose signature carries no arrow says what it returns in a sentence before any caveat; a signature carries an arrow only where the return type is fixed by the signature; arrow and sentence never both appear.

Covered by a reader given nothing.

RULE.DOC.SELF_CONTAINED

A docstring, a page, and the one rationale document this rule's architecture_doc names read top to bottom without another file: every symbol is bound in plain language at first use. Every other rationale document is exempt, since it explains one architecture and may assume the rest of itself.

Later uses may be bare; universally standard mathematics may stand unglossed. The exemption is not indulgence: holding a design document to a cold read means re-binding the same vocabulary on every page, which is what the one-home rule forbids.

Covered by a reader given nothing, because this needs reading order. This package may set architecture_doc; unset, it is docs/ARCHITECTURE.md.

RULE.DOC.STEER

Every ! form with an allocating sibling carries the in-place steer sentence, verbatim from the template this rule's why gives, with destination replaced by the ! form's own destination argument and f by the allocating sibling's name.

The sentence is a template, not a link: destination is replaced by the argument the signature actually has and f by the allocating sibling's own name, written as an @ref link, so the link resolves. The template: Use this in-place form when destination is already allocated; the allocating f returns a fresh result instead.

Covered by a reader given siblings + other documents.

RULE.DOC.TERMS_DEFINED

A term of art is defined in a clause, or @ref-linked to its definition, before its first use on the same page. The test is a cold read of that page alone, and it is asked of docstrings, of pages, and of the one rationale document this rule's architecture_doc names; every other rationale document is exempt.

A docstring can bind every symbol and still be unreadable to someone who has not read the module, because its terms of art are nouns, not symbols; parse it with the module's context withheld, and a noun that silently assumes the package's context is the defect. A design document is read the other way round, by someone who has the architecture in hand, and holding it to a cold read means defining the same nouns on every page.

Covered by a reader given nothing, because this needs meaning. This package may set architecture_doc; unset, it is docs/ARCHITECTURE.md.

RULE.DOC.TWO_TIER

A module docstring is a map: one linked one-line entry per operation family, and no formula. A function docstring is a home: the one place where that operation's identity, arguments and defining formula are stated in full.

The map states what the module is, its scope and place in the architecture, and its invariants — then a linked one-liner per operation family, and no formulas; every formula lives in the operation's own docstring.

Covered by a reader given siblings, because this needs reading order.

RULE.DOC.VARIANT_PAIR

Across an f/f! pair or a getter/setter pair, the defining mathematics appears once, in the docstring of the member that is the home under RULE.DOC.ONE_HOME; the other member carries no display formula. The pair is one unit for this rule.

Typed twice, the math drifts — one member writing a partial one way and its twin another — and a within-string check cannot see it; a lane that groups each operation's generics and diffs them can.

Covered by a reader given other documents.

RULE.DOC.VERIFIED

Every formula, normalization, adjoint relation and cross-scheme equivalence stated in the documentation is true of what the code computes, established by expanding the statement against the code, never taken on the docstring's word.

A plausible 'X is just Y' is a false claim until the expansion matches. Run this as a positive verification — enumerate every formula, constant, relation and quantifier and verify each — not as a read-through; a false-but-plausible statement is as invisible as an unbound symbol. Category and type errors are their own class: an object conflated with its representation, an operator with its parameter, a rate with its time-integral, a scalar with the field it reduces; type every object from the code.

Covered by a reader given source, because this needs meaning.

RULE.TEX.CODE_SPAN_JULIA

A code span holds literal code or input in some language — Julia, shell, TOML, a path, LaTeX source — and never mathematics, which is written as math.

Code formatting marks text to be typed or read as code in any language: a shell flag, a path, an environment variable, a TOML key, LaTeX source on a notation page. A half-open interval, an inequality, a product, a lone ≤ or · glyph is mathematics and is set as such; the real operators ×, ⋅ and ≈ backticked are code and stay. Covered by a reader given nothing.

RULE.TEX.GREEK_AB

RULE.TEX.IMAGINARY

The imaginary unit is upright \mathrm{i}; i, j, k are indices.

Never a bare italic i, never \imath or \mathbb{i}; the differential is likewise upright, \,\mathrm{d}x.

RULE.TEX.NO_HSCROLL

Glossary

The terms the rules use. A rule may use any of these without defining it; a term not here is defined where it is used, or it is not a term of art.

  • consumer — a package that pins this one and receives its wiring.
  • rule — one statement with one check and the examples that show the check matches it. Its id is RULE.<FAMILY>.<NAME>, stable for the life of the rule.
  • check — what decides that a rule was broken: a program, or an agent where no program can.
  • clause — one requirement of a statement. A rule with three clauses owes three breaking examples and three complying ones.
  • switch — a package turning a rule off, wholly or for named files, with its reason. It replaces the exemption ledger: there is no expiry and no ceremony, only a reason a reader can weigh.
  • deferral — a package saying a rule is owed here and not yet met, with what would close it. A switch is an answer; a deferral is a question with a condition on it. It fails no build.
  • file set — which of a package's files a rule runs over: docstrings, code, pages, rationale, Literate examples, tests.
  • finding — one violation at one location, with the rule that found it.
  • location — where a finding is: the file, the node (a binding, or a heading path), the quote as it read then, and the line as a hint only.
  • generated file — a file written by a Julia function of this package. Editing one by hand is drift, which the wiring check reports and gbg sync repairs.
  • pin — the one version of this package a consumer uses, named in its sub-environments.
  • intention — whether a change or a finding is in documentation or in code. Documentation is safe to fix without asking; code is not.
  • operation family — an operation together with its variants: the allocating and in-place forms, a getter and its setter, the methods of one name across representations. A module map lists one entry per family; the family's home docstring is the one RULE.DOC.ONE_HOME names.
  • instrument — one review procedure with one question, started only on the owner's request.
  • run — one execution of one instrument, with its own record, its own report and its own id. A run never starts another.
  • stage — one step of a run, in a fixed order. The session launches each; a stage out of order is refused.
  • reader — an agent given some of the documentation and asked what is wrong with it. Which readers a review has follows from the rules, not from a list.
  • bundle — what a reader is given: one built page alone, the whole documentation with the source, or the built site. A rule's tag says which bundle can judge it.
  • unit — the one page a reader of the first bundle is given. That reader is launched once per unit, so that what it cannot see is what the rule needs it not to see.
  • pass — one round of fixing and verifying inside a run. A documentation review makes one, after which what is still open goes to the owner's queue.
  • verifier — an agent that judges whether the fixes of one place fixed their findings, with the text as it now stands and the diff of the pass in front of it.
  • cover — what decides a rule is broken: a program, a reader, or nothing, the last being an instruction the session follows while working.
  • discipline — a field of expertise a package declares it needs a reader to have. A rule naming a discipline the package does not declare is a gap.
  • gap — a rule no reader of this package can be given what it needs to judge. A run says so at every launch and first in its report.
  • settled — a decision the owner has already given, kept in .gbg/settled.jl and given to every reader as "do not report this again".
