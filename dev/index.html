A consumer holds data; the tool holds behaviour; the only thing connecting them is a pin.

GBGCodingTools is the one shared tooling package of the GBG Julia packages — GBGPeriodicFields, GBGIsotropicTurbulence, GBGStreamingStatistics, GBGCloudPhysics — and of itself. It holds the four review instruments (/check-docs, /check-consistency, /bug-hunt, /audit-changes), the docs-build wrapper and its deterministic scans, the test harness the consumers' suites call, the read-only doctor, and the policy prose every consumer imports, at one version pinned by every consumer through its sub-environment Project.toml files.

What a consumer has

A consumer carries a .gbg/ directory: one config file, one exemption ledger, its domain hats (the reviewer personas of /check-consistency, one per aspect of the package's field), its seed catalogue, the rendered policy copy, and its review rounds. Everything else — the skill stubs, the Stop hook, the CI fragments, the managed blocks of CLAUDE.md and .gitignore — is rendered by gbg sync from the pinned templates and checked by gbg doctor. The consumer's docs/make.jl calls GBGCodingTools.makedocs, which runs the quick doctor, the hard scans and the closure gate around Documenter.makedocs; its test/runtests.jl calls TestHarness.gate and TestHarness.run_regressions.

The module

GBGCodingTools — Module
GBGCodingTools

The one shared tooling package of the GBG Julia packages: the review instruments, the docs-build wrapper and its scans, the test harness, the doctor and the policy prose, at one version pinned by every consumer.

A consumer is a package that uses the tool — one of the four sibling GBG packages, or the tool itself; a pin is the tool version the consumer names in .gbg/config.toml (tool.version: a released X.Y.Z, or dev for a checkout), which gbg sync renders into the consumer's sub-environment compat entries. A consumer holds data; the tool holds behaviour; the only thing connecting them is that pin.

The module is a map; every part is documented at its home. The command line and its configuration:

  • main — the one entry point of gbg <noun> <verb>; the exit contract is 0 clean, 1 substantive finding, 2 cannot evaluate, 3 crash. The verbs live under src/CLI/, one file per noun, each verb a function returning its exit code.
  • Config — Config.read loads and validates a consumer's .gbg/config.toml.
  • makedocs — the mandatory wrapper around Documenter.makedocs (defined by the Documenter extension; declared in DocLints).

The engines:

  • TestHarness, Reflection, Witnesses — the Julia-side engines a consumer's tests and the instruments call.
  • scan_docs, scan_html, register_scan! — the deterministic text and built-HTML scan engine over catalog/scans.toml, one function per scan id under src/Scans/.
  • TreeHash — git blob and tree hashing on the SHA stdlib, behind gbg self verify.
  • HtmlWalker — the Gumbo walker shared by the consolidator and the built-HTML scans.
