The config

Written by AI, not regularly reviewed

This page is written by AI and is not reviewed regularly by a human.

.gbg/config.toml is the one config file of a consumer: one layer, closed keys, validated by schema/config.schema.json through the tool's own validator. gbg init writes it from the package tree; gbg config --toml prints it with every default materialised; gbg schema config prints the schema.

The sections: [tool] (the pinned version), [package] (name, description, modules, the test and build commands), [paths], [git], [surfaces] (the ONE copy of every surface list: rationale documents, pages, generated copies, source, extensions, Literate examples, the built site, the history and references anchors, the glossary file, and any data or script surface whose comments are prose), [docs] (doctest, admonition titles, the Base allowance, retired claims), [rubric], [notation], [citations], [instruments] with one table per instrument, [cost], [schema], [[scans.custom]].

Five values vary by package and are substituted into the rendered policy: rubric.leading_identity, notation.vectors, docs.admonition_titles, notation.mathbf_allowed (which never forbids \mathbf{1}, the indicator and identity every package is granted) and instruments.check-docs.argcov_policy, the tier RULE.DOC.ARGCOV binds at. Everything else about the instruments is a constant of the tool, and changing one is a MAJOR release.

GBGCodingTools.Config.read — Function
read(root = find_root(); check = true) -> Dict

Loads <root>/.gbg/config.toml, validates it against schema/config.schema.json, materialises every default and checks every path. The arguments are:

  • root — the consumer root, found by walking up from the working directory when not given.
  • check — whether to run the path check (false for a config read from a tree that is not fully present).

Returns the validated Dict with cfg["root"] set; throws a ConfigError otherwise.

GBGCodingTools.Config.parse — Function
Config.parse(text; root, check = true) -> Dict

The same validation, materialisation and path check as Config.read over the TOML text of a config instead of the file under root/.gbg/ — what the self-tests and the Step-0 scratch runs use to describe a tree without writing into it. The arguments are:

  • text — the config as TOML.
  • root — the tree it describes.
  • check — whether to run the path check.

Returns the validated Dict with cfg["root"] = root.

GBGCodingTools.Config.surface_files — Function
surface_files(cfg, key) -> Vector{String}

The files of one surface key of cfg["surfaces"] — rationale, pages, src, ext, literate, data, or the compound keys docs (rationale + pages + literate) and all (docs + src + ext) — relative to the root, each file once, sorted. Generated pages (surfaces.generated.globs) are removed from pages, since they are build products. Returns the list.

GBGCodingTools.Config.resolve_anchor — Function
resolve_anchor(root, anchor) -> (file, line, count)

Resolves a file#heading ANCHOR — this sense of the word only, a Markdown reference to one heading. A hat's or lane's anchor is a different thing (whether it runs at full strength rather than on the economy model, Preflight.resolve_hats), and a seed class's a third (Seeds.select). Here: file relative to root, heading a prefix of the text of exactly one Markdown heading (any # level) in it. Returns the file, the 1-based line of the match and the number of headings that matched — 0 or 2+ is a config error to the caller; the line is 0 when the file is absent or nothing matched.

GBGCodingTools.validate — Function
validate(schema, value; root = schema, path = "$") -> Vector{String}

Validates value against schema (a Dict in the JSON-Schema subset above). The arguments are:

  • schema — the schema node to apply.
  • value — the parsed document (TOML.parsefile or JSON3.read into a Dict).
  • root — the document the $refs resolve against; callers pass schema itself.
  • path — the JSON path of value in the messages ($ at the top).

Returns every violation as a message naming its path; an empty vector means valid.

source
GBGCodingTools.load_schema — Function
load_schema(name) -> Dict

Reads schema/<name>.schema.json from the running copy into a Dict (JSON3, mutable copy). Returns the schema; a missing file is an ArgumentError naming it.
