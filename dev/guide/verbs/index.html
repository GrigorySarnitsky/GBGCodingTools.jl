The verbs

Written by AI, not regularly reviewed

This page is written by AI and is not reviewed regularly by a human.

gbg <noun> <verb> is the whole command line; the table is closed, and every verb below is rendered from its own docstring so the page cannot drift from the code. The exit contract is one for all: 0 clean, 1 a substantive finding (the gate's refusal over an open round is one), 2 cannot evaluate (a precondition not met, missing input, torn file), 3 crash.

Entry point

GBGCodingTools.main — Function
main(args) -> Int

The one entry point of the command line: the shim execs julia -e 'using GBGCodingTools; exit(GBGCodingTools.main(ARGS))', and every test of a verb calls it directly. Dispatches <noun> <verb> (or a lone noun) through VERBS and returns that function's exit code: 0 clean, 1 substantive finding, 2 cannot evaluate, 3 crash. A --dev first argument sets GBG_DEV=1 so the stamps read dev+<sha>, exactly as the shim's --dev route does. An exception escaping a verb is printed with its backtrace to stderr and returns 3, so a crash is never read as a finding; an unknown verb prints the table and returns 2. Output is never truncated.

source
GBGCodingTools.parse_options — Function
parse_options(args; valued = String[]) -> Options

Parses args into an Options record. Any --name=value is a value whatever valued says; an option named in valued also consumes the following bare argument as its value; every other bare --name is a flag; a lone -- ends option parsing. The arguments are:

  • args — the command-line arguments to parse, in order.
  • valued — the names, without the dashes, of the options that take a value.

Returns the parsed options; an option that is in valued but has no value is an ArgumentError.

source
GBGCodingTools.Options — Type
Options

The parsed command line of one verb: the positional arguments in order and the options by name.

The fields are:

  • positional — every argument that is not an option, in order.
  • flags — the options given without a value (--deep, --dry-run), as a set of names without the dashes.
  • values — the options given with a value (--only LOAD, --reason "…", --profile=core), name to value.

Machine and self

GBGCodingTools.cmd_install — Function
cmd_install(args) -> Int

gbg install [--dev-checkout <path>]: copies the running copy's bin/gbg to ~/.local/bin/gbg with mode 755 and, with the option, writes the one-line pointer ~/.gbg/dev. Runs from whichever copy Pkg resolved for the calling environment — no depot glob is ever expanded. Returns 0 when the shim is written, and the ~/.gbg/dev pointer with it under --dev-checkout, 2 when the Julia in use is below the floor, when --dev-checkout names a directory that is not a GBGCodingTools checkout, or when ~/.local/bin is not on PATH (the shim would be installed but never found).

source
GBGCodingTools.self_verify — Function
self_verify(root = Config.find_root(); io = stdout) -> Int

Recomputes the git tree hash of the copy this process runs from (pkgdir(GBGCodingTools), through TreeHash.tree_hash) and compares it with what Pkg.dependencies() reports for the tool in the active environment and with the git-tree-sha1 every sub-environment manifest under root records; asserts the dependency entry is is_tracking_repo && !is_tracking_path (a Pkg.develop'd copy lives inside the depot, so only the flags tell it apart). The arguments are:

  • root — the consumer root whose sub-environment manifests are compared; nothing (no root found) leaves only the active environment's entry to compare against.
  • io — where the one line per comparison is printed.

Returns 0 when every comparison agrees, 0 with a WARN when the running copy is a working tree (pinned at dev) or no manifest exists to compare against, and 2 for a disagreement or a developed copy — an edited pinned tree is never allowed to grade a round.

GBGCodingTools.cmd_self_verify — Function
cmd_self_verify(args) -> Int

gbg self verify: the command-line face of self_verify; run by every gbg round verb and by gbg gate before anything else. Returns its code: 0, or 2 for an edited or developed pinned copy.

Consumer setup

GBGCodingTools.Init.init — Function
init(root = pwd(); migrate = false, dry_run = false, io = stdout) -> Int

gbg init [--migrate] [--dry-run]: seeds a consumer. The arguments are:

  • root — the package root (the directory holding Project.toml).
  • migrate — also convert the test baselines and a former seed_defects.py, and write .gbg/scratch/commit-message.txt for the migration commit.
  • dry_run — print what would be written, write nothing.
  • io — where the report goes.

It writes .gbg/config.toml from the tree, an empty ledger, .gbg/rounds/.keep, a placeholder persona for every domain hat without one (Preflight.resolve_hats binds the term), the seeded-once files that are absent (test/Project.toml, docs/make.jl, test/runtests.jl, test/regressions/, docs/ROADMAP.md, docs/prose_shape.csv), and the tool's entries into docs/, test/ and every sub-environment that lists the tool. It refuses an existing .gbg/config.toml (exit 2) unless dry_run, which previews over one rather than refusing, a preview writing nothing. Returns the exit code.

source
GBGCodingTools.Init.migrate_baselines — Function
migrate_baselines(root = pwd(); dry_run = false, io = stdout) -> Int

gbg migrate baselines: the textual converter from the consumer's existing test files to the three frozen TOML baselines TestHarness reads. The arguments are:

  • root — the package root.
  • dry_run — print the TOML instead of writing it.
  • io — where the report goes.

The .jl files are read, never included or edited. A literal not found is reported and skipped (exit 0); a literal that does not parse to its closing paren is exit 2 naming the line; an existing TOML is refused (exit 2) unless dry_run. Returns the exit code.

GBGCodingTools.Init.new — Function
new(pkgname; parent = pwd(), io = stdout) -> Int

gbg new <Pkg>: init for a fifth package. The arguments are:

The package tree must already exist with a Project.toml. Besides init, it seeds CLAUDE.md from the skeleton and adds a [[consumer]] row to the dev checkout's fleet.toml. Returns the exit code.

GBGCodingTools.Sync.sync — Function
sync(cfg; check = false, io = stdout, ledger = Ledger.read(cfg)) -> Int

gbg sync [--check]. The arguments are:

  • cfg — the validated config.
  • check — compare only, write nothing.
  • io — where the status lines go.
  • ledger — the ledger entries.

It renders every managed file and block, seeds .claude/WORK_QUEUE.md when absent, writes the tool's entries into every sub-environment Project.toml that lists it, inserts the CI fragments, and rewrites .gbg/managed.json; idempotent. It refuses (exit 2) on a MODIFIED or UNMANAGED file and writes nothing then. With check = true the exit is 1 when anything would change, else 0. Returns the exit code.

GBGCodingTools.cmd_config — Function
cmd_config(args) -> Int

gbg config --toml|--json [--effective]: prints the validated config with every default materialised — the object Config.read() returns in-process. --toml (the default) prints TOML, --json prints JSON; --effective adds the machine facts read at run time (hostname, Threads.nthreads(), the Julia version and the running tool version) under a [effective] table. GBGCodingTools.Doctor.run — Function
run(cfg; only = nothing, deep = false, io = stdout, json = false, effective = false) -> (checks, code)

Runs the selected checks over a consumer and prints the table. The arguments are:

  • cfg — the validated config.
  • only — ids, id prefixes or the literal QUICK to restrict the run to; every non-deep check when nothing.
  • deep — include the --deep checks (they run builds, tests and witnesses).
  • io — where the report goes.
  • json — print the results as JSON instead of the table.
  • effective — print the effective config after the table.

A FAIL on an exemptable id that a live scope = "check" ledger entry names becomes a WARN carrying the entry's reason. Returns the results and the exit code: 1 on any FAIL, else 0.

GBGCodingTools.scan_docs — Function
scan_docs(cfg; hard_only = false, only = nothing, io = stdout) -> (results, code)

Runs every catalogued text scan (and the consumer's [[scans.custom]] rows) over the source surfaces and prints the full report: every hard hit and every triage hit, never truncated. The arguments are:

  • cfg — the validated config.
  • hard_only — run the hard tier alone (what makedocs calls).
  • only — a list of ids or id prefixes to restrict the run to.
  • io — where the report goes.

The exit code follows the contract: 2 when any scan is DEAD (measured nothing, or raised), else 1 when any hard scan has a hit, else 0; triage hits never change it. Returns the results and the code.

GBGCodingTools.gate — Function
gate(cfg, instruments...; io = stderr) -> Int

The closure gate: whether an open round blocks a build, a test or a release here. The arguments are:

  • cfg — the validated config.
  • instruments... — the instruments whose open rounds block, an instrument being one of the four review procedures GBGCodingTools binds (all four when none is named).
  • io — where the refusal is explained.

It scans EVERY round directory under .gbg/rounds/. An open round of a named instrument is exit 1, naming it — except the rounds named in GBG_ROUND (comma separated), which the CLI exports only while it runs a build, a test or an executable claim on behalf of that round. An open round of a disabled instrument is exit 1 (CFG.VALID).

In a working tree (no CI variable) an open round whose directory is untracked or modified while HEAD ≠ ROUND.head is exit 1: the fixes were committed without the round. A round directory without ROUND.toml is exit 2; .gbg/rounds/ absent while instruments are enabled is exit 2 (ROUND.DIR). gbg self verify runs first and its exit 2 is the gate's. Closed rounds are never re-graded here. Returns the code.

GBGCodingTools.gate_problems — Function
gate_problems(cfg, instruments...; io = devnull) -> (fatal, problems)

What gate refuses for, each problem a kind => message pair. The arguments are:

  • cfg — the validated config.
  • instruments... — the instruments whose open rounds block (all four when none is named).
  • io — where a round directory without a valid ROUND.toml is announced.

The kinds are :open, an open round of a named instrument that GBG_ROUND does not admit; :disabled, an open round of a disabled instrument, whatever was named; and :committed, outside CI, an open round whose files are untracked or modified while HEAD moved past its opening head — the fixes were committed without the round. fatal is a round directory without a valid ROUND.toml, which the gate reports as exit 2. It lists the round-based refusals only: gate's self-verify and ROUND.DIR refusals come before it and are not problems here, so an empty list is not a passing gate. Returns the flag and the problems in round order.

source
GBGCodingTools.frozen_rounds — Function
frozen_rounds(cfg, instruments...) -> Vector{String}

The open rounds of instruments that gate refuses a build for here — every open round of a named instrument except those GBG_ROUND admits. The arguments are cfg, the validated config, and the instruments to ask about (all four when none is named).

A build refused ONLY for these is frozen, not broken: the docs wrapper prints a skip line and exits 0, so a red docs run keeps meaning something is broken rather than meaning a round is open. gbg release and the deep doctor set GBG_DOCS_NO_SKIP, which turns the skip back into the refusal — a release never accepts a build that did not happen. Returns the round names.

Rounds

GBGCodingTools.Preflight.preflight — Function
preflight(cfg, instrument; profile = nothing, hats = String[], strength = "economy", no_seed = false, dry = false, base = nothing, io = stdout) -> Int

gbg preflight <instrument> [--profile all|core|explicit] [--hats a,b] [--strength full] [--no-seed] [--dry] [--base <commit>]. The arguments are:

  • cfg — the validated config.
  • instrument — one of check-docs, check-consistency, bug-hunt, audit-changes, the four review procedures GBGCodingTools binds.
  • profile — the check-consistency profile (all, core, explicit); the config's when nothing.
  • hats — the keys an explicit profile names.
  • strength — economy (the default) or full.
  • no_seed — open an unseeded round; it applies to check-consistency and, where the config turns seed_rounds on, to check-docs.
  • dry — open and write nothing; print the round id and paths that would be used.
  • base — the audit's base commit (required for audit-changes).
  • io — where the protocol, the call and the next step are printed.

It runs the quick doctor set — the QUICK selection of GBGCodingTools.doctor — CFG.TORN and gbg self verify; refuses (exit 2) an open round of this instrument or an uncommitted change under a closed or abandoned round; opens the round (writes ROUND.toml, never git add); copies the scripts and writes the payloads; prints the protocol, the Workflow call and the next step. Returns the exit code.

source
GBGCodingTools.Preflight.dev_round — Function
dev_round(cfg, instrument, st) -> Union{Nothing,String}

The refusal when a documentation round would open with no released instrument to name, or nothing when it may open. The arguments are:

  • cfg — the validated config.
  • instrument — the instrument the round was asked for.
  • st — the stamps Preflight.stamps computed for it.

A /check-docs or /check-consistency round is a measurement, and a dev-stamped round is unclosable: a round graded by an unreleased tool compares with nothing and can be cited by no release. That refusal belongs where it can still be acted on — the round is not opened, and nothing is spent — rather than after the record is frozen and every verb refuses. An audit or hunt round reads base..HEAD and is off-tag by construction, so it is never refused here.

The limit: this is the tool's own root, where the stamp is the working tree's. A consumer driven by gbg --dev still records a dev stamp; PIN.NOT_DEV warns while it does, and ROUND.DEV names the round afterwards.

GBGCodingTools.Rounds.prepare — Function
prepare(cfg, round; io = stdout) -> Int

gbg round prepare <round>, by instrument (GBGCodingTools binds the term). The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • io — where the report goes.

check-consistency: the docs build under GBG_ROUND (exit 0 required; the log path is printed otherwise), the two manuscripts consolidated into the payload directory, and — when the round is seeded — the seeds planted in place.

check-docs: scan docs with every hard hit banked as lane 00-scans, the reflection checks, the build under GBG_ROUND, scan html (its hard hits banked too), the full report saved, and — when the round is seeded — a seeded copy of the lane files under the round's seed_root, which the lanes read in place of the working tree.

Either way the ground truth is NOT written here; bank writes it. audit-changes: the diff, diffstat and claims regenerated. bug-hunt: nothing to prepare. Returns the exit code.

GBGCodingTools.Rounds.bank — Function
bank(cfg, round; io = stdout) -> Int

gbg round bank <round>. The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • io — where the classification and the recall are printed.

It validates every expected lane file, records each classified file's sha at first sight (lane_shas; a DEAD lane's file is not recorded, and Rounds.rerun forgets the sha of a lane it re-runs), classifies (DEAD, REJECTED, EMPTY, TRUNCATED), assigns ids <round>/<lane>#<n>; re-banks the findings carried into this round from the previous one; for a seeded round regenerates the unseeded manuscripts, recomputes the ground truth, marks seeded findings, prints recall per class and SUSPECT hats; for a hunt runs the witness runner over witnesses/ expecting failure and freezes the disposition records; writes findings.json and findings_sha, findings.md and SUMMARY.md.

Five things make it exit 2: a round already banked; any DEAD or REJECTED lane; a carried finding naming a lane this round does not run, which means the roster changed under it; on a hunt, a witness the runner could not decide (hunt_bank! returns its own code); and a banked finding that does not validate against the core finding schema.

lane_shas reaches ROUND.toml on the DEAD-or-REJECTED exit and on success, and only there: the other three return before the record is saved, so a first-sight sha seen on such a run is not kept.

findings.json is frozen on no refusal. By the last exit, a finding that does not validate, a hunt's reproductions/ and a seeded round's ground_truth.json are already written, so a re-bank rewrites them rather than creating them; the hunt's own refusal returns before reproductions/ is written. Returns the exit code.

rerun(cfg, round, lanes; io = stdout) -> Int

gbg round rerun <round> --lanes a,b: prints the call to the instrument's Workflow (its workflow/*.js script) restricted to the lanes the last bank could not evaluate — DEAD or REJECTED, the two it records together in dead_lanes. The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • lanes — the lane keys.
  • io — where the call is printed.

A live lane is refused; the first-sight sha of each named lane is forgotten, since the re-run replaces its file. Returns the exit code.

GBGCodingTools.Passes.pass_open — Function
pass_open(cfg, round; regrade = false, sweep_ok = false, full_state = false, io = stdout) -> Int

gbg round pass open <round> [--regrade] [--sweep-ok] [--full-state]: opens a verification pass. The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • full_state — kept for the command line; it changes nothing, since the state verifier (GBGCodingTools.Passes binds both verifiers) reads every id in scope on every pass.
  • regrade — accept a changed stamp (config_sha, or the tool stamps) and re-stamp it; the round is re-graded from here, and the pass records regrade = true.
  • sweep_ok — open even though an open finding names a file the fix pass did not touch (Passes.unswept), for the fix that rightly lives somewhere else.
  • io — where the calls and messages are printed.

A pass after the first verifies only what Passes.pass_scope returns, and refuses to open at all while an open finding's own named locations are untouched by every fix pass since bank, since a pass spent discovering that a fix stopped at the line it quoted is a pass wasted.

The act verifier grades the OPEN ids against this fix pass's diff; a closed id back in scope is a re-check, read by the state verifier alone, because the question is whether it regressed and its fix is not in this diff. It refuses, too, once the pass budget is spent (pass_budget): the round then closes by carrying what is still open.

It refuses a changed config_sha unless regrade, and a regrade never re-stamps a tool_tree_sha that moved under an unchanged released tool_version — the tag moving, which close refuses; it creates verdicts/pass-<k>/pass.toml with the nonce, head, range = <opening head>..HEAD, the scope, the expected verdict count per lane and the stamps; for the doc instruments rebuilds under GBG_ROUND and regenerates the manuscripts; writes the findings' unabridged text as a payload file; prints the verifiers' Workflow calls rendered by Preflight's renderer. Returns the exit code.

source
GBGCodingTools.Passes.grade — Function
grade(cfg, round; io = stdout) -> Int

gbg round grade <round>: grades the latest pass. The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • io — where the tally lines are printed.

It validates the pass's verdict files (a wrong nonce or sha is REJECTED, an absent file with a non-zero expectation is DEAD ⇒ exit 2), carries forward the entry of every id outside the pass's scope (they were closed and nothing since went near what they name), applies the demotion to the rest, then the closure channels per id — honored, adjudicated, seeded, rescan; for a hunt the disposition records and the witness re-run; for an audit the disposition gate after the severity re-check — and writes tally.json and tally.md with the pass series and the plateau signal.

A re-checked id — closed earlier, back in scope — keeps the act verdict that closed it: it stays closed while the state verifier still reads it absent, and reopens when that reading finds it back.

Exit 1 while open_ids is non-empty, and equally while any id is pending_state — read by the act verifier and not by the state verifier, the two verifiers GBGCodingTools.Passes binds — 0 only when every id is closed.

source
GBGCodingTools.Passes.close — Function
close(cfg, round; carry = String[], io = stdout) -> Int

gbg round close <round>: checks every closing condition in the instrument's order and stamps the round closed. The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • io — where the refusals are listed.

The conditions: the latest pass fully closed, no dead lane, the round's files committed, the stamps unchanged (tool version and config, else regrade; tool tree sha, else abandon-only), the opening head an ancestor of HEAD, the dismissal auditor run over every adjudication and refusal with reopened == [] (its Workflow call is printed when it has not run), the hunt's witness, promotion, test and audit conditions, and for a check-docs round whose fix pass changed code, Passes.audit_after_code. Then closed, closed_head and the tally sha are stamped.

carry names the ids this round closes by carrying them into the next round of its instrument, which carry_conditions gates. Once the pass budget is spent (pass_budget) an empty carry means every id still open or never blind-read, and a serious one rides too: its severity then decides whether a final release may cite the round, not whether the round may close.

Returns 0 when closed, 1 when a condition is unmet — a moved config_sha or tool_version among them, since a regrade answers those — and 2 for a tool_tree_sha that moved under an unchanged tool_version, which is the tag itself moving.

That last one leaves the round abandon-only: pass open --regrade re-stamps config_sha, tool_version and tool_rev, and never tool_tree_sha under an unchanged non-dev tool_version, so no regrade can make a moved tag read as unmoved.

source
GBGCodingTools.Passes.audit_after_code — Function
audit_after_code(cfg, rec) -> Vector{String}

RULE.INST.AUDIT_AFTER_CODE for a documentation round: the refusals when the fix pass of the round rec changed code and no closed /audit-changes round based at its opening head read the LAST of that code — an audit closed before a later fix pass touched src or ext again covers what it saw, not what came after. The arguments are cfg, the validated config, and rec, the round record. A pass that touched only prose is not gated. Returns the refusals, empty when none applies.

GBGCodingTools.Rounds.abandon — Function
abandon(cfg, round, reason; io = stdout) -> Int

gbg round abandon <round> --reason "…": the only wholesale exit. The arguments are:

  • cfg — the validated config.
  • round — the round id.
  • reason — at least 12 characters (a plateau is the usual one).
  • io — where the outcome is printed.

It writes abandoned = {reason, open_ids} with every id still open (every banked id but the seeded ones when no pass was graded), and carries the round's deferred.md into the work queue exactly as close does: abandoning drops the round's record, not what it owes. Returns 0.

It takes an open round, and one other: a CLOSED round stamped dev, which no release may cite and which preflight no longer lets anyone open. That is the exit such a round would otherwise not have — a state a check can name and no verb can leave is a trap, and the repair reached for instead would be editing a frozen record. closed is kept beside abandoned, so the record says it happened; the round reads abandoned from then on.

GBGCodingTools.audit_bank — Function
audit_bank(cfg, round; io = stdout) -> Int

gbg audit-changes bank <round>: the audit's bank runs the executable claims itself, then the generic bank. The arguments are:

  • cfg — the validated config.
  • round — the round id (<date>-<instrument>-<NN>), the instrument being one of the four review procedures GBGCodingTools binds.
  • io — where the report goes.

It runs package.julia_test (the gate claim) and every file named under executable_claims with GBG_ROUND exported, each claim as julia --project=test <file> — which is why test/Project.toml names the package itself as a path source, and without that every claim fails to load it and the audit's account of what runs is built on nothing — records {command, file, exit, log} in audit.json together with base, head, kind and the covered paths, then runs Rounds.bank.

Afterwards it prints the severity re-check Workflow call (an anchor, before "serious" is counted at grade) over the concerns a re-rating can move across the gate — the minor and nit ones not already gated by previously_worked — and, when there are none, writes an empty severity.json itself. Returns the bank's exit code.

A lane whose verdict contradicts its own findings — CLEAN with a concern, CONCERNS with none — is refused before any claim runs: the generic bank is called at once, quarantines that lane as DEAD and records it, and the gbg round rerun it prints re-runs exactly that lane.

Design checks

The two checks on the instruments themselves, run outside any round: an attack on an instrument's lens set, and a calibration of the consistency panel against what a human read found.

GBGCodingTools.attack — Function
attack(cfg, instrument; subject = nothing, io = stdout) -> Int

gbg attack <instrument> [--subject <file>]: puts four adversaries — a logician, a philosopher, a counterexample hunter and a measurement specialist — against an instrument's lens set and asks what harmful defect passes every lane: the check a lens list must survive, run outside any round. The arguments are:

  • cfg — the validated config.
  • instrument — the instrument whose lanes (or, for check-consistency, hats) are attacked.
  • subject — a TOML file naming what the instrument examines, what it must catch, from whose standpoint and where the real material is (schema/attack-subject.schema.json); the tool's own catalog/attack/<instrument>.toml when nothing.
  • io — where the report and the Workflow call go.

It renders the instrument's current roster for this package — each lane's brief or hat's persona, and the files a docs lane reads — into .gbg/attacks/<id>/design.md, fills the subject's {package.…} placeholders and keeps it beside the design as subject.toml, copies attack-design.js into the scratch directory and prints its Workflow call. The script writes attack.json into the same record; attack_read reads it. Returns 0, or 2 for an instrument without a subject or a subject that does not validate.

GBGCodingTools.attack_read — Function
attack_read(cfg, id; io = stdout) -> Int

gbg attack read <id>: validates an attack's result against schema/attack.schema.json and prints every gap the attackers found, fatal first, each with its evading example and the lens proposed to catch it. The arguments are:

  • cfg — the validated config.
  • id — the attack's id, a directory under .gbg/attacks/.
  • io — where the report goes.

GBGCodingTools.calibrate — Function
calibrate(cfg; io = stdout) -> Int

gbg calibrate: scores the check-consistency hats against the defects a human read of the rendered site found — for each defect, which hat's persona should have caught it, and whether that hat, run blind on the passage alone, does. The arguments are:

  • cfg — the validated config.
  • io — where the report and the Workflow call go.

The defects are the owner's record .gbg/human-findings.toml (schema/human-findings.schema.json): one [[finding]] per defect with its id, title, page, the passage verbatim, the defect and the date it was recorded. Every applicable hat's persona and each finding's passage and defect are written as separate payload files, so the blind hat is handed the passage and never the defect; the findings are copied into .gbg/calibrations/<id>/ with the result the script writes there, and calibrate_read reads it. Returns 0, or 2 when the record is absent, invalid or empty, or repeats an id.

GBGCodingTools.Fleet — Module
Fleet

The fleet scorecard: Fleet.rows computes one row per consumer of fleet.toml — OK, NOT-INITIALISED, BEHIND or RED with a detail — and Fleet.diff prints two closed rounds' tallies side by side. The exit contract is D4's: 0 when every row is OK; 1 on NOT-INITIALISED, RED, or BEHIND outside the 7-day sweep window; 2 when a listed path does not exist.

GBGCodingTools.Fleet.rows — Function
Fleet.rows(; deep = false) -> (rows, code)

One row per [[consumer]]: (name, pin, status, detail). A consumer without .gbg/config.toml is NOT-INITIALISED; one whose QUICK doctor fails is RED with the failing ids; one whose pinned version is older than the fleet's newest is BEHIND with both versions and the window state; else OK. The tool's own row (path = ".") shows dev+<sha>[-dirty] with clean at vX.Y.Z or off tag, is OK/RED by its own doctor and never BEHIND. A missing path is exit 2. The arguments are:

  • deep — run every check, the --deep ones included, as each consumer's doctor pass instead of the QUICK set.

Returns the rows and the exit code.

GBGCodingTools.Fleet.diff — Function
Fleet.diff(a, b; io = stdout) -> Int

gbg fleet --diff <consumer>:<round> <consumer>:<round>: two closed rounds' tallies side by side. The arguments are:

  • a, b — the two rounds, each <consumer>:<round> naming a consumer of fleet.toml and a closed round of it; a is the left column.
  • io — where the table is printed.

The table holds the totals, the closure channels, the demotions, the adjudicated share and the recall. Rounds whose tool versions differ in MAJOR.MINOR are refused (exit 2), since their rates are not comparable. Returns the exit code.

GBGCodingTools.release — Function
release(ver; io = stdout, skip_tests = false) -> Int

Tags and pushes v<ver> from the dev checkout. The arguments are:

  • ver — the version to tag, X.Y.Z or X.Y.Z-rc.N.
  • io — where the checks are reported.
  • skip_tests — skips Pkg.test(), the docs build and the deep doctor; for the self-tests of this verb only, never set by the CLI.

Refused (exit 2) unless: the tree is clean and on the configured branch; the tag is absent; CHANGELOG.md carries ## <ver> —; Project.toml's version equals the release version (the base version for a prerelease); Pkg.test() is green; the tool's own docs build exits 0 (SELF.DOCS); gbg doctor --deep is green at the root; and, for a final release only, no round is open under .gbg/rounds/ and the /check-docs round opened at the latest <ver>-rc.<n> tag is closed — every id through honored, adjudicated, rescan or seeded, or carried into the next round (cites_round) — and nothing in the carry ledger holds it back (carry_release_fails). A tag is never moved or re-issued. Returns the exit code.

source
GBGCodingTools.cites_round — Function
cites_round(cfg, tag) -> Bool

Whether the consumer cfg holds the review a release at tag leans on: a CLOSED /check-docs round stamped with that tag, every id of its last tally closed through honored, adjudicated, rescan or seeded — or carried into the next round, which ROUND.toml's closed_by.carried records and which is a disposal, not an open id. tag is the git tag (vX.Y.Z, vX.Y.Z-rc.N); the round's stamp is written without the v (Preflight.stamps), and comparing the two raw made this precondition unsatisfiable — no final release could pass it, and it would have rejected a correctly stamped round.

This is where "the released version was reviewed" is enforced. ROUND.DEV only reports what is already recorded; the refusal that keeps a round citable is Preflight.dev_round, at the door. Returns the answer.

GBGCodingTools.selftest — Function
selftest(; pinned = false, io = stdout) -> Int

Runs the running copy's own Pkg.test() from a temporary environment that develops it by path, so the self-test's arms run over the fixture wherever the tool is installed. With pinned, additionally copies the fixture to ${TMPDIR}/gbg-pinned-fixture/, pins it at the newest released tag (its sub-environment sources rewritten to the https url and rev), instantiates its docs/ environment and runs the QUICK doctor there — the pinned-copy behaviours (PIN.SELF, PIN.TREESHA, PIN.SOURCES) — leaving the copy in place for the install phase. The arguments are:

  • pinned — also runs the pinned-copy arm described above; false stops after the Pkg.test() run.
  • io — where the report and the child processes' output go.

Returns the exit code.
