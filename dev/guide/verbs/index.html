The verbs

Written by AI, not regularly reviewed

This page is written by AI and is not reviewed regularly by a human.

gbg <noun> <verb> is the whole command line; the table is closed, and every verb below is rendered from its own docstring so the page cannot drift from the code. The exit contract is one for all: 0 clean, 1 a substantive finding, 2 cannot evaluate (a precondition not met, missing input, torn file), 3 crash.

Entry point

GBGCodingTools.main — Function
main(args) -> Int

The one entry point of the command line: the shim execs julia -e 'using GBGCodingTools; exit(GBGCodingTools.main(ARGS))', and every test of a verb calls it directly. Dispatches <noun> <verb> (or a lone noun) through VERBS and returns that function's exit code: 0 clean, 1 substantive finding, 2 cannot evaluate, 3 crash. A --dev first argument sets GBG_DEV=1 so the stamps read dev+<sha>, exactly as the shim's --dev route does. An unknown verb prints the table and returns 2. Output is never truncated.

An exception escaping a verb is printed with its backtrace to stderr and returns 3, so a crash is never read as a finding. The exceptions are the consumer's own config failing to read or validate — a ConfigIO.ConfigError — and a UsageError, each the documented exit 2, printed without a backtrace.

GBGCodingTools.parse_options — Function
parse_options(args; valued = String[]) -> Options

Parses args into an Options record. Any --name=value is a value whatever valued says; an option named in valued also consumes the following bare argument as its value; every other bare --name is a flag; a lone -- ends option parsing. The arguments are:

  • args — the command-line arguments to parse, in order.
  • valued — the names, without the dashes, of the options that take a value.

Returns the parsed options; an option that is in valued but has no value — the end of the arguments, or the -- that ends them — is a UsageError, which main turns into exit 2.

source
GBGCodingTools.Options — Type
Options

The parsed command line of one verb: the positional arguments in order and the options by name.

The fields are:

  • positional — every argument that is not an option, in order.
  • flags — the options given without a value (--deep, --dry-run), as a set of names without the dashes.
  • values — the options given with a value (--only LOAD, --reason "…", --profile=core), name to value.

Machine and self

GBGCodingTools.cmd_install — Function
cmd_install(args) -> Int

gbg install [--dev-checkout <path>]: copies the running copy's bin/gbg to ~/.local/bin/gbg with mode 755 and, with the option, writes the one-line pointer ~/.gbg/dev. Runs from whichever copy Pkg resolved for the calling environment — no depot glob is ever expanded. Returns 0 when the shim is written, and the ~/.gbg/dev pointer with it under --dev-checkout, 2 when the Julia in use is below the floor, when --dev-checkout names a directory that is not a GBGCodingTools checkout, or when ~/.local/bin is not on PATH (the shim would be installed but never found).

GBGCodingTools.self_verify — Function
self_verify(root = ConfigIO.find_root(); io = stdout) -> Int

Recomputes the git tree hash of the copy this process runs from (pkgdir(GBGCodingTools), through tree_hash) and compares it with what Pkg.dependencies() reports for the tool in the active environment and with the git-tree-sha1 every sub-environment manifest under root records; asserts the dependency entry is is_tracking_repo && !is_tracking_path (a Pkg.develop'd copy lives inside the depot, so only the flags tell it apart). The arguments are:

  • root — the consumer root whose sub-environment manifests are compared; nothing (no root found) leaves only the active environment's entry to compare against.
  • io — where the one line per comparison is printed.

Returns 0 when every comparison agrees, 0 with a WARN when the running copy is a working tree (pinned at dev) or no manifest exists to compare against, and 2 for a disagreement or a developed copy — an edited pinned tree is never allowed to grade a round.

source
GBGCodingTools.cmd_self_verify — Function
cmd_self_verify(args) -> Int

gbg self verify: the command-line face of self_verify. Returns its code: 0, or 2 for an edited or developed pinned copy.

Consumer setup

GBGCodingTools.Wire.init — Function
init(root; io = stdout) -> Int

Writes .gbg/config.jl for the package at root if it has none, then writes every generated file. The arguments are:

  • root — the package root.
  • io — where the report goes.

It NEVER overwrites an existing config: a package's config is the one file here that is the package's own, holding what it has switched off and why, and a verb that rewrote it would throw that away on a re-run. Where one exists, this is sync and says so.

Exit 0 when the package is wired, 1 when a generated path is already the package's own — nothing is written, the first run included — and 2 when the config it wrote or found cannot be read.

source
GBGCodingTools.Wire.sync — Function
sync(root; check = false, io = stdout) -> Int

Writes every generated file of the package at root, or, with check, reports which of them is not what the running copy would write and changes nothing. The arguments are:

  • root — the package root.
  • check — report instead of writing.
  • io — where the report goes.

Exit 0 when the package is wired (or, under check, already was), 1 when check found drift or a generated path is the package's own file and was refused, 2 when the config cannot be read.

Checks

GBGCodingTools.Check.run — Function
run(root; intention = nothing, network = false, io = stdout) -> Int

Runs the rules and the wiring check over the package at root and prints what they found. The arguments are:

  • root — the package root.
  • intention — Model.Intention.DOCUMENTATION for what a docs build runs, Model.Intention.CODE for what a test suite runs, or nothing for both.
  • network — whether a check that reaches the network may run; false everywhere but this verb.
  • io — where the report goes.

Returns the exit code: 0 clean, 1 findings, 2 the package could not be read or a history rule could not be evaluated here.

Clean means clean OVER WHAT RAN HERE. The rules that read the built site or the loaded package are the build's and the suite's, and this verb builds and loads nothing; it names them rather than counting them into a total, since exit 0 printed as "every rule" was read as every rule (review, 2026-09-26).

The rulebook, measured

GBGCodingTools.StudyCmd.rules — Function
rules(root, path; io = stdout) -> Int

Reports the round of votes in path. The arguments are:

  • root — the package root.
  • path — the votes, tab-separated.
  • io — where the report goes.

Exit 0 when the readers agreed with the rulebook everywhere, 1 when anything is open — a split, a flagged wording, or a tag the readers would move — and 2 when the file is absent or is not votes. The exit code is the contract: a session that must not leave a measurement unread reads it rather than the text.

Fleet and release

GBGCodingTools.Fleet — Module
Fleet

The fleet scorecard: Fleet.rows computes one row per package of Catalogue.FLEET — OK, NOT-INITIALISED, BEHIND, AT-PIN, RED or MISSING with a detail. The exit contract is D4's: 0 when every row is OK or AT-PIN; 1 on NOT-INITIALISED, RED, or BEHIND outside the 7-day sweep window; 2 when a listed path does not exist (MISSING).

source
GBGCodingTools.UsageError — Type
UsageError

A command line a verb cannot run: an option missing its value. The fields are:

  • msg — the sentence printed.

It is the user's mistake, so main prints it without a backtrace and returns 2, not the crash code 3 (found in review, 2026-09-26).

source
GBGCodingTools.Fleet.rows — Function
Fleet.rows() -> (rows, code)

One row per package of Catalogue.FLEET: (name, pin, status, detail). A consumer without .gbg/config.jl is NOT-INITIALISED; one whose generated files are adrift is RED; one whose pinned version is older than the fleet's newest is BEHIND with both versions and the window state; else OK. A missing path is MISSING, exit 2. The tool's own row (path = ".") shows dev+<sha>[-dirty] with clean at vX.Y.Z or off tag, is OK/RED by its own wiring and never BEHIND. Returns the rows and the exit code.

The wiring is judged by THIS copy's generators, which are the dev tree's. That is the right judge of a consumer pinned to the checkout, and the wrong one of a consumer pinned to a release: its files are what its pin writes, and the dev tree words them differently whenever a generator changed since that tag. So a released pin that differs is AT-PIN, not RED — its own build judges it at its pin — and a checkout pin that differs is RED (found in review, 2026-09-26: every consumer behind the dev tree was graded RED WIRING).

GBGCodingTools.Bump.bump — Function
bump(root, version; io = stdout) -> Int

Moves the pin of the package at root to version and rewrites its wiring, or refuses and changes nothing. The arguments are:

  • root — the package root.
  • version — the released version to pin, X.Y.Z.
  • io — where the report goes.

Exit 0 when the pin moved, 1 when the running version's rules found something and it did not, or a generated path is the package's own file, 2 when the config could not be read or the pin line could not be found. The rules that guard the move are the RUNNING copy's, pkgversion(GBGCodingTools), and the report says so: they are the new version's only once the environments resolve it.

A PRERELEASE may be pinned. It was refused here until 2026-09-18, on the reasoning that a candidate is not a release; the refusal bought nothing and the cost was concrete. A tag is immutable whether or not it carries -rc.N, so a candidate resolves from GitHub exactly as a release does.

Refusing it left the first wired package pinned to an absolute path on one machine, its CI resolving nothing and running none of these rules, for as long as the final release was away. What guards a bad pin is the check below, which will not move a pin while the new version finds anything, and that guard does not care what the version is called.

GBGCodingTools.release — Function
release(ver; io = stdout, skip_tests = false, root = pkgdir(GBGCodingTools)) -> Int

Tags and pushes v<ver> from the dev checkout. The arguments are:

  • ver — the version to tag, X.Y.Z or X.Y.Z-rc.N.

  • io — where the checks are reported.

  • skip_tests — skips all four gates after the refusal list: Pkg.test(), the docs build, the wiring check and the question to GitHub; for the self-tests of this verb only, never set by the CLI.

  • root — the checkout to release, the running package directory by default; the CLI never passes it. A keyword because the verb read pkgdir(GBGCodingTools) directly and so had no test at all. Every refusal below reads root, the dev-checkout guard included: root must be a git working tree, since it is what gets tagged and pushed.

Refused (exit 2) unless: the tree is clean and on the configured branch; the tag is absent; CHANGELOG.md carries ## <ver> —; Project.toml's version equals the release version (the base version for a prerelease); Pkg.test() is green; the tool's own docs build exits 0 (SELF.DOCS); gbg sync --check is clean at the root; the newest CI run AT THIS COMMIT is a success (ci_verdict). Nothing else holds a release — no review, no open finding, no unanswered question, no audit. A tag is never moved or re-issued. Returns the exit code; a failed gate, tag or push prints the reason its command gave.

source
GBGCodingTools.release_fails — Function
release_fails(cfg, root, ver, base, rc) -> Vector{String}

Every reason v<ver> may not be tagged from root, in the order they are checked; empty when there is none. The arguments are:

  • cfg — the package's config, read at root.
  • root — the checkout to release.
  • ver — the version to tag.
  • base — its X.Y.Z part.
  • rc — whether it is a candidate.

It reads the tree, the tags, CHANGELOG.md and Project.toml, and writes NOTHING — which is the point of it being separate. A test of release can only reach the refusals: past them the verb runs git tag and git push, and a test must never cut a tag. So the conditions beyond this list were untestable, and that is exactly where a defect lived for nine releases. Lifted out so each can be exercised over a temporary repository (2026-09-12 work queue).

source
GBGCodingTools.ci_verdict — Function
ci_verdict(root, sha) -> Union{String,Nothing}

Why the CI workflow does not say this commit is green, or nothing when it does. The arguments are root, the checkout, and sha, the commit about to be tagged. Returns the reason, in words.

It is asked over the network and is therefore NOT in release_fails, which reads the tree alone and is what the refusal tests exercise.

A tag is permanent and a local gate is not the same question: v2.0.0-rc.2 and v2.0.0-rc.3 both went out on 2026-09-18 with every local command green, one failing on a git identity this machine has and a runner does not, the other on a workflow step greping a banner that had been renamed. Neither could fail here. CI runs on a tag or a dispatch (RULE.GIT.CI_MANUAL), so the run to ask about is a DISPATCH on this commit — gh workflow run CI --ref master — before the tag, not after it.

Where gh is missing or GitHub cannot be reached this REFUSES rather than passing: a release cut blind is what the two red tags were. GBG_RELEASE_IGNORE_CI=1 is the deliberate way past it.
