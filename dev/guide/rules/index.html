The rules

Written by AI, not regularly reviewed

This page is written by AI and is not reviewed regularly by a human.

Generated at build time from this package's rendered policy copy under .gbg/policy/: the shared rulebook every consumer imports, with this package's parameters substituted. A rule's id is stable; the scans and the doctor cite it.

The docstring rubric (RULE.DOC.*, RULE.API.*)

The organizing spec for every user-facing docstring and API page. Two audiences, one rule each: a module docstring is a map; a function docstring is a home.

RULE.DOC.TWO_TIER

A module docstring is a map and a function docstring is a home. The map states what the module is, its scope and place in the architecture, and its invariants — then a linked one-liner per operation family, and no formulas; every formula lives in the operation's own docstring.

RULE.DOC.HOME_ORDER

A function docstring is ordered: identity, when-to-use, arguments, one formula, citation, links, caveats. In full: (1) a plain one-sentence identity in the user's terms; (2) when to use it, versus the alternatives; (3) each argument (positional and keyword) and its effect; (4) one formula if a clean one exists, never overflowing; (5) an inline citation for a named or published method and none for a classical one; (6) cross-links; (7) the caveats a user needs, as an admonition where load-bearing — the last block of the home's PROSE. Then the sections that are not prose, in this order and no other: the # References section of RULE.CIT.FULL_INLINE, then # Fields, which is last (RULE.DOC.SHAPE, and the shape scan reads any heading after # Fields as a hit). Three rules each used to claim the end of a docstring; the order lives here, and they defer to it. Excluded: implementation internals (a # comment), unexplained specialist jargon, architectural rationale and the formal apparatus (the rationale documents).

RULE.DOC.LEADING_IDENTITY

Item (1) of the home is a plain one-sentence identity that leads with what the operation means, not how it is computed. For this package the identity leads with the physical meaning — what the operation does to its object, before how it is computed: an operation computed in a derived representation still states what it does to the real object first — with the explicit relation — and gives the derived form it uses after; an estimator states the population quantity it estimates, in standard probability notation, before the estimator. Where no clean form exists, say so briefly rather than forcing one.

RULE.DOC.ONE_HOME

One concept has one home: one docstring per operation, on the bare binding, and a generic carries one docstring, never one per method. Per-scheme or per-representation specifics live in the scheme's or the representation's own docstring, linked. Across an f/f! pair the in-place ! form is the home — it owns the formula and the kernel and is listed first — and the allocating form and any operator alias is a thin wrapper that leads with the one-sentence meaning and @ref-links the home, carrying no second copy of the formula.

RULE.DOC.VARIANT_PAIR

The review unit is the operation's whole variant set, so the defining math appears once across an f/f! or getter/setter pair and the wrapper carries no display formula. Typed twice, the math drifts — one member writing a partial one way and its twin another — and a within-string check cannot see it; a lane that groups each operation's generics and diffs them can.

RULE.DOC.ARGS_FORM

A docstring documenting three or more arguments, or any keyword argument, uses the bulleted form led by The arguments are:; with fewer, the arguments are bound in running prose, and the two forms are never mixed in one docstring. The threshold counts what one signature takes, not the distinct names across type-specialised overloads. Exempt: a thin allocating wrapper, which documents no arguments at all; an internal _-prefixed helper, which documents its arguments in whatever form reads best; and a single element-type keyword bound in one prose clause.

RULE.DOC.FIELDS

A type that stores named, user-readable fields documents them under The fields are, one bullet per field, every bullet a real field and every field a bullet; prose is reserved for the one-sentence identity above the list. A type docstring is constructor-first: identity, the constructor and its arguments, an example where construction is non-obvious, then the demoted fields list.

RULE.DOC.ADMONITION_TITLE

An admonition title is plain text stating the caveat, so a reader skimming the page learns the hazard without opening the block. For this package the rule is always: every !!! block carries a custom descriptive title: either every !!! block carries a custom descriptive title, or a block carrying one load-bearing claim does while a general aside may stay a bare !!! note. A caveat admonition is the last substantive block of a docstring, before the fields list.

RULE.DOC.STEER

Every ! form that has an allocating sibling carries the in-place steer sentence verbatim, after the identity paragraph and before the arguments, naming its own destination argument. The sentence is the template below — a template, not a link: destination is replaced by the argument the signature actually has and f by the allocating sibling's own name, so the @ref resolves in the docstring that carries it, never here.

Use this in-place form when `destination` is already allocated; the allocating [`f`](@ref) returns a
fresh result instead

A ! form with no allocating sibling and a setter take no such sentence.

RULE.DOC.ALIASING_BULLET

An operation-specific statement of whether the destination may alias an input lives in the destination argument's bullet, not as standalone prose. The package-wide guarantee lives in the module docstring and is not repeated per operation; an operation states it for itself only when it has an operation-specific reason, or when its contract is the contrary one.

RULE.DOC.INTERNAL_API

An ## Internal API section splits into ### Types and ### Functions only when it holds both kinds, comes last on its page, and opens with the same disclaimer sentence. A section documenting only functions uses a single unlabelled block and no ### at all.

RULE.DOC.REF_ABUT

A @ref never abuts a second code span, because two adjacent monospace chips render with a visible seam. Write the whole call as the link text with an explicit target: a Markdown link whose text is the backticked call and whose destination is @ref followed by the bare name.

RULE.DOC.API_GROUPING

API pages are math-grouped under hand-written headers via explicit @docs blocks, each object once, an f/f! pair together with the ! home first, no @index, and no empty block. A group is ordered by increasing complexity of its objects; a page leads with its headline operations, then the supporting types and schemes they take. checkdocs = :exports guards a dropped export, and every derived public operation has a home on a public page.

RULE.DOC.COVERAGE_BASES

A reduction documents every base it supports, not just one. A measure reduction over a grid and the same reduction over a point set are both stated where the operation is documented.

RULE.DOC.GRAMMAR

Every sentence has a subject and a verb; no verbless fragments, noun stacks, label: colon tags or comma splices. Concise means few words, not missing verbs — compact prose that still reads as sentences aloud.

RULE.DOC.SENTENCE_OPENER

A sentence opens with a capitalized ordinary word, never a lowercase code identifier or a math formula. A lowercase start is reworded so an ordinary word leads; the identifier is never capitalized, its binding being lowercase by nature. Exempt: a bullet or list item, a # code comment (but not a Literate example's full-line prose comment, which renders), a heading, fenced code, and a capitalized type, module or file opener.

RULE.DOC.VERIFIED

Correctness is verified, not asserted: every formula, normalization, adjoint relation and cross-scheme equivalence is checked by expanding it against the code. A plausible "X is just Y" is a false claim until the expansion matches. Run this as a positive verification — enumerate every formula, constant, relation and quantifier and verify each — not as a read-through; a false-but-plausible statement is as invisible as an unbound symbol. Category and type errors are their own class: an object conflated with its representation, an operator with its parameter, a rate with its time-integral, a scalar with the field it reduces; type every object from the code.

RULE.DOC.SELF_CONTAINED

A rationale document reads top to bottom without another file: every piece of notation, a math symbol or a code identifier, is introduced in plain language at its first use. Later uses may be bare; universally standard mathematics may stand unglossed. A decision-log entry browsed on its own meets the same bar.

RULE.DOC.TERMS_DEFINED

A term of art naming a package concept is defined in a clause or @ref-linked on its first use, and the acceptance test is the cold read. A docstring can bind every symbol and still be unreadable to someone who has not read the module, because its terms of art are nouns, not symbols; parse it with the module's context withheld, and a noun that silently assumes the package's context is the defect.

RULE.DOC.CURRENT

Every claim matches the code's present state, and a summary that names only a subset of what the code now provides is stale even if every sentence is literally true. No stale future, deferred or none-exist claims; each module and operation summary still names everything added since it was written, against the current exports and method set. Retired phrasings a package bans are listed in its config and scanned.

RULE.DOC.CLASS_SWEEP

A flagged instance is a sample of a class: characterize the class, sweep every surface for it, and fix all occurrences in one pass, reporting the class and the count. Fixing only the pointed-at line and waiting to be handed the next instance is the failure this rule exists to stop. After a class fix, enumerate the surfaces from the finding's own text, not from memory, and re-measure.

RULE.DOC.BATTERY

"Check the docs" means the complete battery over every surface, never one check or one file. When asked to check, review or audit the documentation in any words, run the full matrix — every check across every surface — and report it; do not run one check, sweep one file, and stop.

RULE.DOC.LITERATE

A Literate example is a rendered documentation page: every full-line # comment becomes prose, its math is LaTeX, and a comment that must stay in the code uses ##. A full-line comment inside a control-flow block splits the code fence, so reserve full-line # for narrative prose at statement boundaries. An underscored identifier in that prose is backticked, or Markdown parses it as an italic span.

RULE.DOC.BUILD_VERIFY

A documentation edit is verified by the full docs build exiting 0, never by a diff, a lint subset, or a grep of a log. A lint run standalone cannot see a dangling reference, and grepping a log for error text passes a build that died at load. After editing a Literate example, regenerate it and read the output.

RULE.DOC.TABLE_TOP_LEVEL

A Markdown table is top-level, never indented inside a list item, and no cell holds a literal |. The renderer will not form a table inside an indented item and falls back to literal pipes; inside a list use a nested bullet list, and write a norm bar as LaTeX, never as a bare pipe.

RULE.DOC.ONE_NOTATION

One notation per concept and one concept per notation; a local use yields to a package-wide glyph. Before introducing a symbol, check it is not a synonym for one already in use, and check the section for the glyph and confirm it is free. When an edit introduces a symbol, retire the old one.

RULE.DOC.COORD_FREE

Maps and pairings are stated intrinsically, and coordinate or matrix machinery that buries the structure is confined to the formalization document. Component notation for a genuine fiber algebra is fine; the rule targets flattening a structured space to a bare vector. Where a basis form is needed to mirror the code, state the basis and the space it acts on.

RULE.DOC.LINKS

Cross-referencing is discriminating-minimalist: backtick every code identifier and promote to @ref only where a reader would genuinely jump and there is one clear destination. Link a target at most once per docstring; never link the docstring's own binding, its arguments, option tokens, struct fields or Base names; a family of built-ins is one catalogue destination unless the members are distinct types a reader must choose between; sibling names in one list are all linked or all plain, never a mix. The at-home test: if a sentence would sit equally well in the target's own docstring, cut it and link, the function's own defining formula and validity clauses always staying.

RULE.DOC.SIBLING_LINK

The first mention of a sibling GBG package in a page, a rationale document, a Literate example or a docstring is a link to that package's documentation site, written [Package](https://<owner>.github.io/Package.jl/). A later mention in the same unit does not link that site again — it is a bare code span, or a deep link to a named page of the site, which is a cross-reference rather than the repetition this rule is about. A package never links its own name. The names and sites come from the fleet registry the tool ships (fleet.toml), so the target is one string in every package.

RULE.DOC.NO_DEAD_REFS

A rendered docstring or a thrown error message cites no section number, repo path or inaccessible source, and reads complete at the REPL where links are dead. A cross-reference adds depth one hop away; it never carries a fact the reader needs. Section citations and design rationale stay in # comments and the rationale documents.

RULE.DOC.AI_BANNER

Every AI-written rationale page and Literate example carries the one provenance banner verbatim, and the banner is identical wherever it appears. The banner is the two lines !!! info "Written by AI, not regularly reviewed" and This page is written by AI and is not reviewed regularly by a human.; a Literate file carries them as # comment lines, and a drifted copy is a finding. The site's home page (docs/src/index.md) never carries the banner in any package: the owner reviews that one page in every package, and a banner there would be false. A package that wants the banner on more of its pages says so in its own CLAUDE.md.

RULE.DOC.SHAPE

A docstring's longest paragraph stays within 120 words and it carries at most three admonitions, no unit grows past its recorded baseline, an # Arguments heading — where a consumer uses one in place of the bulleted form of RULE.DOC.ARGS_FORM — precedes any column-0 admonition, and # Fields is last. The caps bind on every docstring and every page unit that is new; a page unit already in the baseline is held by the ratchet alone, which is the one place the baseline is the whole of the check. A paragraph is a run of lines between blank ones, so a Markdown table is ONE paragraph however long: that is why the caps bind on docstrings, where a table is rare, and why an inherited page section is held by the ratchet. A docstring that has taken three or more rounds of patches is rewritten whole rather than appended to again; the shape baseline is re-recorded deliberately, never by accident.

RULE.DOC.MODULE_MAP

A module docstring lists one linked one-liner per operation family and carries no formula. Its order is identity, then the contents list, then an optional trailing remark.

RULE.DOC.ARG_BULLET

An argument or field bullet names its argument in a plain code span, never a bold one. The form is a list item holding the backticked name, an em dash and what it is, one bullet per argument.

RULE.DOC.SIGNATURE_MIRROR

A docstring signature names the method's arguments in the method's order, and only the docstring wraps, to at most 88 columns with a hanging indent under the first argument; the source definition is left exactly as written. How much of the method the signature repeats is this package's to set, and it is the names and their defaults, and no types: a type belongs to the argument's own bullet under The arguments are:, where there is room to say what it constrains, and repeating it in the signature line costs a second place to keep in step. Whichever form a package takes, the two never drift: the signature is checked against the method it documents, not against a reader's memory of it.

RULE.DOC.SIGNATURE_FIDELITY

The displayed signature set and the defined method table agree per exported binding, and the symmetric difference is reported. A displayed keyword no method has is a stale signature; a defined keyword no signature shows is unadvertised. A triage scan: an inner constructor deliberately omitted, an extended external generic and a kwargs... passthrough produce legitimate asymmetries.

RULE.DOC.XLINK

A cross-module name is @ref-linked at its first mention in a docstring, qualified so the link resolves. An unqualified cross-module @ref does not resolve, and the author who downgrades it to a bare span creates a link that is silently missing rather than broken.

RULE.DOC.ARGCOV

Every argument in a docstring signature, positional and keyword, is documented in its body, and the sweep runs from the signature. An argument that surfaces only inside a formula reads as bound by use and slips past a symbol sweep; the accepted forms are a plain span and a span carrying the default. For this package the check is a gate tier.

RULE.DOC.REGISTER

A tunable is an option, a setting or a keyword argument — never a "knob" or a "tweak". The reference register is neutral across every authored surface: docstrings, rationale documents, doc pages, # comments and testset names.

RULE.DOC.RETURNS

A type docstring leads with its constructor, and a -> Type arrow or a Returns x. sentence states the result where the identity sentence does not. A mutator whose signature carries no arrow says what it returns in a sentence before any caveat; a signature carries an arrow only where the return type is fixed by the signature; arrow and sentence never both appear.

RULE.API.POSITIONAL

A result-affecting argument is positional, a performance hint or a builder's cost and accuracy tunable is a keyword, and every exception is recorded. In an operation, every argument that affects the result is positional, defaults included; an argument that cannot change the result is a keyword. An exception is a ledger deviation with its reason.

The doc-edit checklist

Run all of these on every documentation change, most strictly on a rationale document, each as a positive procedure: enumerate, then verify each item. (1) Correct — RULE.DOC.VERIFIED. (2) Self-contained — RULE.DOC.SELF_CONTAINED, RULE.DOC.TERMS_DEFINED, RULE.DOC.ARGCOV. (3) Notation — RULE.DOC.ONE_NOTATION and latex-idiom.md. (4) Formatted, bidirectional — math is LaTeX never backticks, every code identifier backticked never bare, and the silent-rendering rules. (5) Current and complete — RULE.DOC.CURRENT. (6) Cited — citations.md. (7) Across variant pairs — RULE.DOC.VARIANT_PAIR. Order the work code before docs: the docs describe the code, so the reverse order writes every affected docstring twice.

The LaTeX idiom (RULE.TEX.*)

Every rule here is standard LaTeX idiom plus a few documented exceptions, not a matter of taste; when unsure, reach for a standard LaTeX reference and KaTeX's published support table, never a plausible-sounding typographic argument. Documenter renders KaTeX client-side, so a formula's TeX is the page's text.

RULE.TEX.RENDERED_MATH

All mathematics in docstrings and doc pages is rendered LaTeX, never a Unicode-glyph approximation, and every code object is bound to its math symbol on first mention. Inline math is a double-backtick span, display math a fenced block whose language is math; inside a """ docstring every LaTeX backslash is doubled. Plain # comments stay Unicode, being unrendered. Write the binding explicitly — laplacian $\equiv \Delta$ — so the reader always knows which symbol is which function, and write it as one span inside a rendered docstring.

RULE.TEX.CODE_IN_MATH

A code identifier never sits inside a math span, because the renderer sets it as the product of italic single letters. Backtick it in prose; a code name that must appear inside a formula is \texttt{…}.

RULE.TEX.ONE_SPAN

A formula is one LaTeX span, never split across a math span and an adjacent code span. Keep it one span, a trailing code name in \texttt{}.

RULE.TEX.INLINE_ONE_LINE

An inline math span stays on one source line, because a wrapped continuation that begins with a list or blockquote leader is parsed as a new list item and silently drops the span out of math mode. Break the prose around the span, never the span; the docs build fails on the defect.

RULE.TEX.NO_HSCROLL

Nothing scrolls horizontally: a long docstring signature is hand-wrapped with a hanging indent under the first argument, and a wide display formula is broken with aligned, gathered or split. Neither a rendered code block nor display math auto-wraps; inline math reflows and is exempt. Never pack several equations on one line behind \quad.

RULE.TEX.CODE_SPAN_JULIA

A backtick span holds only well-formed Julia — a name, type, call or expression — never math that merely looks code-ish. A half-open interval, an inequality, a product, a lone ≤ or · glyph is LaTeX; the real operators ×, ⋅ and ≈ backticked are code and stay.

RULE.TEX.SPACING

Never space manually around a relation or binary operator, never put \! before a \bigl, never \!\! before a sum, and never write \, except before an upright differential. Spacing next to =, <, \in, + or - doubles the space TeX already puts there; \! before a delimiter that follows an operator or name jams the delimiter into it, there being no gap to remove; between multiplied factors juxtaposition is standard, and when a gratuitous thin space is removed it becomes a plain space, never nothing. Correct and not to be "fixed": \sim\!, \,\mathrm{d}x, \quad/\qquad between display equations, and \mathrm{Re} versus \operatorname{Re} before a delimiter.

RULE.TEX.MATHBB

\mathbb is written only on a capital A–Z or k, and the indicator or identity is \mathbf{1}. KaTeX's blackboard font covers only those glyphs, so \mathbb on a digit falls back to a plain glyph with the font silently dropped.

RULE.TEX.MATHBF

\mathbf is admitted only for an agreed list of strings, and vectors and tensors follow the package's one vector notation. For this package the admitted strings are none and the vector notation is not used (the package has no vector quantities): component notation with index letters, or bold italic \boldsymbol{u} with a braced argument, or no vector notation at all. Never the other, and never an upright \mathbf outside the admitted list. \mathbf{1}, the indicator and identity of RULE.TEX.MATHBB, is admitted in every package whatever that list holds; it is not a package's to withhold.

RULE.TEX.LEFTRIGHT

\left and \right are banned; every delimiter is sized by hand with \bigl/\Bigl … \bigr/\Bigr. Manual delimiters are Open and Close atoms with no added gap, where \left … \right is an Inner atom that adds a spurious gap around the fence. Sole exception: a system or cases written \left\{ … \right.; the arrow commands are not delimiters and are unaffected.

RULE.TEX.PARTIAL

A partial derivative is \partial_{x_i}, subscripting the coordinate, and a bare-index \partial_i is banned. A second-order derivative is \partial^2_{x_i x_i}, a repeated index summed.

RULE.TEX.IMAGINARY

The imaginary unit is upright \mathrm{i}, and i, j, k are indices. Never a bare italic i, never \imath or \mathbb{i}; the differential is likewise upright, \,\mathrm{d}x.

RULE.TEX.FRAC_BRACED

Every fraction argument is braced: \tfrac{1}{2}, never \tfrac12 and never \tfrac N2. Both render alike; the braces are the house style and the scan is exact.

RULE.TEX.BOLDSYMBOL_BRACED

Every \boldsymbol argument is braced: \boldsymbol{u}, never \boldsymbol u. The unbraced form takes one token and silently stops at a subscript.

RULE.TEX.SWALLOWED_ESCAPE

Inside a Julia docstring every LaTeX backslash is doubled, because a single backslash before a, b, e, f, n, r, t, v, an octal digit, x, u or U is swallowed by the string parser. The rendered formula then lacks the command with no error anywhere.

RULE.TEX.RENDERED_MARKUP

No emphasis marker survives into rendered prose. An emphasis nesting CommonMark cannot resolve, such as *a **b***, renders as literal asterisks; the built page, not the source, is where it shows, and the docs build scans the built HTML for it.

RULE.TEX.GREEK_AB

Accumulation scalars are written Unicode α and β everywhere — arguments, locals, kernel bodies and docstrings — and the named ASCII holdouts stay. A hand-written operation spelling them alpha/beta is drift; a flag naming the α/β variant and an external window-shape beta in an English-register block are the recorded exceptions.

Citations (RULE.CIT.*)

RULE.CIT.STYLE

A citation is context-standard author–year: author-prominent with a parenthesized year, a bare year inside an existing parenthetical, at most three authors named, and First et al. for four or more. Keep enough surnames to disambiguate two works that would otherwise collide. An eponymous method name takes no year unless the work is actually cited.

RULE.CIT.FULL_INLINE

A docstring cites author–year in its prose and carries the full reference in a # References section after the home's prose, before any # Fields: one bullet per work, Authors, [*Title*](https://doi.org/…), Journal Volume (Year), verbatim-identical to the canonical entry under the package's references heading, title and DOI compared. Never the full reference in the running prose, which the sentence has to carry and the reader has to step over. Doc pages cite short and the canonical full reference lives in the rationale document; a REPL reader sees the whole reference without opening another file, and drift between the copies is the chosen duplication's only risk, so it is the thing checked.

RULE.CIT.DOI

Every reference carries a clickable DOI on its title, [*Title*](https://doi.org/…), or an Open Library link for a book with no DOI, identical in every copy. A DOI stays REPL-safe; a link target percent-encodes () and <>, and the scan compares DOIs decoded.

RULE.CIT.BLOCK_LIST

Two or more citations form a bullet list under a References: label, one citation per line, and a lone citation stays inline as Reference: …. A semicolon-joined paragraph is unreadable when rendered.

RULE.CIT.NO_INACCESSIBLE

Never cite an inaccessible source on any user-facing surface: not a gitignored monograph, an accompanying thesis, an appendix or figure the reader cannot open, nor working notes. A citation the reader cannot follow is dead weight and implies they are missing something they cannot get; present every result on its own public terms.

The testing protocol (RULE.TEST.*)

RULE.TEST.GATE_VS_SURVEY

Pkg.test() is a gate and the exhaustive suite is a survey; a specific oracle and every completeness guard go in the gate. A gate re-checks claims already known and must be green or the change does not ship; a survey searches for combinations nobody enumerated and is read, not passed. A universal oracle over a product goes in the survey, and anything that may legitimately be non-green goes there too, because a suppressed failure reads as a pass.

RULE.TEST.ORACLE_INDEPENDENT

Every public value-returning operation is classified in the oracle registry, and relational-only coverage is a finding. The classes are analytic (a closed form derived independently of the package), independent (a direct computation written in the test), property (an invariant that pins the operation without computing it), relational (compared only against other package operations — legitimate as a second layer, never as the only one) and structural (returns metadata or storage). A new operation fails the registry until someone classifies it, which is the moment to notice it has no independent oracle.

RULE.TEST.DEFINITION_OF_DONE

A feature is done when its correctness tests, its performance test, the guiding documents, the remaining documents, the benchmarks built and run, and the examples run are each verified, not assumed. "Should work" is not done: a step is done when its verification command exits 0 and the exit code was observed. Grep the docs for stale deferred, none-exist and future claims about whatever was just implemented.

RULE.TEST.ALLOC_ZERO

Every in-place ! operator is allocation-free and appears in the allocation audit, a deliberate materializer gets a bounded guard, and where a bound covers another component's nondeterminism a configuration pins the true zero. The audit runs on the CPU, where a materialized temporary is visible; the completeness of its rows is derived from the export list, never remembered.

RULE.TEST.PASS_AUDIT

Every audited operation has a frozen per-array traffic row, the fused ideal documented beside it, and a named holder for any gap. A raised count is a fusion regression unless a new holder justifies it; the frozen values are refrozen in the same commit as the change, with the reason.

RULE.TEST.METHOD_PARITY

The public method set is frozen per generic and per module, and any change moves a number that is then refrozen deliberately, with the reason. The per-module count is derived from ownership over the whole function surface, internals included, so a method defined under a qualified name cannot hide.

RULE.TEST.MUTATION

A symmetric fixture cannot see an asymmetric defect, a self-referential assertion cannot see a shared defect, and a stated convention must be falsifiable by its fixture. Inject the defect and require the suite to catch it; a fixture that cannot reach the broken branch proves nothing about it.

RULE.TEST.BOTH_DIRECTIONS

Test the check in both directions: a check that cannot fail is not a check, and a self-reported field is acceptable only when the missing case is the failing case. The flattering direction is the one nobody guards: a check that demotes sound answers is stopped being read, and a check nobody reads passes everything.

RULE.TEST.MISSING_IS_FAILING

The missing case is the failing case: a denominator is derived, an absence arm exits non-zero, and a zero count is a dead lane rather than a clean one. An empty witness directory, an empty ledger, an unparsable status — each fails; "nothing to check" is not "all clear".

RULE.TEST.RULE_WITH_CHECK

A rule and its check land in the same commit, and a stated rule without a check is a known weakness. A rule is written by whoever has just fixed an instance, at the moment they are most confident the class is handled — which is precisely when nobody builds the check; afterwards the rule's presence reads as compliance. When a rule is written down, name what would catch its next violation in its RULES.toml check field: a scan:, doctor: or test: id, a harness: binding the tool enforces it by, panel for a rule a reading panel decides inside an instrument that runs, or weakness — a check is possible and none is built. Only panel is an answer without a program behind it, and only because the panel is itself a procedure with a roster, a record and a verdict; "someone remembering this rule" is not one, and a rule resting on nothing but that is weakness however old the habit. A rule no program could ever decide is panel; weakness is reserved for the check that could exist and does not. A sweep reporting zero is the one to distrust: falsify it against a fixture carrying a known positive before believing it.

RULE.TEST.EXAMPLES_RUN

Shipped examples are executed after any change to the public surface, because nothing else runs them. An example is both a rendered page and a downloadable script; the docs build renders it without running it, and a call that no longer dispatches is found only by running it.

RULE.TEST.COUNTS_REMEASURED

A count nothing asserts is re-measured, never cited, and a drop against the last recorded figure is a finding. A test count, a testset count, a coverage figure — each is measured at the time it is stated.

The instruments (RULE.INST.*)

RULE.INST.CONSENT

Unasked, run only Pkg.test(); every instrument, survey, benchmark and panel runs only on the user's request, in words or by slash. The correct output when one would be informative is to name it and its cost and wait. This is a consent boundary, not licence to leave work unfinished: finish the code, run the gate, and report what remains unverified and why. "Check the docs" is such a request: it means run /check-docs.

RULE.INST.FOUR_OBJECTS

The four instruments audit four different objects: /audit-changes the changes to code, /check-docs the source prose, /check-consistency the rendered prose, /bug-hunt the code. A flawless docstring on a function returning the wrong number passes both prose instruments; an edit that is a correct fix and still wider than the defect passes the hunt; each exists for what the others cannot see.

RULE.INST.WITNESS

A static claim about code is a hypothesis; the only admissible evidence is a program that fails; a fixed witness is promoted unchanged. A passing witness means not a bug, discarded however good the argument; no witness writable means a latent hazard, reported and not fixed; a failing witness is the finding and, once the fix lands, the regression test — necessary and not sufficient, since a witness can fail because the witness is wrong, so adjudication derives the expected value independently of the assertion.

RULE.INST.SELF_REPORT

Self-reported closure is not closure: the act verifier sees the diff, the state verifier is blind, and the demotion is mechanical. Both default to the unfavourable verdict so a truncated lane fails safe; a zero count is a dead lane rather than a clean hat; the denominator never comes from the party being measured; and a dismissal is a verdict the verifier grades like any other.

RULE.INST.CLOSURE_LOOP

The closure loop runs over the banked findings by id, never by re-running the battery, and abandon is the only wholesale exit and names every open id. Closing a banked round terminates because the denominator is fixed; re-running the lanes over a just-edited corpus is a new search with no fixed point. Stop on a plateau — three passes flat within noise, with no dead lane — never on a good round.

RULE.INST.CARRY

A round may close by CARRYING a finding into the next round of its instrument: a minor or a nit whenever the owner chooses, and every finding still open once the round has spent its pass budget, a blocker or a major among them. The budget is max_passes verification passes, 3 by default: every pass re-runs both verifiers, and past the third 2026-09-10-check-docs-03 spent six more re-verifying fixes already made. Past the budget severity decides releasability, not closability: a final release refuses while a carried blocker or major stands. The severity that counts is a re-rating by someone other than the lane that reported it, because a rating that can defer a finding is a rating its author has a reason to lower. A carried finding is re-banked into the next round after its lanes have run — never shown to the searching panel, and never left to be rediscovered, since a fresh battery is a fresh search and a finding trusted to luck is a finding dropped. Across rounds the constraint is that the pile drains, which a final release checks, and no finding rides more than three rounds before the owner rules on it instead.

RULE.INST.AUDIT_AFTER_CODE

A fix pass that changed code is audited before its round closes. /bug-hunt always qualifies, and so does a /check-docs round whose pass touched the src or ext surfaces: closing refuses until a /audit-changes round based at the closing round's opening head is itself closed and has read the round's last code change, so it runs after the final fix pass. The two verifiers grade each finding as asked; neither reads the diff whole, runs anything, or asks whether input that worked before still does. A prose-only pass is not gated: run the audit's prose lenses on judgment when the pass rewrote docstrings that state a contract.

RULE.INST.AUDIT_DISPOSED

An audit round is closed by disposing its concerns, never by correcting them inside it. A correction moves the tree, the staleness check then refuses the close, and there is no re-bank; the round would be permanently unclosable. Each gated concern takes a disposition record instead, and a correction the audit asks for rides the next change set, which the next audit covers. This is why bank on an audit round names the disposition and not a fix pass.

RULE.INST.FIX_FROM_LANES

A fix pass is driven from the per-lane findings by id, never from the consolidated summary. Consolidation is lossy by design, which is what makes it readable; a severity in the summary never overrides the lane's own, and closure is reported per lane and per id.

RULE.INST.SEEDS

A seeded finding is never fixed in the corpus and never enters the ledger. Seeds are planted in a disposable copy to measure recall; the ground truth reaches no hat; a class at zero seeded recall is unmeasured, not clean; and recording a seed as adjudicated would hand the next round its answer key.

RULE.INST.NO_TRUNCATION

A scan's output is never truncated by head, tail or a limit: count first, then read all. Adding a limit to keep the output readable is how a class gets half-swept and reported closed; a deterministic check that depends on who types it is not deterministic.

RULE.INST.FROZEN_MIDROUND

An instrument is never changed mid-round; a change is its own commit and release, and reaches a consumer by a bump. A change the round wanted and could not make is written one line per deferral in the round's deferred.md, and gbg round close carries each into .claude/WORK_QUEUE.md, where the Stop hook holds the next session to it. A deferral recorded anywhere else is a note, and a note is not a mechanism. A round records the instrument version that measured it and cannot close under a different one unless re-graded; a rate sequence means something only at a fixed instrument. One relaxation is recorded rather than hidden: a round whose own frozen verifier or auditor scripts cannot run — its verifiers unparseable, so it could never verify — has those differing copies replaced by gbg round scripts --reason, which writes the reason, the pass count and each script's sha into ROUND.toml. A lens script is never replaced mid-round: a changed lens is a new round.

RULE.INST.ECONOMY

Economy lanes are the default, the five phases — adjudication, reproduction, verification, consolidation, the fix pass — are never economised, and full strength runs on explicit request. A cheap lane's false positive is caught downstream; a false negative in a lane with no downstream verifier is why some lanes are anchors and stay at full strength in every mode.

Honest limits

Stated, not claimed closed: grader/graded separation holds for code and prompts, not for files a session can forge — the residue is transcript-visible, not gate-visible. A consistency round's seeded copy lives inside the project, gitignored, and a docs round's in a temporary directory outside it that bank deletes; a hat that opens it, or diffs its manuscript against the built site, leaves a read in its transcript and nothing in the tally except, sometimes, a suspect flag on the hats that did not. A GBG_ROUND exported by hand outside a CLI invocation makes the gate ignore that round exactly as a CLI-run build would; the export is in the transcript, and CI never sets it. A working tree's gate can see an open round that was not committed; CI proves only the pushed state.

Git conventions (RULE.GIT.*)

RULE.GIT.PUSH

Commit ⇒ push, directly on the configured branch; no feature branches. The repository is private and synced across machines through GitHub, so work is committed on the default branch and pushed in the same step; GitHub is the cross-machine sync path and the docs site deploys on push. Stage with git add -u plus every new file by name, never -A.

RULE.GIT.TRAILER

Every commit message ends with the versionless trailer Co-Authored-By: Anthropic Claude <noreply@anthropic.com>, and never carries [skip ci]. The trailer names no model version on purpose: the model in use changes often and the versions supersede each other, so a version in the trailer is a fact about the day rather than about the work, and it goes stale in the one place git never lets anyone correct it.

RULE.GIT.CI_MANUAL

CI is manual-only; the matrix runs locally before a commit, and the docs deploy on every push. Before committing a code change, run the gate locally; a documentation-only change needs a load and the docs build. The docs build is therefore the per-push enforcement point, and the doctor, the hard scans and the gate stay inside it.

RULE.GIT.NO_SHIMS

The API is not frozen; no backward-compatibility shims are built. Errors found later are fixed one by one; architectural soundness is judged on the full picture first.

RULE.GIT.BRANCH

The working branch is the one the package's config names, master by default. A rename is a decision about the package, never bundled with a tooling adoption.

RULE.GIT.MANIFEST_TRACKED

Sub-environment manifests are gitignored, and a tracked root manifest is a declared deviation. A stale sub-environment manifest is resolved locally when precompilation breaks; CI resolves its own.

RULE.GIT.REQUESTS

A cross-package request is a tracked file .gbg/requests/to-<PKG>-<date>-<topic>.md in the requester with a status paragraph on top, and a concluded request is deleted, not kept. The requests directory holds what is still awaiting the other package and nothing else.

Glossary — the terms the rules use

  • Consumer — a package that pins the tool: the four GBG packages, the tool repository itself, and the toy fixture its tests run over.
  • Instrument — one of the four review procedures: /check-docs, /check-consistency, /bug-hunt, /audit-changes. The word keeps its house meaning of a measuring device.
  • Round — one run of an instrument, recorded as a tracked directory under .gbg/rounds/.
  • Lane / hat — one agent of an instrument: a hat is a persona in the panel, a lane a surface or territory in the other three.
  • Anchor — a hat or lane that runs at full strength instead of the economy model.
  • Gate — a program whose non-zero exit blocks a build, a test run or a round's closure.
  • Pinned version — the exact tool version a consumer names in .gbg/config.toml; the doctor's PIN.* checks compare it with what the sub-environments and the running copy resolve.
  • Managed file — a file the tool renders into a consumer and hash-checks thereafter; edited only by gbg sync.
  • Ledger — the consumer's one file of declared exceptions, .gbg/exemptions.toml. The bug-hunt's per-finding fixed | refused | escalated record is the disposition record, never "the ledger".
  • Witness — a self-contained test asserting the correct behaviour of the package, observed to fail on a defective tree; the only admissible evidence of a code defect.
  • Home / map — a function docstring is a home (it owns the operation's formula); a module docstring is a map (linked one-liners, no formulas).
  • Cold read — parsing a docstring with the module's source and the design documents withheld; the acceptance test for self-containedness.
  • Class sweep — treating a flagged instance as a sample and fixing every occurrence on every surface.
  • Estimand / estimator — the population quantity an operation estimates, and the finite-sample rule that approximates it; where the package's leading identity is the estimand, the docstring states the first before the second.
  • Representation — how an object is stored or computed (physical, spectral); an object is never named by its representation — "a field in spectral representation", never "a spectral field".
  • The house notation set — upright \mathrm{i} and \mathrm{d}, coordinate-subscripted \partial_{x_i}, braced fraction and \boldsymbol arguments, no gratuitous \,, no manual spacing around relations, no \left/\right, \mathbb on capitals and k only; the vector notation and the admitted \mathbf strings are the package's own parameters.

Declared deviations — GBGCodingTools

Rendered by gbg sync from .gbg/exemptions.toml: every live entry of scope policy, scan, lint or harness. A rule listed here is disabled or refined for this package, with the reason and the date it lapses; a reading model treats the rule as the entry states it.

  • RULE.TEST.ALLOC_ZERO (scope policy, target *): no in-place operator over element storage exists here: this package's ! functions mutate a registry, a dictionary or a string buffer, and an allocation bound on them measures the Julia runtime, not the package [recorded 2026-09-09, expires 2027-09-09]
  • RULE.TEST.PASS_AUDIT (scope policy, target *): the traffic audit counts reads and writes per array element; this package holds no array whose traffic is a correctness property, so a frozen row would record the runtime's behaviour and nothing of the package's [recorded 2026-09-09, expires 2027-09-09]
  • RULE.TEST.EXAMPLES_RUN (scope policy, target *): this package ships no Literate examples: its literate surface is empty by design, since a worked example of a review instrument is a round, which is recorded under .gbg/rounds/ rather than executed as a script [recorded 2026-09-09, expires 2027-09-09]
  • RULE.DOC.LEADING_IDENTITY (scope policy, target *): the leading identity of a docstring is the physical meaning of the quantity it computes; this package computes no physical quantity, so its docstrings lead with what the operation does, which the rubric's own parameterisation already admits [recorded 2026-09-09, expires 2027-09-09]
