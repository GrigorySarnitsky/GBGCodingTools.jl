The instruments

Written by AI, not regularly reviewed

This page is written by AI and is not reviewed regularly by a human.

Generated at build time from instruments/<name>/PROTOCOL.md: the text gbg preflight <name> injects into the session that runs the instrument, verbatim. Each protocol assumes the round its preflight opened.

/check-docs

This text is injected into the session by gbg preflight check-docs, which has already validated the config, run the quick doctor set (the QUICK selection of checks, the ones that hold on any machine with no build and no network), verified the running copy and OPENED the round named in the lines that follow it. Everything below is done in that round, through the gbg verbs.

What it is

The full matrix of every check × every documentation surface, run to completion in one round — not one check, not one file. The surfaces come from the config: the rationale documents, the hand-written pages, the docstrings of src/ and ext/, the Literate examples, and the BUILT HTML after the docs build (what each @docs block actually collected is visible only there). The checks: correct, self-contained, notation, formatted, current and complete, cited, consistent across variant pairs — and the operational claims of each docstring against its body, which no other instrument holds together.

The deterministic half runs first, in the CLI; the judgment half is a fan-out of lanes, one per surface plus three cross-cutting lanes (one-home, cold-reader, operational-claims). A rationale surface that is one document is cut into rationale_lanes slices on its own headings, the first keeping the key rationale. Every surface lane is handed a computed CLAIM CHECKLIST — each cited number and each exit-code claim on its own surface — and owes a verdict per item in claims_checked[]. A lane reports CLASSES, never sites: a recurring defect is ONE finding whose locations name every site, and finding_cap bounds those findings, so a class with forty sites costs one. The lanes run at economy by default; the fix pass is never economised.

The round, step by step

  1. Prepare. gbg round prepare <round> runs the scan engine (gbg scan docs): every hard hit is banked as lane 00-scans, closed later by rescan, never by a verdict; every triage scan is printed in full — count first, then read all of it; NEVER pipe a scan through head or tail. It then runs the reflection checks (argument coverage under the package's argcov_policy, signature fidelity, dupref, xlink dry-run), builds the docs under GBG_ROUND (exit 0 required) and runs the built-HTML scans (gbg scan html): no docstring rendered on two pages, every derived public operation on a public page, no unexpected Base. name in an internal section (the config's allowance excepted). When the round is seeded (check-docs.seed_rounds), it also plants the labelled defects of the consumer's seed catalogue into a DISPOSABLE COPY of the lane files under the round's seed_root, with a per-round salt, and the lanes read that copy in place of the working tree. The ground truth is written at bank, never before; do not open the seeded copy yourself. One question is a read, not a scan: each API page's blurb against what its @docs block holds — read it from the build.
  2. Lanes. Launch the Workflow call preflight printed, exactly as printed. Each lane first discharges its claim checklist, then runs the six checks as POSITIVE procedures on its surface — enumerate, then verify each item, with src/ as ground truth and the decisive line quoted — and Writes findings/NN-<lane>.json FIRST, then returns the same object. The cold-reader lane reads the ?name view: the module docstring and EVERY method docstring of a generic; verify each of its findings against source before fixing, since a term may be defined on a sibling method it did not open. Every lane is forbidden .gbg/ and ~/.gbg/.
  3. Bank. gbg round bank <round>: schema-validates each lane file, quarantines an invalid one, assigns ids, freezes findings.json, renders findings.md and SUMMARY.md. A DEAD or REJECTED lane is exit 2 and nothing is frozen; gbg round rerun <round> --lanes … re-runs only the dead ones. On a seeded round it also recomputes the ground truth from the untouched tree and the salt, marks the seeded findings (they are never fixed in the corpus), prints recall per class and the SUSPECT lanes — those handed two or more seeds that reported none — and deletes the seeded copy.
  4. Fix pass — on the owner's word, at session strength. Work from findings.md by id. Fix the class, not the line. Drop the genuine false positives with a reason (universally standard math, the real Julia operators × ⋅ ≈, comment-line hits, a kwarg correctly backticked). The build is the oracle for link resolution: a clean exit refutes a "dead link" finding. Builds and tests during the pass go through gbg round build|test <round>.
  5. Verify. gbg round pass open <round> prints the act verifier (sees the diff) and the state verifier (blind) with this instrument's lanes as the roster; launch both as printed. It refuses to open while an open finding names a file the fix pass did not touch — fix the class at every location the finding names, or re-open with --sweep-ok when the fix rightly lives elsewhere. A pass after the first verifies only the ids still open, any closed one the fix pass has touched again, and any closed one that names no location at all; everything else keeps the entry that closed it. The act verifier grades only the open ids; a closed id back in scope is a re-check, read by the state verifier alone, and it stays closed while that reading is still ABSENT. The round has a budget of max_passes passes (3 by default); past it pass open refuses. A dismissal is a verdict the verifier grades like any other: it must name the rule or recorded decision that licenses it, and a dismissal the verifier cannot confirm is UNDONE, not closed.
  6. Grade. gbg round grade <round>: demotion, closure channels, plateau signal; a hard scan finding closes when grade re-runs the scan and it no longer fires. Loop 4–6 over the same findings.json; do NOT re-run the lanes to check the work — a fresh battery over an edited corpus always returns new findings, so it has no termination condition.
  7. Adjudicate and close. Ledger entries with scope = "finding" and overturn_when for what is not a defect; gbg round close <round> when no id is open, no lane is dead, the files are committed and the stamps are unchanged — or, once the pass budget is spent, with every id still open carried into the next round on a blind severity re-check, a serious one included, which then holds a final release back. If the fix pass touched src/ or ext/ — an operational finding fixed in the code, not in the prose — closing refuses until /audit-changes --base <this round's opening head> is itself closed and has read the round's LAST code change, so it runs after the final fix pass (RULE.INST.AUDIT_AFTER_CODE): the verifiers graded each finding, and nothing yet asked whether the edits were proportionate or whether behaviour moved for input that worked before. A class the pass could not fix because the fix is an INSTRUMENT change (a new scan, a changed lane) is one BULLET in <round>/deferred.md (a bullet may wrap; prose outside every bullet is carried nowhere); close carries it into .claude/WORK_QUEUE.md, where the Stop hook holds the next session to it. Never the roadmap: nothing reads the roadmap. Commit ⇒ push the round with the per-lane closure counts in the message.

The rules that carry the weight

  • Verify by EXIT CODE, never by grepping a log: a lint failure prints ERROR: LoadError:, which no ^┌ Error pattern matches, and three false "docs clean" reports once stood on that mismatch.
  • A scan's output is never truncated. A class swept from a truncated list is reported closed while half of it survives.
  • The fix pass is verified, not self-reported: bank, verify, grade, loop over the banked set.
  • "Check the docs" means this complete battery, never one check or one file.

/check-consistency

This text is injected into the session by gbg preflight check-consistency, which has already validated the config, run the quick doctor set (the QUICK selection of checks, the ones that hold on any machine with no build and no network), verified the running copy and OPENED the round named in the lines that follow it. Everything below is done in that round, through the gbg verbs; nothing is done by hand that a verb does.

What it is

An expert panel of fresh-eyed agents reads the rendered documentation site as a reader would — a reader-text manuscript consolidated from the built HTML, math as its TeX, one PAGE: banner per page — and collects every internal-consistency and expert-instinct defect: a quantity or normalization defined two ways across pages, a mathematical or category error, a structure or design smell, an unreachable citation, a cold-read gap. It is the judgment-level counterpart of /check-docs, which runs the deterministic battery against the source. Mechanical, pattern-matchable idioms (a gratuitous \,, an unbraced fraction, a bare-index partial) belong to /check-docs's scans, several of them build-enforced; do not lean on the panel for them.

Most hats read ONLY their manuscript. A few are granted more because their defect class is invisible in the rendered output: the typesetting hat reads the authored source and the rendered policy; the three rulebook hats read the rulebook sections the config names, because a convention the corpus breaks everywhere is invisible to a hat that infers norms from the corpus; the fossil hat reads git history. Every hat is forbidden .gbg/ and ~/.gbg/. The panel is COLLECT-ONLY: it never edits src/ or docs/; the session acts only when the owner says fix.

The round, step by step

  1. Prepare. gbg round prepare <round> builds the docs (exit 0 required; the build runs under GBG_ROUND, so the gate inside it ignores this round), consolidates docs/build into the two manuscripts under .gbg/scratch/<round>/ (manuscript-full.md, and manuscript-siteonly.md with the design docs the config withholds), and — when the round is seeded — plants the labelled defects of the consumer's seed catalogue into them with a per-round salt. During the panel ONLY the seeded copies exist; the ground truth is written at bank, never before. Do not open the manuscripts yourself.
  2. Panel. Launch the Workflow call preflight printed, exactly as printed. The hats run concurrently; each Writes findings/NN-<key>.json FIRST and then returns the same object. The script returns liveness only (written, dead, empty, truncated); no tally. A DEAD hat is a hat that produced no file; an EMPTY hat wrote a file with zero findings and a non-empty checked[]; the two are not the same thing, and the bank tells them apart.
  3. Bank. gbg round bank <round>: validates every lane file against the schema, quarantines an invalid one as .rejected.json, assigns ids <round>/<lane>#<n>, regenerates the UNSEEDED manuscripts, recomputes the ground truth, marks seeded findings by fragment match, prints recall per class (a skipped class is UNDEFINED, not zero) and flags SUSPECT any hat with two or more seeds on its substrate and zero matches, freezes findings.json, and renders findings.md and SUMMARY.md. Any DEAD or REJECTED lane is exit 2 and nothing is frozen; re-run only the dead lanes with gbg round rerun <round> --lanes … and bank again. A live lane whose file changed after first sight is REJECTED.
  4. Read. findings.md is the work list, by id; SUMMARY.md is a reading aid — deduplicated, ranked by severity × corroboration (k of the n hats whose substrate could see it), seeded hits subtracted, capped hats marked — and never the input to a fix pass. A severity in the summary never overrides the hat's own.
  5. Fix pass — only on the owner's word, at session strength, never economised. Work from findings.md by id. A flagged instance is a sample of a class: sweep every surface for the class. A build or test during the pass is gbg round build <round> / gbg round test <round>; a bare julia --project=docs docs/make.jl under an open round is refused by the gate, by design. Never fix the corpus from a seeded finding (bank marks them); never close a finding by declaring it "by design" or "for symmetry" — fix it, or put it to the owner as an adjudication with the trade-off.
  6. Verify. gbg round pass open <round> refuses while an open finding names a file the fix pass left untouched (--sweep-ok overrides) or once the round's max_passes budget (3 by default) is spent; verifies only the ids still open, any closed one the fix pass has touched again, and any closed one that names no location at all — the act verifier the open ids, the state verifier all of them, a closed id back in scope being a re-check it alone reads; records the fix range and a nonce, regenerates the manuscripts after a fresh build, and prints two Workflow calls: the act verifier (sees the diff; grades HONORED / ADJACENT / INSERTED / LINE-ONLY / NEW-DEFECT / SCOPE-CREEP / UNDONE / LAUNDERED, HONORED earned by an enumerated class_surfaces[] list read from the finding's own text, never from the diff) and the state verifier (blind to the diff; PRESENT / PARTIAL / REGRESSED / ABSENT / NOT-A-DEFECT / UNCLEAR, default PRESENT). Launch both as printed. Each verdict file carries the nonce and the sha of findings.json; a copy-forward verdict is REJECTED.
  7. Grade. gbg round grade <round> applies the demotion (HONORED becomes LINE-ONLY, mechanically, when class_surfaces[] is empty and equally when any entry in it is swept: false), the closure channels (honored, adjudicated, seeded, rescan, carried) and prints the pass series and the plateau signal; exit 1 while any id is open, and equally while any id is pending_state — closed by the act verifier with no state reading to confirm it. Loop 5–7 over the SAME findings.json: the denominator is fixed, so it converges. Re-running the panel over a just-edited corpus is a new search, not the closure loop; do it after closure if at all.
  8. Adjudicate. A finding that is not a defect is closed by a ledger entry in .gbg/exemptions.toml with scope = "finding", the id as target, a reason of at least 40 characters and an overturn_when condition. The CLI refuses a seeded id. Every such entry is audited by the dismissal auditor at close.
  9. Close. gbg round close <round> when the latest pass has no open id, no lane is dead, the round's files are committed and the stamps are unchanged (a changed config or a moved pinned version means gbg round pass open --regrade first). Once the pass budget is spent it carries every id still open into the next round on a blind severity re-check, a serious one included, which then holds a final release back. Commit ⇒ push the round; cite the closure per lane and id in the commit message. gbg round abandon <round> --reason "…" is the only wholesale exit and lists every open id — a plateau is the usual reason.

The rules that carry the weight

  • Collect-only until the owner says fix. Verify before you trust: a rendered-text read is not ground truth — confirm a blocker against the current source and the built HTML before relaying it.
  • Self-reported closure is not closure: the act verifier sees the diff, the state verifier is blind, the demotion is mechanical, and a zero count for a hat is a DEAD lane, not a clean hat.
  • The seeded copy is disposable and the ground truth reaches no hat. A hat that opens .gbg/scratch/ or diffs its manuscript against docs/build leaves a Read in its transcript; that residue is stated, not closed.
  • Loop to a plateau, not to a good round: three passes flat within noise, with no dead lanes, is closure.
  • Seeds measure recall only for the defects someone thought to plant. The panel is measured against a human read as well: gbg calibrate runs each hat blind on the passages recorded in .gbg/human-findings.toml and names every defect a hat missed and every one no persona's rubric covers — outside any round, whenever the owner has read the site.

/bug-hunt

This text is injected into the session by gbg preflight bug-hunt, which has already validated the config, run the quick doctor set (the QUICK selection of checks, the ones that hold on any machine with no build and no network), verified the running copy and OPENED the round named in the lines that follow it. Everything below is done in that round, through the gbg verbs.

The one rule

A static claim about code is a hypothesis. The only admissible evidence is a program that FAILS.

/check-docs and /check-consistency audit prose; neither asks whether the code is correct. This one hunts the code, and it is a correction for a measured failure mode, not a preference: an agent reading code and reporting what "looks wrong" produces fluent, confident, unfalsifiable prose, and here that costs a fix pass on WORKING code — strictly worse than the imagined bug, because the tree gets edited, the suite still passes, and afterwards nobody can tell whether anything was ever wrong. So the hunt is static and the confirmation is dynamic. Every candidate reduces to a WITNESS: a self-contained @testset asserting the CORRECT behaviour, therefore observed to FAIL on this tree.

the witness …means
FAILSthe finding. Unchanged, it is the regression test the fix must flip.
PASSESnot a bug. Discarded, however good the argument.
ERRORSevidence about the witness, not the package. Fixed and re-run, or BLOCKED with a reason.
cannot be writtena latent hazard: reported, never fixed on that evidence.

A failing witness is necessary and NOT sufficient: a witness can fail because the WITNESS is wrong, and a test asserting a false identity fails on perfectly correct code. The reproducer therefore derives the expected value INDEPENDENTLY of the assertion — from the documented contract, an analytic case, a mathematical identity, or a second route to the same quantity — and returns WITNESS-WRONG when that derivation agrees with the code. Two classes escape the witness rule and are handled explicitly: ARCHITECTURE (duplication, divergent copies, a leaked abstraction, an invariant broken in code — no test can fail on it, so the evidence is two quoted locations a reader can diff plus the stated maintenance consequence; verdict EVIDENCED), and API-SEMANTICS (a claim about what Base or a dependency does — the official documentation fetched and quoted with its URL AND a witness that runs).

Lanes

The consumer's TERRITORIES (from its config) plus two FREE lanes that are always present and anchored: lanes differ by territory so coverage spreads; the free lanes carry no list, because a list is a hypothesis about where bugs live and a defect outside every class is invisible to every class lane by construction while the run still reports complete. Hunters produce hypotheses with a witness plan; a pipeline hands each candidate to a REPRODUCER at session strength, which writes the witness under the round's witnesses/, runs it with quoted paths under the configured witness environment, and rules. Hunt lanes run at economy by default; reproduction is never economised. Every agent is forbidden .gbg/ except the round's own witnesses/ directory, and ~/.gbg/.

The round, step by step

  1. Hunt. Launch the Workflow call preflight printed, exactly as printed. Each lane Writes candidates/NN-<lane>.json and, through its reproducers, the witnesses witnesses/<lane>-<n>.jl. The script returns liveness only. A lane that died is UNHUNTED territory, not clean territory.
  2. Bank. gbg round bank <round> runs the witness runner itself over witnesses/ expecting failure — the lane's ACCOUNT of a failing program is not the program. It refuses any witness that includes a file or loads anything outside the package under test, Test and the stdlib; REJECTS a REPRODUCED whose witness does not fail mechanically; records the sha256 of every failing witness body; assigns BLOCKED only to a witness that ERRORED, was never observed to fail, and carries a # blocked: <reason> header (moved to witnesses/blocked/); freezes findings.json and the disposition records reproductions/<id>.json. A DEAD or REJECTED lane is exit 2 and nothing is frozen.
  3. Fix — on the owner's word, at session strength, never economised, driven from findings.md by id. A witness is never edited to suit a fix: a witness edited to pass has stopped being evidence. Builds and tests during the pass are gbg round build|test <round>.
  4. Dispose. Every confirmed finding ends in exactly one of three states in its disposition record: fixed (its witness flips), refused (with a reason of at least 24 characters and the measurement recorded at the site), or escalated (a design decision put to the owner, with overturn_when; its witness stays under witnesses/escalated/ and is never promoted, so nothing reads green over it). A finding in none of these is a DROPPED finding and close fails on the arithmetic.
  5. Promote. Each fixed witness is promoted into test/regressions/ by explicit path, per finding as it closes, with its provenance header stripped and its body otherwise unchanged — the promoted body must hash-equal the bank-time body. Never cp witnesses/*.jl: a still-open witness promoted turns the suite red for what looks like a bad fix, and a name reused across rounds overwrites an older regression test. A witness locates files through pkgdir, never by counting .. hops.
  6. Verify the architecture class. gbg round pass open <round> prints the architecture verifier (FIXED / RELOCATED / PARTIAL / ABSENT / NOT-A-DEFECT, default ABSENT); it hunts RELOCATED, the duplicate moved to a new file that reads as a fix in a diff and as a defect in the tree. gbg round grade <round> folds it in.
  7. Audit the edits. Before close, an /audit-changes round with base = this round's opening head and head = HEAD must be run and closed: a witness exists only for a defect the hunt FOUND, so a regression introduced by a FIX is invisible to the witness gate — measured: NEWLY BROKEN = 0 while two regressions were live.
  8. Close. gbg round close <round> requires, in order: the round's files committed; the witness of every fixed finding PASSING under the runner (gbg witnesses pass <round>); every fixed witness promoted with a hash-equal body; Pkg.test() green under GBG_ROUND (gbg round test); the dismissal auditor run over every refusal and adjudication with reopened == [] (a filed dismissal is never revisited otherwise, and two of a real round's were wrong, one a blocker — it defaults to UNSAFE); the audit-changes round closed; fixed + refused + escalated == confirmed; the opening head an ancestor of HEAD; a clean tree; pushed. BLOCKED witnesses are listed in the close account with their reasons and re-run by gbg doctor --deep on a host that has the device.
  9. The pass budget. A hunt has max_passes verification passes (3 by default); past it pass open refuses, and close carries every finding still open into the next hunt, a blocker or major included, which then holds a final release back. A carried finding owes this round no disposition and takes its evidence with it: the next hunt's bank copies its witness in and re-runs it, so a defect still failing is confirmed again, and one whose witness now passes leaves the carried ledger.

Run the hunt ONCE; loop the disposition

The finding set is fixed by one hunt. What loops is fix → witness → dispose over that set, which terminates because the set is finite. A follow-up hunt confirming "nothing new" is not a closure condition: each round's fixes seed the next round's findings (measured across five rounds: 20, 9, 17, 21, 17), so such a rule makes "finished" permanently false and licenses unbounded edits to CODE. Run a new hunt as a new round, on the owner's word, never as the way to close this one.

/audit-changes

This text is injected into the session by gbg preflight audit-changes, which has already validated the config, run the quick doctor set (the QUICK selection of checks, the ones that hold on any machine with no build and no network), verified the running copy and OPENED the round named in the lines that follow it, with the REQUIRED base commit recorded in it. Everything below is done in that round, through the gbg verbs.

The question, and why it is not a defect hunt

Was each change proportionate to the defect it claims to fix, and did it silently alter behaviour for input that previously worked?

/check-docs and /check-consistency audit prose; /bug-hunt audits code. This one audits CHANGES to code — it reads the diff, not the tree. An edit can be a correct fix and still be wrong to make: wider than the defect required, changing a default, rejecting a workflow that used to be legitimate, breaking a contract the fix did not need to touch. Neither the code nor the fix looks wrong in isolation, which is exactly why a hunt cannot find it. A finding that would have been true BEFORE the diff belongs to /bug-hunt, not here. Run it after any instrument's fix pass (the hunt's close requires it), or on request over any commit range.

Two structural rules, each from a demonstrated failure

The norm is pinned at BASE, never at HEAD. The docstrings and tests a lane would naturally treat as the standard were themselves edited in the audited window — the audited party rewrote the description of the thing being audited. A contract quietly amended to match changed behaviour IS the defect, not the baseline: read it at base with git show <base>:<file>.

test/ is inside the audited material. A fix that also edited the test that would have caught it, or re-baselined a frozen ledger in the same commit, is the shape that certifies itself. Every change under test/ and to a baseline is a claim to be checked, never the standard.

Lanes

Thirteen lanes from the catalogue, differing by LENS: ten code lanes (free-reader, executing†, under-rejection†, backend-portability, behaviour-change†, over-rejection†, public-contract, numerics, invariants, claim-versus-edit) and three prose lanes (contract-drift†, sweep-completeness, reader-consequence); † is an anchor, never economised. The lane set was settled by ATTACKING it rather than by taste: the design attacker put a logician, a philosopher, a red-teamer and a measurement specialist against an earlier list and demanded a concrete harmful edit that passes every lane; it produced eleven fatal gaps, and three of four attackers converged on the same one — not a single lane ran anything. Hence executing, which RUNS every measurement claim and calls every new entry point the way its own documentation says to; under-rejection, the guards removed or weakened, which fail silently; and backend-portability, bit-identical on Array and broken on a device. The kind of the round — code, prose or both — is derived from the diff's paths and selects the lanes; a lane that cannot fire on the diff at hand teaches the reader to discount CLEAN everywhere. Covered paths are src, test, ext, docs, Project.toml plus every [paths] entry of the config; config can only add.

The round, step by step

  1. Prepare. gbg round prepare <round> writes the diff (git diff <base>..HEAD -- <covered>), the claims (git log --format="%h %s" <base>..HEAD), the diffstat, the guard symbols and the invariants text from the config into .gbg/scratch/<round>/, derives kind, and resolves the lanes.

  2. Audit. Launch the Workflow call preflight printed. Each lane reads the diff FIRST and in full, then whatever of the tree it needs, and Writes findings/NN-<lane>.json before returning: a verdict CLEAN or CONCERNS, a non-empty checked[] (REQUIRED, especially when clean — clean with an empty list is indistinguishable from a lane that did nothing and is read as such), candidates_found, and the concerns, each with severity (blocker / major / minor / nit), justified (yes / no / unclear), before and after quoted from the diff, why_it_matters, and on the behaviour-change lane previously_worked (yes / no / unknown, unknown gated like yes). An assertion with no quotation is not a concern. Every lane is forbidden .gbg/ and ~/.gbg/.

  3. Bank. gbg audit-changes bank <round> (like every round verb it verifies the running copy and the torn-file guard first): schema-validates the lane files; RUNS the executable claims itself — the package's test gate and each file the config names under executable_claims — under GBG_ROUND and records their exit codes in audit.json, so the executing lane's account is corroborated by a program; runs the severity re-check (an anchor) before "serious" is counted — over the minor and nit concerns not already gated by previously_worked, several per agent, since the gate takes the more serious rating and nothing else can move; freezes findings.json. A DEAD or REJECTED lane is exit 2: that lens is UNAPPLIED, not clean.

  4. Dispose. Every serious concern (blocker or major) and every concern with previously_worked ∈ {yes, unknown} — that field is what the instrument exists to surface, so its severity is not the reporting lane's to downgrade — carries a disposition: fixed, refused with a reason of at least 24 characters, or escalated to the owner with overturn_when. An absent disposition is a dropped finding. Never close a concern by declaring it "by design": answer it or escalate it.

    This step never edits the tree. fixed names a correction the NEXT change set carries, which the next audit then covers; it does not mean "corrected just now". Closing requires that no covered path has moved since the audited head, so a correction made inside the round makes that round unclosable — there is no re-bank — and every disposition recorded in it is lost with it.

  5. Close. gbg round close <round> requires: no dead lane; every gated concern disposed; an empty audit's verdict_all_clean backed by checked[] on every lane AND every recorded executable-claim exit code zero; staleness clean — git diff <audited head>..HEAD -- <covered> empty, with an unreachable audited commit read as UNCHECKABLE, never as clean (empty output from a rebased-away commit is indistinguishable from "nothing changed", and that inversion once passed a stale audit); the dismissal auditor run with reopened == []; the files committed and pushed. The doctor warns (AUDIT.GAP) when this round's base is not the previous closed audit's closed_head — the head it CLOSED at, falling back to head where the earlier round records none.

Why it has no adversarial verifier

The doc instruments carry a state verifier because "is this finding fixed?" is a judgement and judgements get quietly dropped. This one holds its mechanical anchor — the executing lane and the CLI's own re-run of the executable claims — and a second adversarial layer auditing the auditor is where the regress starts and the grounding stops. What it has instead is the disposition gate above, the severity re-check, and the design attacker every lane list has to survive — gbg attack <instrument>, run whenever a lane or hat list changes.
