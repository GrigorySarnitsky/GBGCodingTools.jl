Reading the texts, and finding a place in them again.

GBGCodingTools.Texts — Module
Texts

Reading the texts a rule is about, and finding a place in them again after they have moved: the docstrings of Julia source, the headings of Markdown pages, and the re-anchoring both exist for.

A line number is not a place. A fix earlier in a file moves every line below it, four fix passes compound that, and a finding carried from an earlier run had its lines read at an older commit — so a stale number points at whatever now sits there, which is how a fix lands in the wrong paragraph.

A Model.Location is therefore the file, the NODE (for Julia the binding, method or field of a constant documented; for Markdown the heading path), the QUOTE as it read then, and the line as a hint only. The function reanchor finds the node, then the quote inside it; failing that the quote, nearest the old line; failing that it says OUTDATED rather than guessing.

This module is the second of the order and may name only Model. It parses Julia with the compiler's own parser, so what it calls a definition is what Julia calls one.

GBGCodingTools.Texts.argument_list — Function
argument_list(signature) -> Union{String,Nothing}

What sits between the parentheses of a call: the FIRST opening parenthesis and the one that closes it, matched by depth. The argument is signature, the signature line. Returns the text inside, or nothing where the line holds no balanced call.

Depth matching is what makes it right. Cutting a -> … return annotation off first is unsound, because a default holding an arrow — exempt = (hit -> false) — is then cut in half and the signature parses as nothing at all.

GBGCodingTools.Texts.definitions — Function
definitions(path) -> Vector{NodeSpan}

Every named node of the Julia file at path, in source order: each function, macro, struct, module and constant, and each keyword field of a constant that is written as a keyword call, which is how a generated docstring such as ARGS_FORM.statement has a node of its own.

The argument is path, the file to read. A file that does not parse yields what parsed rather than an error, since a caller asking where something is must not be stopped by a file that is temporarily broken. Returns the spans.

A name is BARE, g and not Inner.g, inside a submodule as at the top: a location's node is looked up by the name a reader writes, and no reader writes the qualified one.

GBGCodingTools.Texts.parameters — Function
parameters(inside) -> Tuple{Vector{String},Vector{String}}

The positional and keyword parameter NAMES of an argument list, with their types and defaults taken off. The argument is inside, the text between the parentheses. Returns the two lists, positional first.

A bare keyword splat, kwargs..., counts as a parameter although it is not an identifier: f(cfg; kwargs...) takes keywords, and dropping the splat would read it as taking none. A typed splat is already its own name and is not counted twice.

GBGCodingTools.Texts.prose_text — Function
prose_text(path; comments = true) -> String

The file's PROSE alone, with every other line left empty so that line numbers are unchanged.

Arguments

  • path — the Julia file to read.
  • comments — whether ordinary comments count as prose here.

Returns the masked text.

The distinction matters to a rule about RENDERING: a docstring is published and a comment is not, so a rule that exists because a reader would see the wrong thing on the page reads docstrings alone, while a rule about what the text says reads both.

A documentation rule reads this rather than the source. Julia code is full of text that looks like prose markup — a regular expression holding double backticks, a string holding a pipe table — and a rule handed the whole file reports the code as though it were the prose about it. Keeping the line numbering is what lets a finding still say where it is.

GBGCodingTools.Texts.reanchor — Function
reanchor(root, loc; loose = true) -> Model.Location

The location as it stands now: the same file, the same node and quote, with the line found again and found saying how. The node is looked for first and the quote inside it (BY_NODE); failing that the quote alone, the occurrence nearest the old line (BY_QUOTE); failing that the location is OUTDATED and its line is left as it was, never pointed at whatever now sits there.

A node that survives does not anchor a finding whose quote is gone: the finding was about that text, and a fixer sent to a paragraph it was not written about is the failure this exists to prevent. A location with a node and no quote is about the node itself and anchors to it.

Arguments

  • root — the package root.
  • loc — the location to find again.
  • loose — whether a quote may, as a last resort, be matched as the built page reads it.

A location with neither node nor quote is the file itself and comes back unchanged while the file exists. Returns the located copy.
