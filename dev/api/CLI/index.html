The wrapper and the dispatcher

GBGCodingTools.makedocs — Function
makedocs(cfg; kwargs...)

The mandatory docs-build wrapper a consumer's docs/make.jl calls instead of Documenter.makedocs. The body is defined by the Documenter extension (ext/GBGCodingToolsDocumenterExt.jl), which Julia loads once Documenter is in the environment — a consumer's make.jl already does using Documenter.

The arguments are:

  • cfg — the validated config object Config.read returns; it names the surfaces the scans read and the instruments whose open rounds gate the build (a round is one run of an instrument over the consumer, tracked under .gbg/rounds/).
  • kwargs... — passed through to Documenter.makedocs unchanged (sitename, pages, modules, checkdocs, doctest, format, …).

Before Documenter runs it runs, in-process, the quick doctor set, the hard scans over the source surfaces and the closure gate of the two docs instruments; after Documenter it runs the built-HTML scans and the gate again. Any non-zero return is an error, so the build fails. It prints one banner line, GBGCodingTools v<ver> makedocs, which a consumer's CI greps for. Returns whatever Documenter.makedocs returns.

GBGCodingTools.VERBS — Constant
VERBS

The closed verb table of the command line: "<noun> <verb>" (or a lone "<noun>") to the function that runs it. Every entry takes the remaining arguments as a Vector{String} and returns the exit code as an Int. Each src/CLI/*.jl file registers its own verbs at load; nothing else adds to the table, and a verb that is not in it does not exist.

GBGCodingTools.Sync — Module
Sync

Renders and checks the managed footprint of a consumer — a managed file is one the tool renders into the consumer and hash-checks thereafter, edited only by gbg sync, never by hand: the skill stubs, the Stop hook and its settings.json, the policy copy under .gbg/policy/, the regressions README, the managed blocks of CLAUDE.md and .gitignore, the tool's entries in every sub-environment Project.toml, the CI fragments, and the sidecar .gbg/managed.json. Sync.plan computes what every managed file must contain; Sync.status compares the tree with it; Sync.sync writes.

source
GBGCodingTools.Sync.plan — Function
plan(cfg; ledger = Ledger.read(cfg)) -> Vector{ManagedFile}

Every generated-managed file for a consumer: one skill stub per enabled instrument plus gbg-doctor, .claude/settings.json, .claude/hooks/queue-guard.sh, the policy copy and test/regressions/README.md. The arguments are cfg, the validated config, and ledger, the ledger entries. The two managed blocks and the sub-environment entries are planned by managed_block and subenv_entries. Returns the list.

source
GBGCodingTools.Sync.status — Function
status(cfg; ledger = Ledger.read(cfg)) -> Vector{Entry}

Compares the tree with a fresh render of every managed file and block, and lists sidecar entries whose file is no longer planned (ORPHAN). The arguments are cfg, the validated config, and ledger, the ledger entries. Returns the entries; MANAGED.HASH fails on any MODIFIED or UNMANAGED, MANAGED.STALE on any STALE, MISSING or ORPHAN.

GBGCodingTools.Sync.render — Function
render(text, slots) -> String

Substitutes every {{key}} in text from slots. A key with no value is a SyncError, never an empty string. Returns the rendered text.

GBGCodingTools.Sync.managed_block — Function
managed_block(cfg, file, s) -> String

The rendered managed block for one file. The arguments are cfg, the validated config; file, "CLAUDE.md" or ".gitignore"; and s, the slot values. The CLAUDE.md header's sha256 is the sha256 of the block's body lines (between the markers), so an edited body no longer matches its header. Returns the block text ending in a newline.

source
GBGCodingTools.Sync.subenv_entries — Function
subenv_entries(cfg, envdir) -> Dict

The [deps], [sources] and [compat] entries for the tool in the sub-environment at envdir (relative to the root): pinned at a release, the https url and rev = "v<version>" with [compat] = "=<version>"; pinned at dev, a path source resolving to the tool repository and no compat. Returns Dict("deps" => uuid, "sources" => Dict, "compat" => String or nothing).

GBGCodingTools.Init — Module
Init

Seeds a consumer: Init.derive_config reads the package tree into a config that validates, Init.init writes .gbg/ and the seeded-once files and renders the tool's entries into every sub-environment, Init.migrate_baselines converts the three Julia test literals to their TOML form textually, Init.migrate_seeds converts a former seed_defects.py catalogue, and Init.new adds a fifth package. init never renders the generated files (the skill stubs, the hook, the CI fragments, the managed blocks): that is gbg sync, which validates what init wrote.

source
GBGCodingTools.Init.derive_config — Function
derive_config(root) -> Dict

The best config the package tree supports (ARCHITECTURE §5): name and description from Project.toml, modules from the module declarations under src/, the surfaces that exist, the history and references anchors found by heading, the executable claims and guard symbols present, one bug-hunt territory per source file, the eight generic hats. The tool root gets its own delta (§5.6); a tree inside the tool repository is pinned dev. The result validates against the schema with defaults materialised; a value the tree cannot supply is written with a TODO the doctor will flag, never invented. Returns the config (without root).

GBGCodingTools.Ledger — Module
Ledger

The reader of a consumer's exemption ledger .gbg/exemptions.toml: Ledger.read validates the file against schema/exemptions.schema.json and returns its entries, Ledger.entries selects the ones naming an id, and Ledger.matches applies an entry's optional match table to a trigger. The doctor's CFG.EXEMPTIONS check applies the ledger's semantic rules (expiry bounds, the non-exemptable prefixes); the reader only parses.

source
GBGCodingTools.Doctor — Module
Doctor

The read-only health check of a consumer's tooling (D14, §7.3). Every check has a stable id, returns PASS, WARN, FAIL or NA, and can be selected by id or prefix; the QUICK set is the subset that holds on a runner with no shim and a detached HEAD. A scope = "check" ledger entry on an exemptable id (LEG.*, GIT.*, AUDIT.*) turns its FAIL into a WARN naming the reason; the non-exemptable families are the tool's own enforcement.

source
GBGCodingTools.Doctor.select — Function
select(only; deep = false) -> Vector{String}

The check ids a run covers: every non-deep check (plus the deep ones with deep = true), or the ids named in only — exact ids, prefixes such as LOAD or WIRE, or the literal QUICK. Returns the ids in table order.

GBGCodingTools.Preflight — Module
Preflight

The opener of a round and the one renderer of Workflow args. Preflight.preflight is the verb; Preflight.resolve_roster turns config and catalogue into the numbered hats or lanes; Preflight.write_payloads writes every large payload as a file under the round's scratch; Preflight.render_args builds the small args object naming those paths; Preflight.workflow_call prints the call the session launches verbatim.

resolve_roster(cfg, instrument; kw...) -> Vector{Dict}

The numbered roster of an instrument: hats for check-consistency, lanes otherwise; nn assigned in order from 01. Keywords: profile, explicit (hats); kind (audit).

GBGCodingTools.Preflight.write_payloads — Function
write_payloads(cfg, instrument, round, roster; base = nothing) -> Dict{String,Any}

Writes every large payload of the instrument under .gbg/scratch/<round>/workflow/payload/. The arguments are:

  • cfg — the validated config.
  • instrument — the instrument name.
  • round — the round id.
  • roster — the resolved hats or lanes; each gains its persona_path or brief_path.
  • base — the audit's base commit (required for audit-changes).

The files: personas (hats/<key>.md), the rulebook (rulebook.md), the policy (policy.md), briefs (lanes/<key>.md), the invariants (invariants.md), and for the audit the diff, diffstat and claims of base..HEAD over the covered paths. The manuscripts are written by gbg round prepare; their paths are returned here so the args can name them. Returns the paths.

source
GBGCodingTools.Preflight.render_args — Function
render_args(cfg, instrument, round, roster, paths; strength, cost, opened, base, head, kind, ledger) -> Dict

The Workflow args of the instrument's main script (its schema.json args): small scalars and the payload paths, never a payload. The arguments are:

  • cfg — the validated config.
  • instrument — the instrument name.
  • round — the round id.
  • roster — the resolved hats or lanes with their payload paths.
  • paths — the payload paths write_payloads returned.
  • strength — economy or full; cost — the config's cost default; opened — the round's opening timestamp.
  • base, head, kind — the audit's commits and kind (nothing elsewhere).
  • ledger — the ledger entries (the adjudicated titles come from them).

The result is validated against the schema before it is returned. Returns the args.

GBGCodingTools.Rounds — Module
Rounds

The round store's writers before verification. Rounds.prepare builds, consolidates, scans or diffs as the instrument needs; Rounds.bank validates the lane files, classifies dead lanes, assigns ids, marks seeds and freezes findings.json; Rounds.rerun re-launches dead lanes; Rounds.abandon is the only wholesale exit. build and test run the consumer's commands under GBG_ROUND so the gate inside them ignores this round.

source
GBGCodingTools.Passes — Module
Passes

Passes.pass_open opens a verification pass (nonce, range, expected counts, the regenerated manuscripts, the verifiers' Workflow calls); Passes.grade validates the verdict files, applies the demotion and the four closure channels and writes the tally; Passes.close checks every closing condition of the instrument in order and stamps the round closed.

GBGCodingTools.Seeds — Module
Seeds

Plants labelled defects into the consolidated manuscripts so a panel's recall is measurable. Seeds.select picks one occurrence per class with a per-round salt, Seeds.plant mutates the manuscripts, and the same select over the unseeded manuscript at bank is the ground truth.

source
GBGCodingTools.Seeds.select — Function
select(catalog, full, round) -> (seeded, skipped)

The seed plan for a round. The arguments are catalog, the consumer's seed catalogue (the seeds shape); full, the FULL manuscript text; and round, the round id that salts the selection.

For every [[class]]: the occurrences of anchor in full; the chosen one is ((occurrence - 1 + salt_offset) mod count) + 1; a class whose anchor occurs nowhere is skipped and named. Returns the plan [{id, class, page, start, stop, original, replacement, original_context, mutated_context}] (byte positions into full) and the skipped classes.

source
GBGCodingTools.Seeds.plant — Function
plant(full, siteonly, plan) -> (full′, siteonly′)

The manuscripts with every planned seed applied. The arguments are full and siteonly, the two manuscript texts, and plan, the selection select returned. In full the seeds are applied at the recorded positions (from the end, so positions stay valid); in siteonly each seed is located as the same occurrence of its original text within the same page (the site is a subset of the full manuscript page by page, so a seed on a withheld page is absent there by design, and a neighbouring seed already applied cannot hide it). Returns both.

GBGCodingTools.Recall.suspect_hats — Function
suspect_hats(findings, ground_truth, roster, site_pages) -> Vector{String}

Every hat with two or more seeds on its substrate and zero seeded findings of its own. The arguments are findings, the banked findings after mark!; ground_truth, the seed plan; roster, the round's roster; and site_pages, the page banners the site-only manuscript keeps (a siteonly hat sees only seeds on those pages). GBGCodingTools.demote — Function
demote(verdict) -> (verdict′, demoted::Bool)

The one demotion rule over an act verdict — the act verifier's grade of what the fix pass DID to one finding, from the diff (the state verifier grades, blind to the diff, whether the defect is still there). class_surfaces is the list the verifier fills from the finding's own text: every surface carrying the same class and whether the diff swept it. An act verdict HONORED whose class_surfaces is empty becomes LINE-ONLY (a fix graded honoured without the class enumerated is a line fix by construction); every other verdict is returned unchanged. Returns the verdict and whether it moved.

GBGCodingTools.Git.porcelain — Function
Git.porcelain(root; untracked = true) -> Vector{Tuple{String,String}}

git status --porcelain seen from a consumer at root, as (status, path) pairs with paths relative to root; with untracked = false untracked files are left out. GBGCodingTools.consolidate — Function
consolidate(build_dir, withheld; out_full, out_siteonly) -> (pages, nfull, nsite)

Renders every page of the Documenter build under build_dir into reader text — headings as #, code as fences, tables as | rows, admonition titles as [ADMONITION], list items as -, formulas as their raw TeX (Documenter renders KaTeX client-side, so the TeX is the page's text) — delimited by ===== PAGE: <name> ===== banners, discovered from the build so the manuscript stays complete when pages are added. Writes two manuscripts: out_full with every page, and out_siteonly without the pages whose relative path contains one of the withheld words (the design documents the config names under design_docs_withheld). Returns the page count and the two character counts.

GBGCodingTools.Hit — Type
Hit(file, line, text; symbol = "")

One scan hit. The fields are:

  • file — the surface file, relative to the consumer root.
  • line — the 1-based line, or 0 when the hit is about the whole file.
  • text — the excerpt or message a reader needs.
  • symbol — the owning binding when the scan knows it (what a ledger entry's symbol predicate is matched against); empty otherwise.

The arguments of the constructor are the fields, symbol as a keyword.

GBGCodingTools.ScanResult — Type
ScanResult

The outcome of one scan. The fields are:

  • id — the scan id.
  • rule — the rule it enforces.
  • tier — hard or triage, the argcov_policy tier resolved from config.
  • hits — the surviving hits.
  • population — what the scan measured (files, docstrings, exports, arguments or pages); zero means the scan measured nothing and is DEAD.
  • exempted — the number of hits the ledger removed.
  • note — a scan-level message: an error, a dead-lane reason, empty otherwise.

GBGCodingTools.TreeHash — Module
TreeHash

Git's content hashing, reimplemented on the SHA stdlib so the running copy can re-hash itself without git: TreeHash.blob_hash and TreeHash.tree_hash reproduce the object ids git hash-object and git write-tree would give, which is what Pkg records as git-tree-sha1 in a manifest and reports as tree_hash from Pkg.dependencies(). gbg self verify compares the two.

source
GBGCodingTools.TreeHash.tree_hash — Function
tree_hash(dir; skip = (".git",)) -> String

The git tree id of the directory dir, computed as git write-tree would over every file below it: entries sorted by git's rule (a directory name compares with a trailing /), modes 100644, 100755, 120000 and 40000, empty directories omitted. Entries named in skip at any level are ignored, .git by default, so a working tree hashes the same as the tree its HEAD names when it is clean. Returns the hex id; an empty tree returns git's well-known empty-tree id.

source
GBGCodingTools.TreeHash.blob_hash — Function
blob_hash(path) -> String

The git blob id of the file at path: SHA-1 over "blob <size>\0" followed by the content (a symlink hashes its target path, as git does). Returns the 40-character lowercase hex id.
