The wrapper and the dispatcher

GBGCodingTools.makedocs — Function
makedocs(cfg; kwargs...)

The mandatory docs-build wrapper a consumer's docs/make.jl calls instead of Documenter.makedocs. The body is defined by the Documenter extension (ext/GBGCodingToolsDocumenterExt.jl), which Julia loads once Documenter is in the environment — a consumer's make.jl already does using Documenter.

The arguments are:

  • cfg — the validated config object Config.read returns; it names the surfaces the scans read and the instruments whose open rounds gate the build (an instrument is one of the four review procedures and a round is one run of one over the consumer, tracked under .gbg/rounds/; GBGCodingTools binds both terms).
  • kwargs... — passed through to Documenter.makedocs unchanged (sitename, pages, modules, checkdocs, doctest, format, …).

Before Documenter runs it runs, in-process, the quick doctor set — the :QUICK selection of GBGCodingTools.doctor, the checks that hold on any machine with no build and no network — the hard scans over the source surfaces and GBGCodingTools.gate, the closure gate, over the two docs instruments; after Documenter it runs the built-HTML scans and that gate again.

Any non-zero return is an error, so the build fails — except either gate refusing only because a docs round is open, which prints a skip line and returns nothing, exit 0, unless GBG_DOCS_NO_SKIP is set: before Documenter nothing is built, and after it (a round opened while the site built) the site is built and not deployed. It prints one banner line, GBGCodingTools v<ver> makedocs, which a consumer's CI greps for.

Returns what Documenter.makedocs returns, true when that is nothing — as it is unless debug = true is passed — or nothing when an open round of a docs instrument froze the build (GBGCodingTools.frozen_rounds): the skip is exit 0, so a red docs run keeps meaning something is broken, and a make.jl deploys only when the value is not nothing. GBG_DOCS_NO_SKIP turns the skip back into the refusal, which is how gbg release and the deep doctor run it.

GBGCodingTools.VERBS — Constant
VERBS

The closed verb table of the command line: "<noun> <verb>" (or a lone "<noun>") to the function that runs it. Every entry takes the remaining arguments as a Vector{String} and returns the exit code as an Int. Each src/CLI/*.jl file registers its own verbs at load; nothing else adds to the table, and a verb that is not in it does not exist.

GBGCodingTools.Sync — Module
Sync

Renders and checks the managed footprint of a consumer — a managed file is one the tool renders into the consumer and hash-checks thereafter, edited only by gbg sync, never by hand: the skill stubs, the Stop hook and its settings.json, the policy copy under .gbg/policy/, the regressions README, the managed blocks of CLAUDE.md and .gitignore, the tool's entries in every sub-environment Project.toml, the CI fragments, and the sidecar .gbg/managed.json. Sync.plan computes what every managed file must contain; Sync.status compares the tree with it; Sync.sync writes. Two of the parts it renders are documented on their own: Sync.managed_block, the managed block of CLAUDE.md or .gitignore, and Sync.subenv_entries, the tool's [deps], [sources] and [compat] entries in one sub-environment.

GBGCodingTools.Doctor — Module
Doctor

The health check of a consumer's tooling: every check reads the tree and writes nothing, except the --deep set, which runs the package's builds and tests. Every check has a stable id, returns PASS, WARN, FAIL or NA, and can be selected by id or prefix; the QUICK set is the subset that holds on a runner with no shim and a detached HEAD. A scope = "check" ledger entry on an exemptable id (LEG.*, GIT.*, AUDIT.*) turns its FAIL into a WARN naming the reason; the non-exemptable families are the tool's own enforcement.

anchor carries three unrelated senses across this package, and the checks below touch two: a hat's or lane's anchor is whether it runs at full strength rather than on the economy model that GBGCodingTools.Config defines (CFG.HATS); Config.resolve_anchor's is a file#heading Markdown reference; a seed class's, in Seeds.select, is the regular expression marking where the seed is planted. No one of them implies another.

write_payloads(cfg, instrument, round, roster; base = nothing) -> Dict{String,Any}

GBGCodingTools.Rounds — Module
Rounds

GBGCodingTools.Passes — Module
Passes

The verification half of a round. Each pass has two verifiers, both agents the session launches, each grading in a closed vocabulary:

  • the act verifier sees the fix pass's diff and grades what it did to each open finding: HONORED (the ask landed by the right means, with class_surfaces naming every other surface carrying the class and whether the diff SWEPT it — fixed the class there, not just the site the finding named), LINE-ONLY (the instance is fixed, the class is alive), ADJACENT (something was done, but not what was asked), INSERTED (repaired by appending, so the flagged text survives beside it), NEW-DEFECT (the fix introduced a fresh one), SCOPE-CREEP (unasked changes, or a flagged term carried through a rewrite), UNDONE (nothing in the diff addresses it) and LAUNDERED (closed by declaring it acceptable);

  • the state verifier never sees the diff and grades whether the defect is in the tree now: PRESENT (its default), PARTIAL (some of the class survives, named in surviving_class), REGRESSED (fixed once and back again), ABSENT, NOT-A-DEFECT or UNCLEAR (the blind read cannot settle it either way, which closes nothing) — of which only ABSENT and NOT-A-DEFECT are favourable.

GBGCodingTools.demote turns an HONORED whose list is empty or names an unswept surface into LINE-ONLY. Passes.pass_open opens a verification pass (nonce, range, expected counts, the regenerated manuscripts, the verifiers' Workflow calls); Passes.grade validates the verdict files, applies the demotion and the four closure channels — honored, adjudicated, seeded and rescan — and writes the tally; Passes.close checks every closing condition of the instrument (GBGCodingTools binds the term) in order, carries into the next round every id still open once the pass budget is spent, or below it, on --carry, one the severity re-check rates minor or nit (the fifth channel, carried), and stamps the round closed.

GBGCodingTools.Seeds — Module
Seeds

Plants labelled defects into the consolidated manuscripts so a panel's recall is measurable. Seeds.select picks one occurrence per class with a per-round salt, Seeds.plant mutates the manuscripts, and the same select over the unseeded manuscript at bank is the ground truth.

source
GBGCodingTools.Seeds.select — Function
select(catalog, full, round) -> (seeded, skipped)

The seed plan for a round. The arguments are:

  • catalog — the consumer's seed catalogue (the seeds shape).
  • full — the FULL manuscript text.
  • round — the round id that salts the selection.

A class's anchor here is a third sense of the word: the regular expression whose match in the manuscript marks where the seed is planted. It is neither a file#heading reference, which is what Config.resolve_anchor resolves, nor a hat's full-strength flag, which is what Preflight.resolve_hats returns.

For every [[class]]: the occurrences of anchor in full; the chosen one is ((occurrence - 1 + salt_offset) mod count) + 1; a class whose anchor occurs nowhere is skipped and named. Returns the plan [{id, class, page, start, stop, original, replacement, original_context, mutated_context}] (byte positions into full) and the skipped classes.

source
GBGCodingTools.Seeds.plant — Function
plant(full, siteonly, plan) -> (full′, siteonly′)

The manuscripts with every planned seed applied. The arguments are:

  • full — the FULL manuscript text.
  • siteonly — the site-only manuscript text.
  • plan — the selection select returned.

In full the seeds are applied at the recorded positions (from the end, so positions stay valid); in siteonly each seed is located as the same occurrence of its original text within the same page (the site is a subset of the full manuscript page by page, so a seed on a withheld page is absent there by design, and a neighbouring seed already applied cannot hide it). Returns both.

GBGCodingTools.Recall.suspect_hats — Function
suspect_hats(findings, ground_truth, roster, site_pages; lane_files = nothing) -> Vector{String}

Every hat handed two or more seeds and reporting no seeded finding of its own. The arguments are:

  • findings — the banked findings after mark!.
  • ground_truth — the seed plan.
  • roster — the round's roster: the hats it resolved to run, each with its substrate.
  • site_pages — the page banners the site-only manuscript keeps; a siteonly hat sees only seeds on those pages, so an EMPTY set means a siteonly hat sees none and can never be SUSPECT, while a full hat is unaffected.
  • lane_files — a docs round's view: lane key → the files and directories that lane reads. Given, it replaces the substrate test.

A hat is judged only on the seeds it was actually handed, which follows the delivery. The panel splits the corpus once, siteonly against full: a siteonly hat sees only the seeds on a kept page, a full hat is handed the whole seeded manuscript and is judged on all of them.

A docs lane reads a file set, not a manuscript view, so a check-docs round passes lane_files: a lane sees a seed planted in one of its files or under one of its directories, and a lane naming no files — a cross lane, which reads the whole corpus — sees every seed. Before, a docs lane was judged on every seed in the round, including seeds in files it never opened. Returns the keys.

source
GBGCodingTools.demote — Function
demote(verdict) -> (verdict′, demoted::Bool)

The one demotion rule over an act verdict — the act verifier's grade of what the fix pass DID to one finding, from the diff (the state verifier grades, blind to the diff, whether the defect is still there; GBGCodingTools.Passes binds both verifiers and their verdict vocabularies). class_surfaces is the list the act verifier fills: every surface carrying the finding's class of defect, its own site included, each marked swept when the fix pass's diff fixed the class there.

An act verdict HONORED becomes LINE-ONLY when that list is empty, a fix graded honoured without the class enumerated being a line fix by construction, OR when any entry is swept: false — a verdict that says "the fix landed" while its own evidence says "and here is where the class still lives" is a line fix that has said so.

Emptiness alone fired 0 times in the 571 act verdicts of 2026-09-09-check-docs-02, which never handed in an empty list, while admitting 21 closures whose own list named an unswept surface — templates#3 five times, and that contradiction shipped. The design record weighed the two rules, content against emptiness; the data settled it. Every other verdict is returned unchanged. Returns the verdict and whether it moved.

GBGCodingTools.Git — Module
Git

Thin readers over a consumer's repository: Git.run returns a command's output or nothing, Git.head, Git.is_ancestor, Git.porcelain (modified and untracked paths), Git.diff, Git.log. Nothing here writes; git add is never called by the tool.

source
GBGCodingTools.Git.run — Function
Git.run(root, args...) -> Union{String,Nothing}

git -C root args... with stderr discarded; the stdout with TRAILING whitespace removed, or nothing on a non-zero exit or when git is absent.

Trailing only, never leading. git status --porcelain puts the status in the first two columns, so an unstaged modification begins with a SPACE (" M path"), and a full strip deleted it — from the first line alone, since only that line touches the start of the output. Git.porcelain then read the code as "M " and the path from column 4 as gbg/exemptions.toml, one character short, matching no watched path.

So CFG.TORN called a modified pinned file unmodified whenever that file sorted first, and sort order is what hid it: with any other file ahead of it the pinned one kept its space and the guard fired normally (2026-09-12-check-docs-01, work queue). --stat output is indented the same way and was losing its first line's alignment for the same reason.

  • hits — the surviving hits.
  • population — what the scan measured (files, docstrings, exports, arguments or pages); zero means the scan measured nothing and is DEAD, whatever the ledger removed.
  • exempted — the number of hits the ledger removed.
  • note — a scan-level message: an error, a reason a lane is dead (a lane being one agent's share of a round, bound in GBGCodingTools), empty otherwise.

register_scan!(id, f)

Registers f as the scan id. The contract: f(cfg, files) receives the validated config and the surface files (relative paths) the catalogue resolves for the scan, and returns (hits::Vector{Hit}, population::Int), or (hits, population, note::AbstractString) when the scan owes the reader something about the measurement itself, which a DEAD line then carries. An HTML scan receives the built pages instead of source files. Returns f.

GBGCodingTools.TreeHash — Module
TreeHash

Git's content hashing, reimplemented on the SHA stdlib so the running copy can re-hash itself without git: TreeHash.blob_hash and TreeHash.tree_hash reproduce the object ids git hash-object and git write-tree would give, which is what Pkg records as git-tree-sha1 in a manifest and reports as tree_hash from Pkg.dependencies(). gbg self verify compares the two.

GBGCodingTools.TreeHash.tree_hash — Function
tree_hash(dir; skip = (".git",)) -> String

The git tree id of a directory, computed as git write-tree would over every file below it: entries sorted by git's rule (a directory name compares with a trailing /), modes 100644, 100755, 120000 and 40000, empty directories omitted. The arguments are:

  • dir — the directory to hash.
  • skip — entry names ignored at any level, .git by default, so a working tree hashes the same as the tree its HEAD names when it is clean.

Returns the hex id; an empty tree returns git's well-known empty-tree id.

source
GBGCodingTools.TreeHash.blob_hash — Function
blob_hash(path) -> String

The git blob id of the file at path: SHA-1 over "blob <size>\0" followed by the content (a symlink hashes its target path, as git does). Returns the 40-character lowercase hex id.
