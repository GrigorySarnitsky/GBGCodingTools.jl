The wrapper and the dispatcher

GBGCodingTools.makedocs — Function
makedocs(cfg; kwargs...)

The mandatory docs-build wrapper a consumer's docs/make.jl calls instead of Documenter.makedocs. The body is defined by the Documenter extension (ext/GBGCodingToolsDocumenterExt.jl), which Julia loads once Documenter is in the environment — a consumer's make.jl already does using Documenter.

The arguments are:

  • cfg — the package ROOT, for a package wired by gbg init; or, for one still carrying the old .gbg/config.toml, the dictionary Config.read returns.
  • kwargs... — passed through to Documenter.makedocs unchanged (sitename, pages, modules, checkdocs, doctest, format, …).

Before Documenter runs it runs, in-process, the documentation rules of the rulebook and the wiring check; after Documenter it runs the rules that read the built site. Any non-zero return is an error, so the build fails. It prints one banner line, GBGCodingTools v<ver> makedocs, which a consumer's CI greps for.

A build reads no review state and nothing can freeze it: the closure gate that used to refuse a build while a round was open went with the round machinery on 2026-09-17, because a check that runs inside a consumer's build must give the same answer on a fresh clone and on CI.

Returns what Documenter.makedocs returns, true when that is nothing — as it is unless debug = true is passed.

GBGCodingTools.VERBS — Constant
VERBS

The closed verb table of the command line: "<noun> <verb>" (or a lone "<noun>") to the function that runs it. Every entry takes the remaining arguments as a Vector{String} and returns the exit code as an Int. Each src/CLI/*.jl file registers its own verbs at load; nothing else adds to the table, and a verb that is not in it does not exist.

Engines

GBGCodingTools.Wire — Module
Wire

The two verbs that write a package's wiring, gbg init and gbg sync. The first puts a package under this one; the second brings an already-wired package up to what the running copy generates.

One module, because they are one act at two moments. The first writes the config a package could not have written itself and then calls the second; everything after that is the second alone, and there is no third path by which a generated file comes into being.

Neither merges. A generated file is the return value of a function, so there is nothing to merge WITH: sync writes what the function returns, and a hand edit is lost. That is the bargain the wiring check states out loud — it reports drift on every build so that nothing is lost silently.

GBGCodingTools.Ledger — Module
Ledger

The reader of a consumer's exemption ledger .gbg/exemptions.toml: Ledger.read validates the file against schema/exemptions.schema.json and returns its entries, Ledger.entries selects the ones naming an id, and Ledger.matches applies an entry's optional match table to a trigger. The doctor's CFG.EXEMPTIONS check applies the ledger's semantic rules (expiry bounds, the non-exemptable prefixes); the reader only parses.

source
GBGCodingTools.Ledger.read — Function
Ledger.read(cfg) -> Vector{Dict{String,Any}}

Every [[exemption]] of <root>/.gbg/exemptions.toml, schema-validated. Returns an empty vector when the file is absent (an empty ledger is a legal state) and throws a LedgerError when it does not parse or does not validate — an unreadable ledger is never treated as empty.

source
GBGCodingTools.Ledger.entries — Function
Ledger.entries(ledger, id; scope = nothing, live = true) -> Vector

The entries naming an id. The arguments are:

  • ledger — the entries Ledger.read returned.
  • id — the id to select.
  • scope — one scope to restrict to (any when nothing).
  • live — whether to drop an entry past its expires date (it no longer exempts anything, and the doctor reports it).

Returns the selection in file order.

source
GBGCodingTools.Ledger.matches — Function
Ledger.matches(entry, root; file = "", symbol = "",
               arg_name = nothing, arg_type = nothing) -> Bool

Whether entry covers a trigger. The arguments are:

  • entry — the ledger entry.
  • root — the consumer root; globs in target and match.path resolve against the file's relative path, so root only names the tree.
  • file — the trigger's file, relative to the root.
  • symbol — the trigger's owning binding.
  • arg_name — the argument name, for a reflection scan's trigger.
  • arg_type — the argument's declared type, for a reflection scan's trigger; a text scan passes nothing and refuses an entry carrying match.arg_type before calling — this function throws on it.

The entry covers the trigger when its target is *, equals file or symbol, or is a glob matching file; and, when it carries a match table, every present sub-key holds (path a glob over file, symbol a regex over symbol, arg_name a regex, arg_type a type name tested by <:). Returns the boolean.

GBGCodingTools.Git — Module
Git

Thin readers over a consumer's repository: Git.run returns a command's output or nothing, Git.head, Git.is_ancestor, Git.porcelain (modified and untracked paths), Git.diff, Git.log. Nothing here writes; git add is never called by the tool.

source
GBGCodingTools.Git.run — Function
Git.run(root, args...) -> Union{String,Nothing}

git -C root args... with stderr discarded; the stdout with TRAILING whitespace removed, or nothing on a non-zero exit or when git is absent.

Trailing only, never leading. git status --porcelain puts the status in the first two columns, so an unstaged modification begins with a SPACE (" M path"), and a full strip deleted it — from the first line alone, since only that line touches the start of the output. Git.porcelain then read the code as "M " and the path from column 4 as gbg/exemptions.toml, one character short, matching no watched path.

So CFG.TORN called a modified pinned file unmodified whenever that file sorted first, and sort order is what hid it: with any other file ahead of it the pinned one kept its space and the guard fired normally (2026-09-12-check-docs-01, work queue). --stat output is indented the same way and was losing its first line's alignment for the same reason.

GBGCodingTools.Git.is_ancestor — Function
Git.is_ancestor(root, a, b) -> Bool

Whether one commit is an ancestor of (or equal to) another (git merge-base --is-ancestor). The arguments are:

  • root — the repository the two commits are read in.
  • a — the commit tested as the ancestor.
  • b — the commit tested as the descendant; a equal to b counts as an ancestor.

Returns the boolean; false outside a repository.

source
GBGCodingTools.Git.porcelain — Function
Git.porcelain(root; untracked = true) -> Vector{Tuple{String,String}}

git status --porcelain seen from a consumer, as (status, path) pairs with paths relative to the consumer root. The arguments are:

  • root — the consumer root the status is read from and the paths are made relative to.
  • untracked — with untracked = false untracked files are left out.

Porcelain paths are relative to the repository top, so for a consumer nested inside a larger repository (the fixture inside the tool's) they are translated and paths outside the consumer are dropped — the tool's own modified files are not the fixture's. Empty outside a repository.

source
GBGCodingTools.Git.diff — Function
Git.diff(root, range, paths) -> String

The diff of a commit range restricted to a set of paths. The arguments are:

  • root — the repository the diff is taken in.
  • range — the commit range, <base>..<head>.
  • paths — the paths the diff is restricted to.

Returns the patch text, empty outside a repository.

GBGCodingTools.HtmlWalker — Module
HtmlWalker

The one HTML reader of the tool: Gumbo parses a built page (HtmlWalker.parse_page), and these helpers walk it — the article element Documenter renders into (HtmlWalker.article_of), the text of a node (HtmlWalker.text_of), the elements matching a predicate (HtmlWalker.elements), and a node's tag, classes and attributes (HtmlWalker.tagname, HtmlWalker.classes, HtmlWalker.attr). Both the consolidator and the built-HTML scans go through here, so the rendered site is read one way.

source
GBGCodingTools.HtmlWalker.parse_page — Function
parse_page(path) -> HTMLDocument

Parses the HTML file at path with Gumbo, keeping whitespace-only text nodes (Gumbo.jl drops them by default, and a dropped space between two inline elements changes the reader text — the 1.6 byte comparison against the Python consolidator is what caught it). Returns the document; its root is doc.root.

GBGCodingTools.HtmlWalker.attr — Function
attr(el, name, default = "") -> String

The named attribute of a node, or a fallback. The arguments are:

  • el — the node; anything that is not an HTMLElement (a text node) carries no attributes and always takes default.

GBGCodingTools.Hit — Type
Hit(file, line, text; symbol = "")

One scan hit. The fields are:

  • file — the surface file, relative to the consumer root.
  • line — the 1-based line, or 0 when the hit is about the whole file.
  • text — the excerpt or message a reader needs.
  • symbol — the owning binding when the scan knows it (what a ledger entry's symbol predicate is matched against); empty otherwise.

The arguments of the constructor are the fields, symbol as a keyword.

source
GBGCodingTools.ScanResult — Type
ScanResult

The outcome of one scan. The fields are:

  • id — the scan id.
  • rule — the rule it enforces.
  • tier — hard or triage, the argcov_policy tier resolved from config.
  • hits — the surviving hits.
  • population — what the scan measured (files, docstrings, exports, arguments or pages); zero means the scan measured nothing and is DEAD, whatever the ledger removed.
  • exempted — the number of hits the ledger removed.
  • note — a scan-level message: an error, a reason a lane is dead (a lane being one agent's share of a round, bound in GBGCodingTools), empty otherwise.
source
GBGCodingTools.register_scan! — Function
register_scan!(id, f)

Registers f as the scan id. The contract: f(cfg, files) receives the validated config and the surface files (relative paths) the catalogue resolves for the scan, and returns (hits::Vector{Hit}, population::Int), or (hits, population, note::AbstractString) when the scan owes the reader something about the measurement itself, which a DEAD line then carries. An HTML scan receives the built pages instead of source files. Returns f.

source
GBGCodingTools.prose_lines — Function
prose_lines(cfg, file) -> Vector{ProseLine}

The rendered-prose lines of one surface file: a Markdown file outside its fenced blocks; a Julia file only inside """ docstrings (a one-line """…""" docstring is one prose line); a Literate file's full-line # comments with the marker stripped, outside fences. Fence lines themselves are not returned. Returns the lines; an empty vector for a file with no prose.

source
GBGCodingTools.TreeHash — Module
TreeHash

Git's content hashing, reimplemented on the SHA stdlib so the running copy can re-hash itself without git: TreeHash.blob_hash and TreeHash.tree_hash reproduce the object ids git hash-object and git write-tree would give, which is what Pkg records as git-tree-sha1 in a manifest and reports as tree_hash from Pkg.dependencies(). gbg self verify compares the two.

source
GBGCodingTools.TreeHash.tree_hash — Function
tree_hash(dir; skip = (".git",)) -> String

The git tree id of a directory, computed as git write-tree would over every file below it: entries sorted by git's rule (a directory name compares with a trailing /), modes 100644, 100755, 120000 and 40000, empty directories omitted. The arguments are:

  • dir — the directory to hash.
  • skip — entry names ignored at any level, .git by default, so a working tree hashes the same as the tree its HEAD names when it is clean.

Returns the hex id; an empty tree returns git's well-known empty-tree id.

source
GBGCodingTools.TreeHash.blob_hash — Function
blob_hash(path) -> String

The git blob id of the file at path: SHA-1 over "blob <size>\0" followed by the content (a symlink hashes its target path, as git does). Returns the 40-character lowercase hex id.
