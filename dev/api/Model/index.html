The types.

GBGCodingTools.Model — Module
Model

Every type the rebuilt package is written in, and nothing else: the enums, the structs and the abstract types of, with no behaviour and no values attached. It is the bottom module of the order — Model → Texts → Catalogue → ConfigIO → Engine → Render → Orchestration → CLI — so every later module may name these types and none of them may reach upwards.

The enums are scoped, one module each (Decider.PROGRAM, Verdict.FIXED), so values of different enums never share a name and a misplaced one is a method error rather than a silent equality.

  • Location and FindingDraft, Finding — where a defect is, and what is reported about it.
  • Rule with ProgramCheck, AgentCheck, Example and Parameter — the rulebook as values.
  • AgentRole, Instrument, AlwaysOn, Budget — who reads, what starts, and what a run may spend.
  • Question with Option and Item — the one form for asking the owner.
  • Config, Switch, Deferral, Setting, PatternRule, Settled — a package's own settings and the rulings it has already given.
  • DocFix, CodeFix, Run, Generated — what a run did and what writes each generated file.

GBGCodingTools.Model.AgentRole — Type
AgentRole

One kind of agent an instrument launches: what it reads, what it is kept from, and which rules it checks.

Fields

  • id — its stable identifier.
  • instrument — the instrument that launches it.
  • reads — the file sets it is given.
  • site — whether it reads the built site rather than the source.
  • kept_from_code — whether the code is withheld from it.
  • description — who the reader is, in two or three sentences.
  • rules — the rules it checks; empty makes it an open reader, looking for what no rule names yet.
  • strength — which model it runs on.
  • cap — how many distinct defects it may report, the agent saying how many it left out.

GBGCodingTools.Model.AlwaysOn — Type
AlwaysOn

A program check that every build and test runs; nobody starts it and it has no runs.

Fields

  • id — its stable identifier.
  • purpose — what it is for.
  • intention — whether its defects are in documentation or in code.
  • fixer — who fixes what it found.
  • decider — what decides that a finding is real, a program by definition.
  • when — which builds or tests run it.

GBGCodingTools.Model.Budget — Type
Budget

The one ceiling on a run: how many fix passes it may make.

There is no ceiling on agent launches, as ruled 2026-09-21: the design bounds them — a panel over the units per stage, one relaunch each, one verifier per unit holding open findings — and a run interrupted before its end is continued, not capped. One pass by default [ruled 2026-09-26: a second pass re-verified unchanged text and moved a fifth of the verdicts by variance].

Fields

  • fix_passes — how many times the open findings may go back to the fixer.

GBGCodingTools.Model.Check — Type
Check

What decides whether a rule is broken: a program, or an agent for one of the three reasons a program cannot. The two concrete types are ProgramCheck and AgentCheck.

GBGCodingTools.Model.CodeFix — Type
CodeFix

One approved code fix and the single audit of it, kept with the question that approved it.

Fields

  • question — the question whose answer approved it.
  • direction — how the owner asked for it to be fixed, where he said.
  • attempts — how many attempts it took.
  • commits — the commits it landed in.
  • touched_tests — whether it changed anything under test/, which the audit is told first.
  • audit — the one audit run over it.
  • proportionate — whether the change was no wider than the defect and the direction.
  • contract_kept — whether it left every documented contract and default alone.
  • old_input_works — whether input that worked before still works.
  • concerns — what the audit raised.
  • note — the audit's sentence to the owner.

GBGCodingTools.Model.Config — Type
Config

A package's settings, written by hand in .gbg/config.jl and read by a parser that evaluates nothing.

Fields

  • package — its name.

  • tool — the version of this package it pins, or :dev here.

  • docs_build — what builds its documentation.

  • test — what runs its tests.

  • rules — its own pattern rules.

  • filesets — file sets, where defaults miss.

  • normative — the documents that bind it.

  • copies — each build-time copy and its tracked source.

  • generated — pages a build writes, which no rule reads.

  • switches — what is off here, with reasons.

  • deferrals — what is owed and not yet met, with what closes it.

  • settings — its values for rule parameters.

  • code_areas — its code in named areas, one hunter each.

  • disciplines — the catalogued disciplines its documentation needs read by.

  • material — documents a reader may consult and never report on: the rationale documents beyond the one architecture_doc names.

  • claude_documentation — the headings of its CLAUDE.md sections that are documentation.

  • exclusions — files no rule reads, with the reason.

  • leak_emails — the email addresses the owner approves for publication.

  • leak_terms — words never published, as the machines' names.

GBGCodingTools.Model.DocFix — Type
DocFix

One documentation-fixer attempt at one finding, with the program and agent judgements of it.

Fields

  • finding — the finding it fixed.
  • pass — which fix pass made it.
  • commit — the commit it landed in.
  • formula_edit — whether it changed mathematics, which needs agreement and a numeric check.
  • blind — the verifier's verdict (one verifier sees the text and the diff since 2026-09-26).
  • with_diff — a second verifier's verdict, in records from before that; nothing since.
  • agreeing_code — the code the fixer quoted as agreeing with the new text.
  • note — what the program did to the verdict, if anything: demoted for a quote not in the text, or no verifier answered.

GBGCodingTools.Model.FindingDraft — Type
FindingDraft

What an agent or a check reports, before a run gives it an id.

Fields

  • rule — the rule it breaks, or nothing where no rule names it yet.
  • locations — every site, each with its own quote.
  • claim — what is wrong, in one sentence.
  • evidence — a failing test's path, or the reason to believe the claim.
  • fix — what would put it right.
  • maybe_code — the agent believes the code, not the text, is wrong.
  • in_material — every location is in material a reader was given to consult, not in a target of the review; such a finding goes to the owner and never to the fixer.

Instrument

  • intention — documentation or code.

  • fixer — who fixes what it found.
  • when — when it runs.
  • ends — when a run ends.
  • budget — what a run may spend.
  • built — false while its row is future: no skill, no run.

GBGCodingTools.Model.Location — Type
Location

Where a finding is, held still while the text around it moves: the node and the quote survive edits above them, and the line is only a hint.

A line found again on a later pass is a line of that later tree; mapped from the run's first commit, it was moved a second time.

Fields

  • file — the path, relative to the package root.
  • node — for a .jl file the binding, method or field of a constant documented (ARGS_FORM.statement); for Markdown the heading path; empty where the file has neither.
  • text — the quote: the decisive text as it read when the finding was made.
  • line — the line it was on then, kept as a hint and never taken from an agent.
  • found — how it was anchored the last time it was looked for.
  • at — the commit line was read at, empty for the commit the run began at.

GBGCodingTools.Model.Question — Type
Question

A decision put to the owner: plain data, checked against the language rules only when it is put.

Fields

  • id — its identifier, stable once written.
  • decision — the decision itself, one sentence ending in a question mark.
  • context — what he needs to know to answer, without jargon.
  • options — the answers he may give.
  • items — the separate decisions the options apply to, empty for a single question.

GBGCodingTools.Model.Rule — Type
Rule

One rule of the rulebook, carrying its own statement, the check that decides a violation, and the examples that show the check matches the statement.

A rule with an access tag is a READER'S rule: the readers of a documentation review are derived from these tags rather than listed. A rule naming a discipline goes to that discipline's reader where the package declares it, and to nobody — said in the report — where it does not.

A file set is shared and some rules are not, which is what files_parameter answers. Which pages must carry the provenance banner differs per package and has nothing to do with which pages are rationale.

Expressed as a file set, widening one rule's reach drags every other rule reading that set along with it. A rule naming a parameter lets a package say which files it means and leave the sets alone.

Fields

  • id — its stable identifier.

  • statement — the rule in plain English; this is its only home.

  • why — what goes wrong without it.

  • intention — whether its defects are in documentation or in code.

  • filesets — the file sets it runs over.

  • files_parameter — a parameter of globs a package may set to name this rule's files in place of filesets, or nothing.

  • check — what decides a violation, or nothing where nothing does.

  • unchecked_reason — why it has no check, required when it has none.

  • hook — the shell lines the end-of-turn hook runs for a rule that reads the history, printing one line per violation; empty for every other rule. The check and the hook are one program.

  • parameters — the values a package may set.

  • examples — texts, trees, sources, pages or questions the check must judge a known way.

  • access — what a reader must be given beyond the unit; empty where a program decides it or a session keeps it as a habit.

  • discipline — the catalogued discipline deciding it takes, or nothing: any careful reader.

GBGCodingTools.Model.Run — Type
Run

One execution of one instrument on one package, stored beside its report.

The count dropped is what keeps an abandoned record honest. Stopping a run removes its open findings from the list — what a verdict had closed stays — and leaves its launch count alone, and those two read together say that every reader wrote its file and none of them found anything — of a run that found a hundred. What was thrown away is part of what happened, and belongs where the run is written down rather than only in a line nobody keeps.

A bound reader carries rules; an open one carries a standpoint and no rule. Bound is the default, and runs most often.

Fields

  • id — its identifier, which names its directory.

  • instrument — the instrument that ran.

  • tool_version — the version of this package that ran it.

  • first_commit — the commit the package was at when it started.

  • budget — what it was allowed to spend.

  • stage — the stage it is at.

  • findings — what it found.

  • fixes — the documentation fixes it made.

  • questions — what it asked the owner.

  • code_fixes — the code fixes its questions were answered with, added as they land.

  • agent_launches — how many agents it launched.

  • tokens — what they cost, where the platform reports it.

  • stop — why it ended.

  • readers — which readers it launches: :bound, :open or :both.

  • passes — how many fix passes it has begun; the cap is budget.fix_passes.

  • model — the careful model its readers ran on, or "session" where they ran on whatever model the session itself was on, which is the default and the only honest answer when nobody named one.

  • sequential — whether its agents were launched one at a time rather than together.

  • scope, base, driver — :changed read what moved since base; the SHA-256 of the driver used.

  • already_failing — the rules already violated when it opened, so a fix is held to what it broke.

  • dropped — how many findings the owner's stop threw away, 0 for every other run.

  • unreverted — the fix commits a verdict said to revert and git could not, because a later fix conflicts; each leaves a rejected edit in the tree, and the run cannot end as evaluated.

  • silent — the agents that wrote nothing, or nothing readable, after being launched again once; the report names each, and none is read as a clean result.

  • rulebook — the digest of the rules it judged by, which a later --scope changed run compares with its own: a version number does not move when a development checkout's rules do.

  • pass_since — the commit the current fix pass began at; its fixes are the commits after it.

  • dropped_ids — what the owner's stop threw away, kept in findings with its text [ruled 2026-09-26] and carried nowhere.

  • usage — what each stage's agents cost, per stage and pass, as gbg run cost recorded it.

GBGCodingTools.Model.Deferral — Type
Deferral

Says that one rule is owed here and not yet met: a question with a condition on it, where a switch is an answer. A deferred rule reports nothing in a build or a test — a deferral never fails a build — and is listed beside the switches on the package's own site and by gbg check, so "not yet" is on the record as owed rather than filed as "does not apply".

Fields

  • rule — the rule deferred.
  • until — what would close it: the condition on which the package means to meet the rule.
source
GBGCodingTools.Model.TextExample — Type
TextExample

One text, judged by a check that reads a source text.

A rule whose behaviour is a package's to supply cannot otherwise be shown to work, which is what settings answers. A parameter empty by default makes its check silent by default, so every example of it complies and the rule carries no demonstration that it ever fires.

Fields

  • fileset — the file set the text stands for.
  • text — the text itself.
  • expect — the locations the check must report, empty when the text complies.
  • clause — the clause of the rule's statement this example is for.
  • settings — the package settings the example is judged under, empty for the rule's own defaults.
source
