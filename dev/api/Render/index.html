GBGCodingTools.Render — Module
Render

Every file that connects a package to this one, written by a Julia function. There is no template language and no template directory: a generated file is the return value of a function that takes the package's config, so what a package receives is decided in Julia, beside the values it is derived from, and can be compared with what is on disk by running the function again.

That comparison is the WIRING CHECK, which every build and every test runs: a generated file that has been hand-edited, or that a newer version of this package would write differently, is a finding rather than a silent divergence. Regenerating is left to gbg sync, gbg bump and gbg release, so a build reports drift and never repairs it.

This is the sixth module of the order: it may name Model, Texts, Catalogue and ConfigIO, and nothing above. What it writes today is the WIRING — the ignore block, the end-of-turn hook, the settings that install it, the regressions note — and the RULEBOOK a session loads, rendered from the rule values themselves, so a rule cannot be reworded in the text without being reworded in the program that enforces it. The instrument skills wait for the instruments.

GENERATED

Every path this module writes in a package, with how much of it is written. A path is here only when a generator writes it today: the instrument skills wait for the instruments and are not in the register, so the wiring check does not claim to hold them.

GBGCodingTools.Render.POLICY_FILES — Constant
POLICY_FILES

One rendered rulebook file per family of rule ids, with the families it carries and the sentence that opens it. RULE.API.* shares a file with RULE.DOC.*: an API page and a docstring are one subject, and splitting them would put the two halves of "one concept, one home" in two files.

GBGCodingTools.Render.SUBENVS — Constant
SUBENVS

The sub-environments of a package that must see this one: the documentation build and the test suite. Both run this package's checks, so both name it, and a package whose two environments disagree about which version to use gets two different answers from the same commit.

GBGCodingTools.Render.claude_block — Function
claude_block(cfg) -> String

The block this package owns at the top of a package's CLAUDE.md: the import of the rulebook, and the four standing instructions a session needs before it has read anything. The argument is cfg, the package's config. Returns the block, marked at both ends so the rest of the file is the package's own.

It imports and does not restate. A block that listed the rules, or what this package has switched off, would be a second copy of the rulebook in the one file every session reads first — and the copy that is read is the copy that drifts.

GBGCodingTools.Render.hook — Function
hook(cfg) -> String

The end-of-turn hook: the script that refuses to let a session stop while an item of its work queue is open. The argument is cfg, the package's config. Returns the script.

Two things in it are load-bearing. The loop guard — a hook that blocks again while already holding the session open would trap it with no way out — and the rule that an item is closed only when it is done, since an item closed to end the turn is the defect the hook exists to prevent. A run's own leftovers go under a heading this hook does not count, so a review never puts a session to work on something the owner has not asked about.

GBGCodingTools.Render.pin_drift — Function
pin_drift(cfg, root, envdir) -> Union{String,Nothing}

What one sub-environment's Project.toml gets wrong about this package, or nothing where it gets it right. The arguments are:

  • cfg — the package's config, which carries the pin.
  • root — the package root.
  • envdir — the sub-environment.

Returns the first disagreement, in words.

Only this package's own entries are compared, as parsed values: Pkg rewrites these files whenever it resolves, so comparing the text would report every ordinary Pkg.add as drift.

GBGCodingTools.Render.pin_entries — Function
pin_entries(cfg, root, envdir) -> Dict{String,Any}

What one sub-environment's Project.toml must say about this package: the dependency, and either the released version with its compat bound or the path to the checkout. The arguments are:

  • cfg — the package's config, which carries the pin.
  • root — the package root.
  • envdir — the sub-environment, "docs" or "test".

Returns the entries, keyed by the TOML table each belongs in; a table whose value is nothing must be absent, which is how a checkout is distinguished from a release rather than merely left unstated.

A checkout is named by a relative path where this package's repository encloses the consumer, or is it, and absolutely otherwise: a chain of ../ out of one repository and into another breaks the moment either moves.

A PRERELEASE pin names the full tag as its rev and its BASE version in compat. The two differ because Pkg refuses a prerelease in a version specifier outright — semver_spec("=2.0.0-rc.1") throws invalid version specifier — while release already refuses to tag vX.Y.Z-rc.N unless Project.toml says X.Y.Z, so the base is what a consumer resolving that tag actually reads. The tag is what pins; compat is the guard that the tree behind it is the version it claims to be.

GBGCodingTools.Render.rule_section — Function
rule_section(rule) -> String

One rule as the rendered rulebook shows it: its heading, its statement, why it exists, what decides a violation, and the values a package may set. The argument is rule, the rule. Returns the section.

No example is shown. A rulebook page carrying an example of a rule being broken is by construction full of text that breaks the rules it states, which a reader spends its budget reporting and no fixer may touch; the examples live in the rule value, where test/rules.jl runs them.

GBGCodingTools.Render.runtests_call — Function
runtests_call() -> String

The line a package's test/runtests.jl ends with: the harness, handed the wiring check. The harness sits below the generators in the module order and so cannot reach that check itself; a consumer gets both by being given both, in one line it can read. Returns the line.

It is dirname(@__DIR__), not @__DIR__ |> dirname: a macro call takes the rest of the line as its arguments, so the second spelling is a parse error. This line is copied into consumers verbatim, and it was wrong in both places that already held it.

HOOK_COMMAND

GBGCodingTools.Render.settings_drift — Function
settings_drift(root) -> Union{String,Nothing}

What .claude/settings.json gets wrong about the end-of-turn hook in the package at root, or nothing where it installs it. The argument is root, the package root. Returns the fault, in words.

Only this package's own Stop hook is looked for. The file is the PACKAGE's — it may hold its own hooks, its own permissions and its own settings — so a whole-file comparison would report every one of them as drift, and writing the file whole would delete them.

GBGCodingTools.Render.write_settings — Function
write_settings(root) -> Bool

Adds this package's Stop hook to .claude/settings.json in the package at root, keeping every other hook and setting the file holds. The argument is root, the package root. Returns whether it changed.

The entry is added to the Stop list rather than replacing it: a package that has its own stop hook keeps it and gets this one as well.

GBGCodingTools.Render.switches — Function
switches(cfg) -> String

What this package has switched off, and why: one entry per Switch in its config, and a rule a package adds for itself listed after them. The argument is cfg, the package's config. Returns the file.

A switch is read as part of the rulebook: a session that has loaded the rules has loaded what this package does not hold itself to, which is the only way a rule can be escaped.

GBGCodingTools.Render.wiring — Function
wiring(cfg, root) -> Vector{Model.Location}

Every generated path of the package at root that is not what its generator writes now, and each sub-environment whose pin disagrees with the config: one location per path, quoting the first line that differs. The arguments are cfg, the package's config, and root, the package root. A path that does not exist at all is reported the same way, since a package missing a generated file is as wired-wrongly as one holding a stale copy. Returns the locations.

write_all(cfg, root) -> Vector{String}

Writes every generated path of the package at root, sets the pin in each sub-environment, and returns the paths it changed. The arguments are cfg, the package's config, and root, the package root. A marked block is replaced inside the file that holds it and the rest of that file is left alone; anything else is written whole.
