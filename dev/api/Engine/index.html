What runs the rules.

GBGCodingTools.Engine.Checks — Module
Checks

Running the rulebook over a package: which files each file set names here, which rules apply here, and what their program checks report.

Everything in this module runs inside a consumer's docs build and test suite, so it is offline, starts no child process and reads no review state: a check must give the same answer on a fresh clone and on CI. A rule whose check reaches the network is skipped unless it is asked for by name.

GBGCodingTools.Engine.Checks.applies — Function
applies(cfg, id; file = "") -> Bool

Whether the rule, agent role or instrument with that id is on in this package: a Model.Switch naming it turns it off, and one naming files turns it off for those files alone. The arguments are:

  • cfg — the package's config.
  • id — what is being asked about.
  • file — the file it would run over, empty to ask about the package.

Returns whether it applies.

GBGCodingTools.Engine.Checks.not_run — Function
not_run(cfg; pkg = nothing, site = nothing, network = false) -> Vector{Symbol}

The rules a run could not reach, and why it could not: those that read the loaded package where nothing loaded it, those that read the built site where none was built, and those that reach the network where that was not allowed. The arguments are:

  • cfg — the package's config.
  • pkg — the loaded package, or nothing.
  • site — the built site's directory, or nothing.
  • network — whether a check that reaches the network was allowed.

Returns the rule ids, so a caller can say what it did not check rather than reporting clean.

GBGCodingTools.Engine.Checks.run_all — Function
run_all(cfg, root; intention = nothing, network = false)
    -> Vector{Tuple{Symbol,Model.Location}}

Everywhere any rule of the rulebook is broken in the package at root, for the rules of one intention — the documentation rules in a docs build, the code rules in a test suite — or for every rule when intention is nothing. The arguments are:

  • cfg — the package's config, which says which rules are off here and where its files are.
  • root — the package root.
  • intention — the intention to run, or nothing for every rule.
  • network — whether a check that reaches the network may run; false inside every build and test.

Returns the locations, in file and line order.

GBGCodingTools.Engine.Checks.run_rule — Function
run_rule(rule, cfg, root; network = false) -> Vector{Model.Location}

Everywhere the rule is broken in the package at root. The arguments are:

  • rule — the rule to run.
  • cfg — the package's config.
  • root — the package root.
  • network — whether a check that reaches the network may run; false inside every build and test, so a run gives the same answer offline.

A rule an agent decides, or one with no check at all, reports nothing here: this is the program half. Returns the locations, in file and line order.

GBGCodingTools.Engine.Guard — Module
Guard

The change guard: the program that decides whether one changed file is a DOCUMENTATION change, which the documentation fixer may commit on its own, or a CODE change, which waits for the owner . It is the gate the whole automatic half rests on, so it answers CODE whenever it is unsure.

Documentation is exactly: docstrings and comments in .jl files under src/ and ext/; hand-written Markdown under docs/src/; the package's README.md; and the rationale documents the config names. Everything else is code — other .jl files whole, the config, stored data, generated files, CI and hook files, CLAUDE.md, and any document the config declares normative.

For a .jl file that is on the documentation list, being on it is not enough: both versions must parse, and with the docstrings and the standalone string literals removed, THE CODE MUST BE IDENTICAL. A docstring whose target is a call rather than a definition is not documentation at all — Julia then documents the call instead of running it — and neither is one built by interpolation.

Clause 0, a generated file equal to its generator's output, needs the generators, and the caller passes their output in rather than this module reaching for them, since Engine may not name Render. Clause 3 — in GBGCodingTools only, a change confined to the plain string literals given to statement or why of a Rule(…) call is documentation — is decided by comparing the two versions' shapes with those literals elided; any other difference, a moved argument, a changed check or tag or an interpolated statement among them, is code.

GBGCodingTools.Engine.Guard.Ruling — Type
Ruling

What the guard decided about one changed file, and why. The fields are:

  • path — the file it is about.
  • documentation — whether the change may be committed by the documentation fixer.
  • reason — the clause that decided it, in one line a person can act on.

GBGCodingTools.Engine.Guard.classify — Function
classify(cfg, path, before, after; generated = nothing) -> Ruling

What one changed file is: documentation, which the documentation fixer may commit, or code, which waits for the owner. The arguments are:

  • cfg — the package's config, which names the rationale documents, the declared copies and the normative documents.
  • path — the file's path relative to the package root.
  • before and after — its content on each side of the change; nothing for a file that was added or removed, which is always code.
  • generated — what this path's generator produces now, for clause 0; nothing where no generator writes it. Passed in by the caller, because the generators live above this module.

Returns the Ruling, whose reason names the clause that decided it.

source
GBGCodingTools.Engine.Guard.code_shape — Function
code_shape(src) -> Union{String,Nothing}

The Julia source with everything that is documentation taken out of it: docstrings whose text is a plain literal and whose target is a definition, and string literals standing alone at top level or in a struct body. What is left is written out in a canonical form that holds no line numbers, so two versions differing only in their prose have the same shape and any other difference shows.

A docstring whose target is a CALL, or a macro call that does not define anything, is left in: Julia then documents the call instead of running it, so removing it would hide a change in what the file does. So is one built by interpolation, whose text is a program. A docstring on a bare NAME comes out — that is how a whole generic is documented where its methods are written one per backend — because what is left is the name alone, which runs nothing.

The arguments are src, the file's content, and rule_prose, whether the plain string literals given to statement or why inside a Rule(…) call are elided too (clause 3). Returns the shape, or nothing when the source does not parse.

GBGCodingTools.Engine.Guard.fenced_kept — Function
fenced_kept(before, after) -> Bool

Whether every fenced block that is RUN rather than read is identical in both versions, in the same order and with the same info string: a doctest (`jldoctest) and every Documenter block whose info string starts with @ (@example, @eval, @setup, @meta, @raw, @docs, @autodocs, @index, @contents). Their content is executed or collected at build time, so an edit to one is a code change however much it looks like prose.

The arguments are the two versions. Returns whether they all survived unchanged.

source
GBGCodingTools.Engine.Guard.literate_changed — Function
literate_changed(before, after) -> Bool

Whether any comment carrying a Literate mark — #src, #md, #jl, #nb — differs between the two versions. Those marks decide which lines of a script are executed, rendered or dropped, so a change to one changes what runs. The arguments are the two versions. Returns whether such a comment moved.

GBGCodingTools.Engine.Guard.on_documentation_list — Function
on_documentation_list(cfg, path) -> Bool

Whether the path is one where documentation can live at all: a .jl file under src/ or ext/, hand-written Markdown under docs/src/, the package's README.md, or a rationale document the config names. A document the config declares normative is never on the list, whatever else it looks like — a fix that aligned a specification with the code would be authorising that code.

The arguments are cfg, the package's config, and path, the file's path relative to the package root. Returns whether documentation may live there.

GBGCodingTools.Engine.Harness — Module
Harness

What a package's test/runtests.jl calls: the code half of the always-on checks, run inside the suite so that a broken contract is a failing test rather than a report nobody reads.

It runs only programs — the code rules of the rulebook, and the frozen contracts a package pins — and reads no review state, starts no child process and never touches the network, because CI and a fresh clone must give the same answer.

It does NOT reach the wiring check, though a test suite runs that too. Render is above Engine in the order and the harness reaches no further than its own layer, so the wiring check is handed IN, by whoever calls this. That is what checks is for, and it is how a consumer's suite gets both without this module knowing what a generator is.

The contract engines still live in TestHarness, the module of the tree being replaced; a package passes its own contract runner as contracts until those are harvested.

GBGCodingTools.Engine.Harness.test — Function
test(root; rules = Catalogue.RULES, checks = (), contracts = nothing)

Runs the code half of the always-on checks over the package at root and throws on anything found, so a red suite means a broken contract and a green one means every program that can check this package has. The arguments are:

  • root — the package root; the directory holding .gbg/config.jl.
  • rules — the rules to run, the whole rulebook by default; only those whose intention is code.
  • checks — further checks to run, each (cfg, root) -> Vector{Model.Location}. The wiring check is passed in this way, because it lives in a module above this one.
  • contracts — the function that runs the package's frozen contracts, or nothing to run none. It is passed the package root and is expected to throw on a broken contract, as a test does.

Prints one banner line naming the version that ran, which a consumer's CI reads to know the suite was this package's and not a bare Pkg.test(). Returns nothing.
